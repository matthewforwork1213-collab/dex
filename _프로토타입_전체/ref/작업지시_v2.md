## 3. 작업 순서 (화면마다)

1. 그 화면의 **기본 페이지 프레임**(PC·mWeb)을 찾는다(DEX(revision) 또는 기존 페이지). 이것이 셸까지 포함한 「진짜 제품」 기준이다.
2. 모든 상태를 표로 대응시킨다: `상태 → DEX(revision) 노드 | 기존 페이지 노드 | 재사용 컴포넌트 노드 | 없음`. `ref/대응_<그룹>.md`로 남긴다(근거 노드 · 찾은 키워드).
3. 기존 구현을 그 프레임대로 다시 만든다(필요하면 화면을 처음부터 다시 작성). 상태의 `figma`에 실제 근거 노드를 적고, 기존 페이지에서 온 것은 note 맨 앞에 `[기존 MAX-nnn]`을 붙인다.
4. `node build.cjs && node tools/check.cjs <접두사>` 오류 0, 대표 상태마다 `tools/shot.py`와 Figma `get_screenshot`을 비교.
5. `ref/누락_<그룹>.md`를 다시 쓴다 — **어디에도 디자인이 없는 상태만**, 찾아본 키워드와 함께.

## 4. 코어

- 셸(GNB·푸터·모바일 상단·하단 탭·드로어)은 「공통」 담당만 고친다. 다른 담당은 셸이 실제 디자인과 다르면 보고만 한다.
- 화면 모듈은 `shell:false`로 자체 셸을 그려도 되지만, 가능하면 코어 셸(`gnb()` `footer()` `moTop()` `moNav()`)을 쓴다.
