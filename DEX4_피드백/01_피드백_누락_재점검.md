## 1. 기존 피드백에 추가할 항목

### A-01. 출금 신청에서 CEX·DEX를 통합한다는 결정

**판정: 직접 충돌 누락. 우선 반영 필요.**

- **확정 기준:** 출금은 CEX·DEX 별도 탭 없이 자격 있는 계정을 한 목록에 기존 우선순위대로 나열하고 한 번에 신청합니다. 일부 계정만 고르는 구조를 새로 만들지 않습니다. 비회원은 단일 지갑입니다. 근거: 결정 기록 `Q`, 638~674행.
- **DEX4:** API p3은 CEX UID를 한 번에 하나씩 출금하고 DEX는 별도 탭에서 여러 지갑을 출금한다고 합니다. API p8은 별도 DEX 탭을 `Agreed`로 표시합니다. Service Flows p13~21의 WD-1~WD-5도 같은 구분을 전제로 합니다.
- **기존 피드백:** C-1은 출금액 계산식, C-2는 계정 연동 한도입니다. 둘 다 **출금 신청 목록·탭·계정 선택 방식의 차이**를 지적하지 않습니다.
- **추가할 피드백:** “출금은 CEX·DEX 통합 목록·기존 우선순위·한 번의 신청으로 수정해야 합니다. API의 합의 상태 표와 WD 요구사항도 함께 수정해야 합니다. 백오피스에서는 한 신청에 속한 계정별 처리 건을 공통 신청 ID 또는 그룹으로 추적할 수 있어야 합니다.”

### A-02. 계산기 요율을 별도 화면에서 다시 입력·저장하는 구조

**판정: 직접 충돌 누락. ‘Backoffice Part 3 추가 지적 없음’ 정정 필요.**

- **확정 기준:** Spending Estimate에서 별도로 관리하는 값은 거래량 슬라이더 범위입니다. 요율은 기존 거래소 레코드에서 읽습니다. 근거: 결정 기록 `R-25`, 1891~1933행.
- **DEX4:** BO Part 3 p17~20의 SPE-5·6·10·13은 파트너별 적용 전·후 요율 두 개를 필수 입력하고 별도 저장하도록 합니다. SPE-6에는 소수 세 자리 제한도 있습니다.
- **기존 피드백:** M-14의 독립 계산기 누락과 다른 문제입니다. 5차에서는 BO Part 3에 추가 지적이 없다고 했고, 해당 PDF 주석도 같은 결론입니다.
- **추가할 피드백:** “별도 요율 입력·저장을 제거하고 거래소 레코드를 참조하도록 SPE 요구사항을 수정해야 합니다. 입력 정밀도 역시 실제 거래소 요율을 손실 없이 표현하는 기존 필드와 함께 점검해야 합니다.”
- **주의:** 결정 기록 R-25 안에도 ‘3자리 제한 이관’이라는 문구와 4자리 요율을 보존해야 한다는 설명이 함께 있습니다. 이를 근거로 **새로운 소수 자릿수를 임의 확정하지 않습니다.** 요율의 단일 관리 원칙은 명확하고, 정확한 필드 정밀도는 구현 확인 사항으로 남깁니다.

### A-03. 없는 기능인 ‘선정산’이 DEX 적용 목록에 남아 있음

**판정: 범위 충돌 누락.**

- **확정 기준:** 최신 정책표의 ‘퀴즈·선정산’은 현재 없는 기능으로 지원 검토·개발 목록에서 제외합니다.
- **DEX4:** BO Part 1 p32 LST-49는 `Cashback Pre-Settlement`에 거래소 유형·지갑 주소·계정 ID를 추가합니다. p47 LST-51에서도 DEX 선정산 모듈을 전제로 합니다.
- **기존 피드백:** C-13은 퀴즈, C-4는 마일스톤입니다. 선정산 제외는 별도로 지적하지 않았습니다. S-1의 지급 구조 수정만으로 선정산 기능 자체가 범위에서 빠지지는 않습니다.
- **추가할 피드백:** “선정산은 이번 기능 범위에서 제외하고 LST-49 및 관련 참조를 정리해야 합니다.”

### A-04. 확인 중인 계정에도 리뷰 작성을 허용

**판정: 직접 충돌 누락.**

- **확정 기준:** 해당 거래소 계정이 **연동 완료**되어야 리뷰를 작성할 수 있습니다. 페이백 이력은 추가 조건이 아닙니다. 근거: 결정 기록 D-5, 1296행.
- **DEX4:** User Edge p61 EC-PG-14는 `Lighter Processing`이어도 연결이 존재하면 리뷰를 작성할 수 있다고 제안합니다.
- **기존 피드백:** M-6은 리뷰의 Verified **배지** 조건입니다. 리뷰 **작성 가능 여부**의 차이는 빠져 있습니다.
- **추가할 피드백:** “Processing 상태의 리뷰 작성 허용안을 연동 완료 조건에 맞춰 수정해야 합니다. 배지와 작성 권한을 각각 확인해야 합니다.”
- Aster 귀속 만료는 연동 진행 중과 다른 상태이므로 같은 사유로 일괄 차단한다고 새로 결정하지 않습니다.

### A-05. 비회원 미수령 잔액 10 USDT 이상일 때 연동 차단

**판정: 직접 충돌 누락. 파트너별 잔액 취득 방식은 별도 미정 유지.**

- **확정 기준:** 비회원 미수령 잔액이 10 USDT 이상이면 회원 연동을 차단하는 기존 기준을 DEX에도 적용합니다. 근거: 결정 기록 B-5, H-4 및 연동·출금 전체 플로우.
- **DEX4:** DEX Pages p49 LK-4, Service Flows p50 및 p63 LW-8은 연동 과정에서 먼저 페이백을 출금하도록 요구하지 않는다고 명시합니다.
- **기존 피드백:** 이 조건과의 차이를 지적하지 않았습니다. C-11의 **최소 출금액**과는 다른 정책입니다.
- **추가할 피드백:** “미수령 잔액 기준에 따른 연동 차단 조건과 안내를 반영하고, ‘먼저 출금하도록 요구하지 않는다’는 일괄 문구를 정리해야 합니다.”
- **미정 유지:** ApeX의 기존 미수령 잔액을 어떻게 조회·이관할지는 최신 보류 목록에 있습니다. 이 검토로 해당 API나 이관 방식을 확정하지 않습니다.

### A-06. 초대 리워드가 발생하는 시점

**판정: 직접 충돌 누락. 지급 대상 추가와는 다른 문제.**

- **확정 기준:** 하위 회원의 출금 실적과 해당 마진·적립률에 따라 초대 리워드가 발생합니다. 최신 정책도 하위 출금 실적이 없어서 발생액이 0인 경우를 명시합니다. 근거: 최신 정책의 ‘초대 리워드’, `_제출본_V2/5_부가서비스_연동가능여부/부가서비스_DEX연동_가능여부_V2재판정_국문.md`의 B-2-8 및 `DEX/10_기존_테더맥스_기준선.md` 318행의 산식.
- **DEX4:** Service Flows p87~88 IF-1은 친구의 DEX 페이백이 원장에서 테더맥스 잔액으로 **적립되면** 초대 리워드가 발생한다고 합니다. p46~47 PH-1도 원장 적립을 기준으로 설명합니다.
- **기존 피드백:** S-1은 백오피스의 ‘초대 리워드는 CEX 전용’ 제한을 지적합니다. **적립 시점과 출금 시점의 차이**는 짚지 않았습니다.
- **추가할 피드백:** “DEX도 하위 회원 출금 기준의 기존 초대 리워드 발생 규칙을 적용하도록 IF-1·PH-1과 관련 문구·수용 기준을 수정해야 합니다.”
- 실제 계약 마진율·재원은 협의 대기로 유지합니다.

### A-07. Lighter 맥스보드 참여 조건과 공통 배치 시각

**판정: 확정된 운영 조건 누락.**

- **확정 기준:** Lighter는 일 단위 원장을 확보하지 못하면 맥스보드를 운영하지 않습니다. 금액 칸만 쓰는 대체안도 채택하지 않았습니다. 빙고 배치는 예외 없이 12:30 UTC입니다. 근거: 결정 기록 O-2, D-10.
- **DEX4:** API p5·19·21 등은 맥스보드에 필요한 데이터를 `symbol + volume` 위주로 설명합니다. Lighter의 일별 원장 확보 조건과 12:30 UTC 배치 조건은 해당 요구사항에 연결되어 있지 않습니다.
- **기존 피드백:** C-8의 글로벌리그 거래량 기준 정정, M-3의 시간별 원장은 관련 있지만 위 운영 조건까지 다루지는 않습니다.
- **추가할 피드백:** “맥스보드 요구사항에 Lighter 일별 원장 확보를 운영 전제로 명시하고, 미확보 시 제외·금액 칸 대체 미채택·공통 12:30 UTC 배치를 반영해야 합니다.”
- 일별 원장을 실제로 받을 수 있는지는 계속 거래소 협의 사항입니다.

### A-08. 서비스 소개 캐러셀과 두 곳의 출금 피드

**판정: 구성 요소·노출 위치별 수용 기준 누락. ‘DEX 추가’ 총론만으로 완료 판정 불가.**

- **확정 기준:** 공식 파트너 자동 캐러셀은 **서비스 소개** 영역입니다. CEX·DEX의 로고·순서·노출 등을 API로 받습니다. 완료 출금 피드는 **홈과 서비스 소개 양쪽**에 CEX·DEX를 포함합니다. 근거: 최신 정책의 디자인 표시 범위 및 캐러셀·출금 피드 항목.
- **DEX4:** User Overview p4에 홈·서비스 소개 추가와 DX-16·DX-17 참조가 있습니다. Service Flows p31 WD-13에도 출금 피드가 있습니다. 하지만 이 총론·피드 설명만으로 위 캐러셀의 API 데이터 범위와 두 위치의 반영 조건을 확인하기 어렵습니다. Hub p29 RT-6의 정적 파트너 로고는 다른 구성 요소입니다.
- **기존 피드백:** 해당 요소·위치별 누락을 지적하지 않았습니다.
- **추가할 피드백:** “서비스 소개의 공식 파트너 자동 캐러셀과 홈·서비스 소개의 완료 출금 피드를 각각 수용 기준으로 명시해야 합니다. 캐러셀은 CEX·DEX 통합 API 데이터, 공개 피드는 기존 뒤 4자리 마스킹을 적용합니다.”
- 화면 자체가 전혀 없다고 단정하는 지적이 아닙니다. **구체적 요구사항의 연결·검증 범위**를 보완해야 한다는 뜻입니다.

### A-09. 거래소 필터의 그룹·전체 선택 및 미연동 대상 정의

**판정: 일부 반영됐으나 공통 조건 누락.**

- **확정 기준:** 출금을 제외한 지정 화면은 하나의 거래소 선택 목록 안에서 CEX·DEX를 구분합니다. 두 그룹을 모두 가진 대상 필터에는 전체/CEX 전체/DEX 전체 범위를 제공합니다. 기존 수동 푸시의 CEX 전체 선택이 DEX까지 자동 확장되지 않도록 합니다. ‘미연동’은 CEX·DEX 어디에도 연동 계정이 없는 회원입니다. 근거: 결정 기록 Q, D-9, R-19 및 최신 정책표.
- **DEX4:** Service Flows p39 CS-1은 CEX·DEX를 필터에 함께 나열하지만 그룹별 범위 선택은 정의하지 않습니다. BO Part 2 p75 MSG-1은 DEX 옵션 추가만 명시합니다. BO Part 1 LST-17의 대상 선택에도 최신 미연동 정의를 연결해야 합니다.
- **기존 피드백:** O-4를 ‘문제없음’으로 판정한 근거는 DEX 옵션이 존재한다는 점입니다. 기존 저장 대상의 의미 보존과 범위 선택까지 확인한 내용은 없습니다.
- **추가할 피드백:** “해당 필터들의 CEX·DEX 그룹 및 범위 선택을 보완하고, 기존 CEX 전체 대상이 자동으로 DEX까지 확대되지 않게 해야 합니다. 미연동 대상은 두 유형 모두 연동이 없는 회원으로 판정해야 합니다.”
- 모든 단일 계정 수령 선택기에 ‘전체 계정으로 지급’을 추가하라는 뜻은 아닙니다. 기존 확정 적용 화면·필터 범위에 한정합니다.

### A-10. 연동 접수 시 ‘확인 중’ 알림과 완료 알림의 구분

**판정: 알림 요구사항 명시 누락.**

- **확정 기준:** 연동 접수 시 ‘확인 중’, 확정 시 ‘연동 완료’로 구분합니다. 근거: 결정 기록 D-12, 1299행.
- **DEX4:** Service Flows p62~63에는 Processing 화면 및 완료·실패 통지가 있습니다. BO Part 2 p78 MSG-12도 대기 연동의 승인·거절·해제 알림을 정의하지만 **접수 단계의 확인 중 알림**은 명시하지 않습니다.
- **기존 피드백:** M-5는 **출금 이메일** 정책이며 연동 알림 요구사항을 대신하지 않습니다.
- **추가할 피드백:** “연동 접수와 최종 확정의 알림 문구·발생 조건을 D-12에 맞춰 구분해야 합니다. Processing 화면이 있다는 사실만으로 접수 알림까지 반영됐다고 판정하지 않습니다.”
- **출금 중간 이메일을 새로 만들자는 요구가 아닙니다.** 알림 채널이나 추가 이메일 템플릿을 이번 검토에서 새로 정하지 않습니다.

## 2. 기존 지적에 붙여야 할 보완 내용

### B-01. 포인트 관리: ‘문제없음’ 판정 수정

- **기존:** 요약 3-B의 R-2는 DEX 목록·적립률 필드가 있으므로 정상이라고 판정했습니다.
- **빠진 차이:** BO Part 1 p45~46 LST-30의 뒤쪽 주석은 **DEX 이벤트 리워드 적립률을 비활성화**하고, DEX 활동에 포인트가 적립되는지 자체도 미확정이라고 합니다. 앞쪽의 ‘CEX처럼 관리’와 충돌합니다.
- **기준:** DEX 포인트 관리 포함, 입력·검증은 CEX와 동일, 미설정은 0.
- **보완:** 정상 판정을 ‘부분 반영’으로 정정하고, 비활성화 문구·미확정 문구·저장 검증까지 수정 대상으로 지정해야 합니다. S-1의 일반적인 이벤트 리워드 지적과 연결하되 신규 정책으로 중복 집계하지 않습니다.

### B-02. C-6 첫 연동 3 USDT: 발급뿐 아니라 DEX 수령도 지적

- **기존:** C-6은 BO Part 2 p35의 DEX 첫 연동 쿠폰 발급 및 CEX UID 대기를 지적합니다.
- **빠진 차이:** User Edge p29 EC-CPN-1과 Service Flows p84~85 LW-30은 **DEX만 가진 회원도 DEX 지갑으로 그 3 USDT를 적용**할 수 있다고 합니다. 백오피스와 사용자 문서의 지급 대상도 서로 다릅니다.
- **기준:** UID 연동 3 USDT는 DEX 제외. 일반 이벤트·쿠폰의 DEX 지원과 구분.
- **보완:** 발급 조건, 수령 계정 필터, DEX에 적용되는 수용 기준을 함께 수정 대상으로 지정해야 합니다. C-6 자체는 이미 있으므로 별도 신규 누락으로 세지 않습니다.

### B-03. M-7 챌린지: 수령 계정뿐 아니라 게이지도 제외

- **기존:** CSB-4 공백과 보상 수령 계정에서 DEX를 제외한다는 지적이 있습니다.
- **빠진 차이:** Service Flows p5는 DEX 이벤트 리워드의 예에 challenges를 포함합니다. 결정 기록 D-13은 **챌린지 게이지에도 DEX를 산입하지 않는다**고 명시합니다.
- **보완:** DEX 챌린지 참여·실적 누적·보상 수령 모두 제외하고, 실제 챌린지 상세·계정 선택 등 필요한 화면에 CEX 전용임을 안내하도록 M-7을 확장해야 합니다. 사용자 요청대로 혜택 목록 전체에 장황한 공통 안내를 다시 넣지는 않습니다.

### B-04. C-9 공유 카드: 대표 계정 선택 규칙 추가

- **기존:** 신청 완료를 지급 완료처럼 표현하는 문구를 지적했습니다.
- **빠진 차이:** Service Flows p21 WD-4는 단일 DEX 칩·지갑 주소로 카드를 설명하고, 여러 계정 또는 CEX·DEX 혼합 신청에서 무엇을 대표로 표시할지 연결하지 않습니다.
- **기준:** 출금 신청 성공 후 공유 가능. 대표 계정은 현재 출금 신청 목록의 우선순위로 선택.
- **보완:** 문구뿐 아니라 대표 계정 선택 규칙도 C-9에 추가하고 A-01의 통합 출금과 연결해야 합니다. 새로운 정렬 기준은 만들지 않습니다.

### B-05. M-11 집계 일자: 정확한 설정 위치·주기·요일 추가

- **기존:** 집계 일자 드롭다운을 7일까지 늘린다는 지적입니다. 관련 주석은 BO Part 1 p39에 있습니다.
- **빠진 차이:** 최신 정정 R-22는 **거래소 생성·수정**의 집계 시작·종료 상대 일자를 늘리고, **주기(일/주)와 요일**도 설정하도록 했습니다. 페이백 전체 내역의 조회 필터 확장이 아닙니다.
- **보완:** 위치·상대 일자·주기·요일을 한 묶음으로 명시해야 합니다. ‘7일’만 늘리면 주 1회 집계 규칙을 표현하지 못합니다.

### B-06. S-1 백오피스 전면 갱신: 구체적 수정 대상 연결

S-1은 중요한 차이를 이미 포착했습니다. 이를 ‘아예 누락’이라고 다시 보고하면 중복입니다. 다만 전체 갱신이라는 말만으로 다음 기능들이 자동 반영됐다고 판정해서는 안 됩니다.

## 4. 피드백 문구의 작은 정정 두 가지

이 항목은 누락 건수에 포함하지 않았습니다. 범위를 잘못 전달할 수 있어 함께 기록합니다.

- **M-1:** 보안 제한이 ‘한 건도 없다’는 표현은 좁혀야 합니다. Service Flows p19 WD-4에 기존 출금 인증과 24시간 제한을 적용한다는 서술이 있습니다. **72시간 제한과 회원 공통 적용·비회원 예외까지 충분히 정의됐는지**를 지적하는 형태가 정확합니다.
