# ★ 구조 문제

**개별 지적보다 먼저 봐야 합니다.** 백오피스 PRD 3종이 V2 구조 이전의 전제 위에 서 있습니다.

## 🔴🔴 구조 S-1 · 이 백오피스 PRD는 V1 전제 위에 그대로 있습니다

> 위치 — **BO 개요** p3

**사용자 PRD와 API PRD는 V2로 다시 쓰였는데, 백오피스 PRD는 안 바뀌었습니다.**

문서별로 세어 본 결과입니다.
   · API 문서 ........... V1 문구 0건 / V2 문구 59건
   · 사용자 문서 5종 ...... V1 문구 3건 / V2 문구 38건
   · 백오피스 문서 3종 .... V1 문구 35건 / V2 문구 1건  ← 여기

10-20 추출본과 10-23 추출본을 비교하면 그 이유가 보입니다. `As a TetherMax admin`, `Part 2 Linking·Settlement·Messaging`, `Part 4 Broker Content Editors` 세 문서는 **바이트 단위로 동일**합니다. 사용자 쪽은 Service Flows 가 +4,614줄, Hub and Navigation 이 19쪽→41쪽으로 늘어나는 동안 백오피스는 손대지 않았습니다.

그래서 백오피스 PRD는 아직 이렇게 말합니다.
   · "TetherMax never settles or pays DEX trading cashback"
   · "TetherMax pays no event rewards to DEX traders"
   · "Invite rewards are CEX only"
   · "DEX trading cashback is withdrawn on the DEX through the Withdraw on {DEX} redirect"
   · Out of Scope: "Any payment of DEX trading cashback or DEX event rewards by TetherMax ... There is therefore **no DEX payout approval, omni account, payout file, layer two internal transfer**"

**같은 PRD 묶음의 API 문서는 정반대입니다** — 커미션 100%를 Wallet A 로 받아 Wallet B 가 트레이더에게 직접 지급하고, 가스비는 테더맥스가 냅니다.

🔴 **결과적으로 백오피스에 다음이 전부 비어 있습니다.**
   · Wallet A → Wallet B 리밸런싱 운영 화면
   · DEX 출금 승인·실행·실패 처리
   · 가스비 예치·소진 관리
   · DEX 이벤트 리워드 지급 (LST-21 이 CEX only 로 막아 둠)
   · DEX 초대 리워드 출금 (LST-46 이 CEX only 로 막아 둠)

앞서 드린 지적 중 C-2(연동 한도 산식), C-5(브로커 에디터), C-6(첫 연동 쿠폰), C-11(최소 출금액)이 전부 이 세 문서에서 나왔습니다. **개별 수정이 아니라 백오피스 PRD 전체를 V2 기준으로 다시 봐야 합니다.**

## 🔴 구조 S-1 (이어서) · `LST-21` 이 DEX 이벤트 리워드를 막고 있습니다

> 위치 — **BO Part 1** p43

`LST-21` 이 Event Reward Payment 를 **CEX only** 로 두는 근거가 *"TetherMax pays no event rewards to DEX traders"* 입니다.

**확정 정책(A-1)은 DEX에도 이벤트 리워드를 지급합니다.** 구조가 바뀌어 테더맥스가 커미션을 수신하므로 지급이 가능해졌기 때문입니다. 같은 PRD의 사용자 문서도 *"event rewards apply to DEX traders"* 라고 적고 있습니다.

같은 문서의 `LST-46`(Invite Reward Withdrawal, CEX only)도 같은 문제입니다 — 확정 정책 A-2는 초대 리워드를 CEX UID와 동일하게 취급합니다.

→ S-1 참조.

✅ **확정 (2026-10-23)**
**DEX에도 이벤트 리워드를 지급합니다.** `LST-21 Event Reward Payment` 의 CEX 전용 제한을 제거하고 **DEX를 필터·대상·지급 내역에 포함**해 주십시오.

## 🔴 구조 S-1 (이어서) · `CSB-11` 이 V2와 정반대입니다

> 위치 — **BO Part 2** p44

`CSB-11 No TetherMax payout for DEX traders` — *"TetherMax pays no event rewards to DEX traders and never moves money for DEX traders. DEX trading cashback is paid by the DEX into the trader's DEX account and withdrawn on the DEX."*

**같은 PRD 묶음의 API 문서는 Wallet B 가 트레이더 지갑으로 직접 송금한다고 합니다.** 정산 모듈 설계가 통째로 달라집니다 — 이 문서대로면 **지급 승인·실행·실패 처리 화면이 아예 없습니다.**

→ S-1 참조. 백오피스 PRD 3종이 10-20 판에서 갱신되지 않았습니다.

─────────────────────
✅ **확정 (2026-10-23)**
**V2에서는 테더맥스가 지급합니다.** `CSB-11` 의 *"never moves money for DEX traders"* 는 V1 전제이며 **폐기 대상**입니다. DEX도 **이벤트 리워드를 받고**, 페이백은 **테더맥스 잔액에서 Wallet B를 통해 지급**됩니다. 따라서 **지급 승인·실행·실패 처리 화면을 신규로 설계**해야 합니다 (`F-2` 참조).

→ **이 문단은 V2 구조로 다시 써야 합니다.** 문구 수정이 아니라 **전제 자체를 바꾸는 것**입니다 — 테더맥스가 지급 주체이고, Wallet B가 트레이더 지갑으로 송금하며, 그에 따른 **승인·실행·실패 처리 화면이 필요합니다.**
