# DEX 프로토타입 V2.1

V2의 화면 구성을 바탕으로 최신 DEX 정책을 반영한 디자인 검토 자료입니다. 기존 `_프로토타입`과 `_프로토타입_V3`는 수정하지 않았습니다.

- [사용자 화면](사용자화면_DEX_V2.1.html)
- [백오피스](백오피스_DEX_V2.1.html)

각 HTML을 브라우저에서 직접 열 수 있습니다. 설치나 서버 실행은 필요하지 않습니다.

## 2026-10-26 모달 재수정

모달을 일반 카드로 생성한 뒤 후처리하던 방식을 바꿨습니다. 이제 화면 생성 결과 자체에 배경 페이지·음영·모달이 포함됩니다. 제휴사 등록을 포함한 전체 모달에 적용했으며, 상단 메뉴와 변경점 표시는 모달 바깥에 유지합니다.

로컬 파일이나 IDE 미리보기에서 주소 변경이 차단돼도 화면 전환이 계속되도록 수정했습니다. 두 HTML 상단의 버전 표시는 **V2.1 | 2026-10-26**입니다. 로컬 파일 주소 및 주소 변경이 제한된 미리보기 조건에서 상단 메뉴 클릭·모달 열기·닫기·변경점 전환을 추가 검사했습니다.

## 2026-10-23 디자인 검토 기준

기본 미리보기에는 제품 화면만 표시합니다. 시연용 버튼·번호·API 응답 선택·개발 설명을 제거했습니다. 화면과 상황은 상단 GNB와 미리보기 바깥의 **화면 상태**에서 선택합니다. 최신 요청에 따라 **변경점 표시** 체크박스를 복원했습니다. 체크할 때만 변경 영역의 색상 테두리·번호와 연결된 설명 패널이 나타나고, 해제하면 모두 사라집니다. 초기화·화살표 플로우 도구는 복원하지 않았습니다.

변경점은 현재 V2.1 화면 요소와 최신 정책을 기준으로 작성했습니다. 예전의 폐기된 정책 주석을 그대로 노출하지 않습니다. 변경점 번호를 클릭하면 해당 설명이 선택되고, 설명을 클릭하면 해당 화면 영역이 선택됩니다. 표시 전환만으로 입력값·선택값·계정 데이터나 출금·저장 상태를 바꾸지 않습니다. 작은 화면에서는 설명이 미리보기 아래에 배치됩니다. 자세한 내용은 [변경점 표시 적용 내역](변경점표시_적용내역.md)을 참고합니다.

혜택 목록 하단의 DEX 지원 범위 안내를 삭제했습니다. 서로 다른 기능을 한 순서로 묶던 화살표·단계·다음 화면 플로우 바도 사용자·백오피스 전체에서 제거했습니다. 상단의 독립적인 화면 선택과 화면 상태 변경만 검토용 탐색에 사용합니다.

- 계정 상세는 V2의 잔액 카드·페이백 타임라인·주간 내역 구조를 사용합니다. 추가했던 ‘계정 목록’과 ‘지갑 관리 안내’ 버튼을 제거했습니다.
- 출금 인증·계정별 최종 결과 화면을 사용자 목록과 흐름에서 제외했습니다. 출금 목록 → 신청 완료 → 공유 카드로 확인합니다. 실제 서비스의 보안 인증 정책을 폐기한 결정은 아닙니다.
- 신청 완료·공유·연동 완료·비회원 출금은 앞 단계 입력 없이 바로 열립니다. 아직 신청하지 않았다는 안내나 출금 시작 버튼을 끼워 넣지 않습니다.
- 공식 파트너 캐러셀은 서비스 소개에 배치합니다. 홈과 서비스 소개의 실시간 출금 피드는 모두 CEX·DEX 완료 출금을 표시합니다.
- 쿠폰과 초대 리워드 계정 선택은 V2의 목록 및 ‘취소 / 확인’ 버튼을 사용합니다. 임시 ‘대상 계정 확인’, ‘계정 확인 · 시연’ 버튼은 사용하지 않습니다.
- 드롭다운 내부의 개발 설명·신규 변경 마커와 숨길 영역을 설명하기 위해 그렸던 관리자 KYC·DEX 소유 확인 섹션도 제거했습니다.
- 관리자 귀속 원장 여부·승인 결과·포인트 모달·콘텐츠 미리보기는 바깥의 화면 상태에서 직접 확인할 수 있습니다.
- 회원 연동 계정은 회원 목록을 배경으로 한 모달입니다. 배경 음영·닫기·Escape·포커스 제한을 적용하고 작은 화면에서는 표 안에서 가로 스크롤합니다. 통합 연동 한도 정책을 신규 화면 승인으로 해석해 추가했던 카드·독립 메뉴는 제거했습니다. 별도 사용량 조회 화면의 추가 여부와 위치·표시 항목은 미확정으로 기록했습니다.
- 제휴사 등록·레퍼럴 마진 수정·거래소 순위 수정·포인트 관리/강조 거래소, 사용자 계정 연동·출금·쿠폰/리워드 계정 선택·리그 참가 계정 선택·하위 계정 조회도 배경 위의 모달로 표시합니다. 공통 음영·닫기·Escape·배경 차단·포커스 제한·내부 스크롤을 적용했습니다. 전체 적용 범위는 [모달 적용 내역](모달_적용내역.md)에 기록했습니다.

Wanted Sans, 상단 GNB, V2의 색상·계산기 영수증·출금 카드·거래소 화면과 관리자 틀을 유지합니다. 작은 화면에는 열 재배치와 표 내부 가로 스크롤을 적용했습니다.

백오피스의 데스크톱 화면은 기존 최대 미리보기 영역(1740px)에서 여백·테두리를 뺀 **1714px**로 고정합니다. 메뉴·모달·변경점 설명의 표시 여부에 따라 관리자 외곽 폭이 달라지지 않습니다. 창이 좁으면 미리보기 안에서 가로 스크롤하며, 760px 이하의 모바일 화면은 기존 반응형 구성을 유지합니다. 세로 스크롤 유무에 따른 가로 흔들림도 방지합니다.

후속 가독성 점검에서는 계정 상세의 카드 간격, 신청 가능 금액의 강조, 진행 막대와 출금 버튼 사이 여백, 타임라인과 주간 내역의 글자 크기를 보완했습니다. 클릭 위치를 알려주던 점선과 설명 패널 때문에 남던 빈 열을 제거했습니다. 리그의 참가 계정 선택과 하위 회원 계정 모달, 미완료 챌린지도 V2의 개별 화면 형태로 바로잡았습니다. [가독성·노출 재점검](가독성_노출재점검_20261023.md)에 상세 내용을 기록했습니다.

## 정책과 사용 범위

[확정 정책과 보류 사항](정책변경_미결정.md)을 기준으로 합니다. 통합 연동 한도와 확인 중 점유, 계정별 출금 계산, 0.01 USDT 기준, 뒤 4자리 마스킹, DEX 리워드 지원·CEX 전용 보상 제한, 포인트 4개 필드를 유지합니다. 이메일은 접수 1회 → 계정별 최종 성공·실패이며 중간 이메일을 추가하지 않습니다.

네트워크·실제 계약 요율·Aster 만료 후 적립과 갱신·일별 원장·콘텐츠 게시 권한 등 미정 사항은 확정하지 않았습니다. 변경 내역은 [디자인 검토 수정 결과](디자인검토_수정결과_20261023.md)에 있습니다. 소스에는 재현을 위한 원본 템플릿과 계산 함수가 남아 있으므로 HTML 소스 검색 결과가 현재 노출 화면을 뜻하지는 않습니다.

실제 조회·송금·이메일 발송·게시를 실행하는 서비스 구현물이 아닙니다. 기존 서비스의 외부 가입·엑셀 작업 등은 화면 위치를 보존한 범위입니다.

## 확인 방법

1. 상단 업무 메뉴와 화면 탭으로 원하는 화면을 바로 선택합니다.
2. **화면 상태**가 있는 화면은 정상·제한·오류·완료 등을 바로 선택합니다.
3. 사용자 출금의 **신청 완료**를 선택하면 선행 신청 없이 V2 완료 화면을 확인합니다.
4. **기타 반영 지점 → 서비스 소개**에서 공식 파트너 캐러셀과 통합 출금 피드를 확인합니다.
5. 백오피스 **포인트**에서 목록·관리 모달·강조할 거래소를 직접 선택합니다.
6. 상단 **변경점 표시**를 체크해 영역별 테두리·번호·설명을 확인합니다. 기본 상태는 해제입니다.

## 빌드와 검증

- `node build.cjs`: V2 원본을 보존하며 두 HTML 생성
- `node check.cjs`: 스크립트·화면 생성·경로·계산·정책 **462/462 통과**
- `node check-dom.cjs`: HTML 파싱·클릭·폼·저장·회원 모달 열기/닫기·포커스 **93/93 통과**
- `node check-design.cjs`: 한국어·영어 화면, 외부 상태 변경, 드롭다운, 직접 진입, 내부 문구·플로우 바 제거·계정 상세 CSS 규칙 **630/630 통과**
- `node check-changes.cjs`: 두 파일의 전체 화면·상태별 변경점 표시·해제, 번호·설명 연결, 입력 보존·오작동 방지 **320/320 통과**
- `node check-modals.cjs`: 전체 화면·상태의 모달 구조, 배경 차단, 닫기·Escape·포커스·폼·변경점 연동, 로컬/제한된 미리보기 메뉴 클릭 **176/176 통과**

[기본 검증](검증결과.json), [DOM 검증](DOM검증결과.json), [디자인 화면 검증](디자인화면_검증결과.json)에 결과를 기록합니다. 검사는 오프라인 VM/JSDOM으로 실행했습니다. 실제 브라우저와 모바일 기기에서의 시각적 배치·터치·겹침은 검증하지 못했습니다. 새 화면의 전체 다국어 번역은 별도 작업입니다.

변경점 표시의 별도 결과는 [변경점 표시 검증](변경점표시_검증결과.json)에 기록합니다. 영어 화면에서도 변경 영역을 표시하지만 변경점 설명은 한국어 검토용으로 제공합니다.
