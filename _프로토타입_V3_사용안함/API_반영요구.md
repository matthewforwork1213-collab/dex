# API 반영 요구 — 실서버 미연결

이 문서는 기존 API를 조회한 결과가 아니라, 이번 결정에 따라 구현팀이 연결해야 하는 데이터 요구입니다. URL·인증 방식·최종 필드명·갱신 주기는 기존 시스템과 맞춰야 합니다.

## 1. 거래소 통합 목록

공식 파트너 자동 캐러셀은 CEX·DEX를 합친 거래소 목록 응답을 사용합니다. 별도의 하드코딩 로고 배열을 운영하지 않습니다.

필요 데이터: 거래소 식별자, 이름, `CEX/DEX` 유형, 로고 URL, 노출 여부, 연동 가능 여부, 활성 여부, 표시 순서, 수수료·페이백 요율.

- 캐러셀: 노출 대상 필터와 표시 순서 적용, 로고 없거나 응답 비었을 때 대체 표시.
- 계산기: 동일 거래소 레코드의 요율 참조. 계산기 관리에는 최소·최대 거래량만 저장.
- 관리자 목록: 비노출 거래소도 수정할 수 있어야 함. 고객 공개 목록과 관리자 목록의 필터 구분.
- 통합 연동 한도: CEX·DEX 전체 계정 수에 확인 중도 포함. 기존 공통 최대값/계산 결과를 읽고 별도 DEX 산식은 제거. 신규 한도 숫자는 임의 설정하지 않음.

프로토타입은 `DemoAPI.getPartners()`로 예시 데이터를 읽습니다. 실제 API가 붙었다고 표시하지 않습니다.

## 2. 완료 출금 통합 피드

**홈과 서비스 소개 페이지 모두** 같은 CEX·DEX 통합 피드를 사용합니다.

필요 데이터: 거래소 식별자·유형, 공개용 축약 식별자, 금액·자산, 완료 시각, 처리 결과. 서버에서 공개 응답을 만들 때 전체 UID·지갑 주소를 불필요하게 노출하지 않아야 합니다. 프로토타입은 예시 원본을 축약하여 표시합니다.

- 성공이 확정된 계정별 지급만 노출. 신청 접수·처리 중·실패·결과 불명은 성공 피드에 넣지 않음.
- DEX 지갑·CEX UID 모두 기존과 동일하게 뒤 4자리만 표시. 본인 계정 화면에서는 전체 주소 펼쳐보기 제공. 열 제목은 공통으로 ‘거래 계정’ 사용.
- 원본 시각은 UTC, 화면은 사용자 현지 시각.
- 로딩·빈 목록·오류·다시 불러오기 상태 제공.
- 실제 실시간 갱신 방식은 폴링/SSE 등 기존 서비스 구현과 확인. 프로토타입은 초기 조회와 수동 재조회만 구현.
- 공개 피드에 거래 해시를 노출할지는 별도 확정하지 않음.

프로토타입의 두 페이지는 `DemoAPI.getWithdrawalFeed()` 응답과 공통 렌더 함수를 사용합니다.

## 3. 포인트 관리

거래소 목록 조회·관리 상세 조회·설정 저장·강조 거래소 선택에서 DEX를 누락하지 않습니다.

관리 필드:

1. 페이백 커미션 적립률.
2. 이벤트 리워드 적립률.
3. 상위 일반 계정 TP 적립률 — 하위 계정 출금액 중 커미션 기준.
4. 상위 파트너 계정 TP 적립률 — 동일 기준.

미설정/null은 0으로 처리합니다. 입력·검증 정책은 기존 CEX와 동일하게 적용합니다. 프로토타입은 기존 UI의 숫자·마이너스·소수점 최대 9자리 표현을 따릅니다. 최종 계약 마진율은 협의 대기입니다.

강조할 거래소는 CEX/DEX 중 단일 선택이며 ‘전체’ 옵션을 넣지 않습니다.

## 4. 이벤트 제외 문구와 서버 대상 판정

고정 정책 문구는 언어팩으로 관리합니다. 예:

- UID 연동 3 USDT: ‘CEX 전용 보상입니다. DEX 지갑 연동은 이 보상 대상에 포함되지 않습니다.’
- 챌린지: ‘DEX 거래 계정으로는 챌린지에 참여하거나 리워드를 받을 수 없습니다.’
- 소유권·마이포트폴리오: ‘DEX는 이 기능을 지원하지 않습니다.’

노출 위치는 혜택 카드, 상세 보상 정보, 수령 계정 선택, 참여 가능한 계정 없음 안내입니다. 일반 이벤트·쿠폰·초대 리워드에 DEX 불가 문구를 공통 적용하지 않습니다.

UI의 선택지 제외만으로 끝내지 말고 API에서 보상 종류별 수령 계정을 검증해야 합니다. 프로토타입에도 같은 구분의 입력 검사를 구현했습니다. 부스트에는 DEX를 포함하지 않습니다.

## 5. 공통 출금

회원 제한 72시간/24시간은 같은 모달을 사용하는 것으로 자동 보장되지 않습니다. 요청 API의 공통 검증에도 적용해야 합니다. 계정별 계산·최소액·귀속·중복 지급 방지·결과 판정은 서버 기준입니다.

다중 신청은 신청번호 아래 계정별 결과를 기록합니다. 성공은 유지하고 실패만 실패 처리합니다. 회원 이메일은 기존 흐름을 유지합니다: 단건·다건 모두 신청당 접수 이메일 1회 → 최종 결과만 계정별 성공/실패 각각 1건. 처리 중·결과 확인 중 이메일을 추가하지 않습니다. 비회원 이메일은 없습니다. 기존 템플릿의 DEX 주소·금액 등 표시 대응은 필요하지만, 이 때문에 새 중간 상태 템플릿이 필요한 것은 아닙니다. DEX 출금 버튼은 외부 거래소 출금 페이지가 아니라 테더맥스 공통 출금 요청으로 연결합니다.

프로토타입의 중복 요청 차단은 시연 보호 장치입니다. 응답이 지연되면 처리 중으로 두고 백엔드에서 결과를 재확인합니다. 최종 결과는 성공·실패 두 가지이며 중복 지급 방지는 백엔드 구현 책임입니다. 비회원에는 회원 계정 기반 72/24시간 제한을 적용하지 않습니다.

## 최신 공통 표시·대상 기준

소액 표시와 랭킹은 0.01 USDT 기준, 원장 정밀도 유지. 미연동은 모든 거래소의 연동 계정 없음. 리뷰 빈 상태는 CEX와 동일. D-4는 리뷰 작성자의 해당 거래소 연동 완료를 뜻하는 Verified 배지이며 CEX·DEX 같은 의미로 사용. 신규 적립 데이터 지연은 기존 확정 잔액·출금을 차단하지 않음. 공유 카드는 신청 성공 후, 신청 목록 우선순위로 대표 계정을 표시. 잘못 연동·중복·해제는 CS 접수 후 백엔드에서 처리.
