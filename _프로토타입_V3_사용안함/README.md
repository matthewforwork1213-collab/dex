## 권장 확인 순서

1. **사용자 → 출금 → 출금 목록**: 합계 161.68 USDT, 3개 계정. 인증 버튼 → 보안 확인 → 시연용 번호 `123456` → 신청 → **일부 실패**. 계정별 결과와 이메일 예시 확인.
2. **예시 초기화 → 지갑 연동 → 게스트·통합 목록**: DEX와 지갑 주소 입력 → 조회 → 단일 지갑 출금. 기본 주소는 동작 확인용이며 실제 주소 조회는 실행하지 않습니다.
3. **혜택 → UID 연동 미션**, **페이백 챌린지**: DEX 제외 문구와 CEX 전용 계정 선택 확인. **쿠폰**에서는 DEX도 선택 가능.
4. **홈 → 비회원 홈**, **서비스·알림 → 서비스 소개**: CEX·DEX 캐러셀과 동일한 출금 피드 확인. 정지·이전/다음 및 오류/빈 상태 버튼 사용.
5. **백오피스 → 포인트 관리**: DEX의 관리 버튼 → 4개 비율 입력 → 예시 저장. 강조 거래소에서 DEX 선택.
6. **거래 계정 → 수동 연동**: 원장 없음으로 바꾸면 승인 불가. 원장 있음 + 근거 입력 시 승인 예시.
7. **콘텐츠·운영 설정 → 통합 연동 한도** 및 **결정·확인 대기** 확인.

입력·저장·계정 이동은 시연 상태입니다. 새로고침 시 일부 설정만 브라우저 저장소에서 복원합니다. 두 HTML 사이의 상태 동기화는 구현하지 않았습니다. 백오피스 설정이 열린 사용자 HTML에 실시간 전파되는 제품 구현은 아닙니다. `예시 초기화`로 데모 설정을 초기화할 수 있습니다.

## 실제 API와의 차이

실제 API URL·인증·응답 명세가 제공되지 않아 **실서버 연동은 하지 않았습니다**. `DemoAPI.getPartners()`와 `DemoAPI.getWithdrawalFeed()`라는 비동기 경계에 예시 응답을 연결했습니다. 이름·유형·노출·순서 등을 응답에서 읽으며, 캐러셀용 로고 URL이 있으면 사용하고 없으면 이름/이니셜로 표시합니다. 출금 피드는 초기 로드와 다시 불러오기를 지원하며 실제 스트리밍·폴링 주기는 미정입니다.

개발 연결 요구는 [API 반영 요구](API_반영요구.md)를 참고하세요. 여기의 필드명은 제안된 계약 형태이며 기존 API 명세라고 주장하지 않습니다.

실제 거래소 조회, 계정 연동, 송금, 이메일·푸시 발송, 파일 업로드, 서비스 게시를 실행하지 않습니다. 예시 거래소 수·요율·마진·미디어·지급 네트워크를 운영 확정값으로 사용하지 마세요.

## 검증과 한계

- 기존 77개 화면 식별자를 새 버전의 대응 화면에 유지했고, 인증·결과·통합 데이터·미결정 화면을 추가했습니다. 원본 디자인과 모든 세부 기능의 1:1 재현을 뜻하지 않습니다.
- `node build.cjs`로 HTML 생성, `node check.cjs`로 오프라인 검증을 재현합니다. 최종 검사 결과는 [검증결과.json](검증결과.json)에 있습니다.
- 검사는 화면 생성, 경로, 금액 계산, 지갑 체크섬, 출금 상태, 보상 대상 제한, 저장·미리보기 등을 확인합니다.
- **브라우저 도구의 로컬 파일 접근 제한으로 실제 브라우저에서 클릭·모바일 줄바꿈·색 대비·스크린샷 검증은 수행하지 못했습니다.** 접근 제한을 우회하지 않았습니다. 오프라인 검사 통과를 실제 브라우저 검증 완료로 해석하면 안 됩니다.
- 한국어 검토용 버전입니다. 기존 언어팩 전체와 다국어 번역은 구현하지 않았습니다. 확정 문구는 개발 단계에서 언어팩으로 연결해야 합니다.
