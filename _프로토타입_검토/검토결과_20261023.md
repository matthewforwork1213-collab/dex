## 판단

**두 파일은 변경 영향과 논점을 모은 자료로는 유용하지만, 현재 상태 그대로를 최종 정책이 반영된 작동 예시로 개발팀·경영진에게 전달하기에는 수정이 필요합니다.**

가장 큰 이유는 세 가지입니다.

1. 기존 화면, 변경해야 할 내용, 변경 후 예시가 한 화면에 섞여 있습니다. 주석에서 오류라고 설명해도 화면 본문에는 그 오류가 남아 있습니다.
2. 출금 합계·비회원 경로·DEX 제외 기능처럼 이미 확정된 정책과 다른 사례가 있습니다.
3. 여러 선택기는 선택한 이름만 바꾸고 결과를 바꾸지 않습니다. 주소·금액 입력 및 저장을 실제로 체험할 수 있는 상태도 아닙니다.

이번 작업에서는 원본 두 HTML을 수정하지 않았습니다. 검토 근거와 수정 방향을 이 폴더에 기록했습니다. 사용자가 보류하라고 한 정책은 임의로 선택하지 않았습니다.

- 정책을 판별하는 표적 검사 17개: 8개 일치, 9개 불일치. 전체 품질의 통과율을 의미하지 않습니다.

**브라우저의 로컬 파일 접근이 보안 정책으로 차단됐습니다. 우회하지 않았습니다. 따라서 실제 클릭·스크롤·모바일 줄바꿈·화면 겹침·대비·키보드 조작을 브라우저에서 확인했다는 주장은 하지 않습니다.** 아래 동작 지적은 소스와 오프라인 함수 검사 근거입니다.

## 이번 대화에서 확정된 출금 결과 처리

**통합 출금 신청 안의 각 계정을 개별 처리합니다.**

| 개별 결과 | 처리 | 회원 이메일 |
|---|---|---|
| 성공 | 해당 건 성공 유지 | 해당 UID/지갑 계정의 성공 이메일 1건 |
| 실패 확정 | 해당 건 실패 처리. 기존 CEX 실패 처리 기준 사용 | 해당 UID/지갑 계정의 실패 이메일 1건 |
| 전송 여부 불명·결과 대기 | 성공/실패로 임의 확정하지 않음 | 판정·재확인 규칙은 미결정 유지 |

- 일부 실패 때문에 이미 성공한 건까지 전체 취소하는 정책이 아닙니다.
- DEX의 계정 식별자는 UID 대신 지갑 주소입니다.
- 비회원 알림 없음이라는 기존 정책은 유지합니다.
- “결과를 계정별로 보낼지 묶어 보낼지”와 “일부 성공을 유지할지”는 이제 미결정 목록에서 제외합니다.
- 성공·실패 이메일의 실제 발송, 자금 이동은 이번 검토에서 실행하지 않았습니다.

권장 시연 사례: 요청 3건 중 Bitget 성공, OKX 실패, Lighter 성공. 동일한 신청 아래 결과 3건을 보여주고 성공 메일 2건·실패 메일 1건의 예시를 연결합니다. 이는 이번 결정의 설명용 시나리오이며 새 금융 정책이 아닙니다.

## A. 확정 정책과 다른 내용 — 우선 수정

### A-01. 출금 목록·완료·공유의 금액과 계정 수 불일치

- 위치: 사용자 `wd/DW1` 823~855행, `wd/DW2` 881~893행, `wd/DW3` 897행 이후.
- 목록의 출금 가능액: Bitget 10.00 + OKX 31.68 + Lighter 120.00 = **161.68 USDT**.
- 상단 합계와 신청 완료·공유 카드는 **41.68 USDT**. DEX 120이 누락됐습니다.
- 신청 완료는 `Bitget +1`, 식별자도 `UID ... +1`로 두 건을 표시합니다. 현재 목록은 세 건입니다.
- 영향: 개발자는 DEX가 합계에서 제외된다고 오해하고, 경영진은 실제 지급 요청 규모를 잘못 이해합니다.
- 수정: 동일한 예시 데이터에서 계정별 매칭액·합계·건수·신청 후 잔액·결과를 함께 계산해야 합니다. 현 예시를 유지하면 합계 161.68, 계정 3개입니다. 대표 계정을 무엇으로 정할지는 별도 미결정으로 남깁니다.

### A-02. 비회원 출금이 회원 다중 출금으로 연결

- 위치: 사용자 `wd/NM` 912행 이후, `GO['wd/NM']`, `NEXT['wd/NM']`.
- 비회원 화면은 단일 Lighter 42 USDT인데 출금 버튼 목적지가 `wd/DW1`입니다.
- 그 화면에는 다른 CEX UID들과 DEX 지갑이 함께 등장합니다. `NEXT`도 회원 신청 완료로 연결합니다.
- 회원 완료 화면은 `+N`과 알림·이메일 발송을 약속합니다.
- 수정: 비회원 단일 지갑 → 캡차 → 해당 지갑 신청 접수 → 결과 확인 경로로 분리합니다. 회원의 여러 계정·OTP/이메일·완료 알림 문구를 가져오지 않습니다.

### A-03. 출금 부족액 안내가 매칭 공식과 다름

- 위치: 사용자 `wd/DW0` 872~877행.
- Lighter A=0, B=20인데 “페이백 10 USDT를 더 받으면 출금”이라고 표시합니다.
- 실제로는 A=5에서 5+MIN(20,5)=10이므로 **5 USDT가 더 필요**합니다.
- 수정: 부족액도 매칭 공식으로 계산합니다. 이벤트 리워드 잔액이 다른 계정에 같은 고정 안내액을 쓰지 않습니다.

### A-04. 허브 계산기의 지급 주체가 V1

- 위치: 사용자 `hub/H1-DEX` 499행 이후.
- 본문: “Lighter 계정으로 지급돼요.” 주석은 이 문장이 오류라고 설명합니다.
- 수정: 사용자 본문을 **“테더맥스 잔액으로 적립돼요”**로 변경합니다. 출금 안내에서는 “출금 신청 시 연동한 지갑으로 보내드려요”로 적립과 출금을 구분합니다.
- 주석만 읽으면 V2, 실제 카드만 읽으면 V1이 되는 상태를 해소해야 합니다.

### A-05. DEX 초대 리워드 제외 문구가 본문에 남음

- 위치: 사용자 `ph/PH1` 1146행 이후, `lnd/LND2` 606행 이후.
- 파트너 허브 본문에 “DEX 지갑은 초대 리워드 대상이 아닙니다”가 있습니다.
- 랜딩 설명에도 이벤트·초대 혜택은 CEX에서만 성립한다는 과거 설명이 있습니다.
- 수정: DEX도 이벤트·초대 리워드 대상이라는 현재 정책으로 본문·설명을 함께 바꿉니다. “퀴즈 보상만”이라는 과거 문구도 최종 정책처럼 보여주지 않습니다. 퀴즈 자체의 보상 여부는 미결정 목록에 유지합니다.

### A-06. DEX 제외인 챌린지가 내역에 존재

- 위치: 사용자 `hist/CS3` 927행 이후, `bnf/UIDM`, `cp/CP1`, `rule/R2`의 설명.
- 캘린더에 “페이백 챌린지 리워드 / Lighter / +50.00”이 있습니다.
- 다른 화면의 설명에는 “챌린지·리그는 전부 포함” 등 이전 판단이 남아 있습니다.
- 수정: DEX 예시 보상은 실제 지원하는 이벤트 리워드로 바꾸고, 챌린지 선택지·설명·내역을 CEX 전용 기준으로 통일합니다. 데이터 예시를 고치는 것이며 과거 실제 지급 기록을 삭제하라는 뜻이 아닙니다.

### A-07. DEX 소유확인 가이드를 어드민이 편집하는 모습

- 위치: 백오피스 `ex/EX-3` 382행 이후.
- 선택 거래소가 Lighter인데 “녹화를 시작한 뒤 지갑 연결을 해제하세요”라는 소유확인 슬라이드가 표시됩니다.
- 같은 화면의 주석은 DEX 소유권 미지원이라고 합니다.
- 수정: 소유 확인 가이드는 CEX 예시로 보여주거나 DEX 선택 시 해당 없음으로 비활성화합니다. DEX 지갑 주소 찾기 가이드는 별도 유지합니다.
- “CEX용으로도 신규 구축”이라는 제목은 “이미 있는 탭”이라는 최신 정정과도 맞춰야 합니다.

### A-08. DEX에 남은 페이백이 없다는 계정 장부

- 위치: 백오피스 `ac/AC-1` 473행 이후.
- DEX의 남은 페이백은 대시이며, 주석은 “DEX에는 테더맥스 미출금 잔액이 없다”고 합니다.
- V2에서는 DEX도 테더맥스 잔액이 있으므로 이 설명은 폐기돼야 합니다.
- 수정: 남은 잔액·누적 적립·누적 출금의 정의를 CEX와 같은 의미로 표시합니다. 예시 금액의 정확한 구성은 공통 데이터로 정합성을 맞춥니다. 임의로 새 잔액을 채우지 않습니다.

### A-09. 회원 금액 화면에서 최신 정정과 제목·예시가 반대

- 위치: 백오피스 `mb/MB-1` 531~542행, `mb/MB-4` 545행 이후.
- 최신 주석은 “기존 금액 컬럼에 DEX를 합산, V1 분리안 철회”라고 정정했습니다.
- 제목은 여전히 “DEX 금액을 섞으면 안 됩니다”이고 DEX 전용 회원의 현재 잔액 예시는 0입니다.
- 다른 주석은 DEX 별도 컬럼이 지급 의무 금액을 “오염시키지 않는다”고 표현합니다.
- 수정: 실제 잔액에는 DEX를 포함하고 운영상 거래소 유형별 구분이 필요한 정보는 별도 표기합니다. 정의가 다른 누적액·현재액을 단순 합치라는 뜻은 아닙니다. 최신 정정 하나만 남겨야 합니다.

### A-10. Affiliate 지급 계정에 DEX 선택지를 보여줌

- 위치: 백오피스 `pa/MB-2` 584행 이후.
- 제휴사 등록 모달에 Lighter·ApeX·EdgeX·Aster가 표시됩니다.

- 수정: 어드민 Affiliate 지급 계정은 CEX만 유지합니다. 일반 회원의 초대 리워드 출금에 DEX를 포함하는 정책과 구분합니다.

### A-11. Standard 허용 정책과 연동 선택 문구 불일치

- 상세 주석도 연동 시 경고한다고 설명합니다.
- 수정: 선택 행에서 연동 제한처럼 읽히는 표현을 제거하고, 상세·유의사항에 **“페이백은 Premium·Plus 계정에 적용됩니다”**로 설명합니다. Standard 연동 차단은 만들지 않습니다.

### A-12. Lighter 맥스보드의 조건이 화면에서 빠짐

- 위치: 사용자 `mb/MB1` 1125행 이후, 백오피스 `bd/LG-2` 778행 이후.

- “금액 칸만 운영할지 정해야 한다”, “배치 시각 미정”이라는 오래된 주석도 남아 있습니다.

### A-13. 브로커 어드민 제외가 일부 화면에만 반영

- 위치: 백오피스 `ex/EX-1`, `nw/NW-2`, `nw/NW-3`.

- 수정: 이번 작업 대상인 어드민 예시에서는 제외 기준을 통일합니다. 사용자 허브의 브로커 탭 유지와 혼동하지 않습니다.

## B. 작동 예시로 이해하기 어려운 부분

### B-01. 선택기는 이름만 바꾸고 결과를 바꾸지 않음

- 근거: 양쪽 파일의 `ddOpen` → `ddVal` → `ddClose`.
- 함수 검사에서 Lighter를 ApeX로 선택하면 표시값만 `ApeX`로 바뀌고 화면 상태는 그대로였습니다.
- 계산기 요율·예상 페이백, 거래소별 입력 설명, 필터 결과가 선택과 연결되지 않습니다.
- 수정: 시연에 필요한 최소 데이터 상태를 두고, 파트너·범위 선택에 따라 결과를 함께 갱신합니다. 실제 서버나 API 연결까지 요구하는 것은 아닙니다.

### B-02. CEX 전용 드롭다운의 “제외” 항목을 선택할 수 있음

- 위치: 백오피스 `ac/AC-2`, `EXTYPE_CEX`, 1220행 이후 선택기 핸들러.
- DEX 항목에 `no` 클래스를 붙여 취소선만 표시합니다.
- CSS에 선택 방지 처리가 없고 핸들러도 제외 여부를 검사하지 않습니다. 오프라인 함수 검사에서 DEX가 선택값으로 받아들여졌습니다.
- 수정: CEX 전용 필터는 고정 표시로 두거나 제외 항목을 아예 넣지 않습니다. 비활성 항목을 표시할 경우 이벤트도 차단해야 합니다.

### B-03. 입력·저장·계산이 가능한 폼처럼 보이지만 실제 입력 요소가 아님

- 두 파일의 각 업무 화면 생성 결과에는 기본 `input`, `select`, `textarea`, `button` 입력 요소가 없고 대부분 `div`·`span`입니다. 바깥 설명 도구의 버튼·체크박스는 별도입니다.
- 주소 입력 화면은 고정된 주소를 보여주고 다음 버튼은 바로 연동 성공으로 이동합니다.
- 계산기 거래량 바는 그림이며 값 입력·계산 변경을 체험할 수 없습니다.
- 어드민의 저장·검색·승인 중 다수는 설명만 있고 상태 변화가 없습니다.
- 수정: 주요 시연 경로에 한해 실제 입력·간단한 검증·저장 상태·결과를 구현합니다. 기능 범위 밖 버튼은 비활성 이유를 분명히 표시합니다. 실제 외부 발송·자금 이동은 하지 않습니다.

### B-04. 회원 출금 인증 단계가 동작 흐름에서 생략

- 위치: 사용자 `wd/DW1`의 출금 버튼은 `wd/DW2`로 직접 이동.
- 캡차·OTP 또는 이메일 인증의 상태가 49개 상태 목록에 없습니다. 관련 설명만 존재합니다.
- 수정: 회원 출금 시연에 확인·인증·요청 접수의 단계가 필요합니다. N-2의 계정 제한 정책까지 임의로 확정하는 것은 아닙니다. 실제 캡차나 인증 메일 전송이 아닌 명확한 시연용 상태여야 합니다.

### B-05. 계정별 성공·실패 결과를 볼 수 없음

- 현재 사용자 출금은 신청 완료·공유까지만 있습니다.
- 백오피스 `pb/PB-1`에는 결과 상태·공통 신청번호·온체인 증빙이 없어 하나의 다중 신청을 추적하기 어렵습니다.
- 이번 대화 결정에 맞춰 부분 성공 결과 예시와 계정별 성공·실패 이메일 예시가 필요합니다.
- 전송 결과 불명 상태의 판정·재시도 기준은 미결정으로 남깁니다.

### B-06. “신청 완료” 직후 “받으셨습니다” 공유 카드

- 위치: 사용자 `wd/DW2` → `wd/DW3`.
- 아직 지급 결과를 받기 전인데 “41.68 USDT를 받으셨습니다”라고 합니다.
- 신청 시각 11:34와 공유 시각 02:34도 달라 로컬 시간 표시 기준과 맞지 않습니다.
- 수정: 신청과 지급 완료를 분명히 구분합니다. 공유를 어느 시점에 허용할지·어디로 연결할지는 미결정으로 남기되, 대기 중인 건을 수령 완료로 표현하지 않습니다.

### B-07. 선택한 대상이 다음 화면에 이어지지 않음

- 예: 파트너 허브의 서로 다른 하위 회원 행이 모두 같은 `ph/PH3`로 이동하며 동일한 회원을 표시합니다.
- 예: Aster 만료의 다시 연동 경로는 `link/L3`로 가지만 입력 화면은 Lighter로 고정입니다.
- 예: `link/L3`에서 거래소 드롭다운을 바꿔도 성공 화면은 Lighter입니다.
- 수정: 선택한 거래소·회원·지갑을 화면 사이에서 유지합니다. 이를 위해 필요한 것은 예시 상태 연결이며 새 정책 결정이 아닙니다.

### B-08. 필요한 사용자 안내도 내부 설명으로 이동됨

- 공통 `liftComments()`가 `.note[data-kind]` 등을 일괄적으로 제품 영역 밖으로 옮깁니다.
- Aster 만료 안내의 “다시 연결하기”도 이 형태라 사용자 화면 안에서 빠집니다.
- 수정: 개발 검토 주석과 고객 안내 컴포넌트를 구분합니다. 고객에게 필요한 경고·안내·다음 행동은 제품 화면에 남겨야 합니다.

### B-09. 예시 데이터의 의미가 화면마다 다름

- `hub/H5`: 출금 가능 120인데 누적 페이백 40.
- `wd/NM`: 출금 가능 42인데 누적 페이백 0.
- `home/LKD`: Lighter 주간 정산 설명 옆 타임라인은 하루 간격. 날짜·시간은 고정값.
- `etc/EML`: 미정인 지급 체인이 Arbitrum으로 확정된 것처럼 보임.
- 수정: 하나의 예시 데이터로 잔액·누적·건수·기간을 맞춥니다. 네트워크·요율처럼 미정인 값은 화면 밖에 “설명용 예시, 정책 미확정”이라고 구분합니다. 임의로 운영값을 정하지 않습니다.

### B-10. 잘못 연결된 선택기 구성

- 백오피스 이메일 캠페인의 거래소 값 입력란이 거래소 선택이 아니라 숫자 임계값 목록(`AMTVAL`)에 연결됩니다. 거래소 항목명 쪽에는 약 40개 푸시 대상 목록(`EXPUSH`)을 연결했습니다.
- 강조할 거래소처럼 단일 파트너를 선택하는 곳에도 전체/CEX 전체/DEX 전체 범위가 나옵니다.
- 거래소 생성 폼의 주기·요일은 선택값처럼 보이지만 고정 문자열입니다.
- 수정: 조건 종류, 비교 연산자, 선택값을 각각 맞는 컨트롤로 연결합니다. 필터용 전체 옵션을 단일 거래소 지정에 재사용하지 않습니다.

## C. 개발팀·경영진이 읽을 때의 설명 개선

### C-01. 현재 화면과 변경 후 예시를 명시적으로 분리

현재 파일은 “영향도” 자료이므로 기존 오류를 보여주려는 의도가 있습니다. 그러나 초기 안내는 클릭하며 실제 흐름을 따라갈 수 있다고 설명하고, 이미 변경한 예시도 같은 방식으로 보여줍니다. 독자는 어느 쪽이 최종 모습인지 판단해야 합니다.

권장 구성:

1. 기본 화면은 **확정 정책을 적용한 예시**.
2. 각 화면 오른쪽 설명은 **무엇이 바뀌는지 / 확정 기준 / 개발 시 확인할 점** 세 항목.
3. 이전 화면이 필요하면 **현재 서비스 화면**이라고 명시해 따로 비교.
4. 미결정은 마지막 **결정이 필요한 사항**에 모으고, 해당 예시의 값은 확정으로 표시하지 않음.

이는 보고 자료 구성 제안입니다. 미정 사업 정책을 정하는 제안이 아닙니다.

### C-02. 내부 약어 대신 업무 이름 사용

| 현재 표현 | 먼저 보여줄 표현 |
|---|---|
| ELC | DEX 소개 목록의 카드 편집 |
| EDC | 거래소 상세 페이지 편집 |
| SPE / Spending Estimate | 예상 페이백 계산기 설정 |
| TUID | 회원 번호 |
| Processing | 연동 확인 중 |
| Wallet A / Wallet B | 커미션 수취 지갑 / 고객 지급 지갑 |
| 3 / 2 | CEX 계정 3개 · DEX 지갑 2개 |
| 패스스루 | 거래소가 제공한 페이백 금액 그대로 반영 |
| NEXT / 상태 기계 / 파급 | 다음 단계 / 처리 상태 / 함께 바뀌는 화면 |

개발용 식별자는 보조 정보로 남길 수 있습니다. 첫 독해에 필요한 설명은 일반 언어여야 합니다.

### C-03. 작업 경위와 감정 표현을 결론으로 바꾸기

현재 주석에는 “제가 틀렸습니다”, “함정”, “영영”, “가혹하게”, “전부 틀립니다” 등의 표현과 과거 작업 경위가 많습니다. 개발자에게 필요한 것은 현재 기준과 수정 범위입니다.

예:

- 기존: “제가 여기 기록했던 DEX 불가라는 것은 V1 전제였고 지금은 무효입니다.”
- 권장: **“DEX도 이벤트 리워드를 지급합니다. 이벤트 유형 두 가지 모두 DEX를 선택할 수 있어야 합니다.”**

- 기존: “영수증 카드가 잔액 패널로 바뀝니다.”
- 권장: **“사용자가 출금할 수 있는 잔액을 표시합니다. 출금하면 잔액이 줄어듭니다.”**

### C-04. 같은 화면의 확정·미정 충돌 제거

마일스톤은 위 주석에서 “확정”, 아래에서 “재확정 필요”라고 합니다. 리뷰 자격도 연동 완료로 확정했다가 뒤에서 다시 질문합니다. 금액 컬럼은 합산·분리가 동시에 적혀 있습니다.

확정된 내용은 한 문장으로 남기고, 사용자가 보류한 내용은 미결정 하나로 정리해야 합니다. 해결된 항목을 미결정 목록에 다시 넣지 않습니다.

### C-05. 설명 표시 품질

- 설명 패널은 `esc()`로 주석 전체를 이스케이프하므로 주석 속 `<b>`·`<code>`가 서식 대신 문자로 보일 수 있습니다. 이는 패널 생성 코드에서 확인됩니다.
- 사용자 패널 범례에 “언어팩 신규”가 두 번 들어 있습니다.
- 한국어 보기에서도 제품·내부 설명이 영문으로 섞여 있습니다. 모든 15개 언어 구현을 요구하는 것이 아니라 이번 한국어 보고에서 핵심 설명을 이해할 수 있게 해야 합니다.
- 키보드 조작은 실제 브라우저 검증을 하지 못했습니다. 다수 업무 버튼이 `div`·`span`이며 역할·포커스 처리도 별도 확인이 필요합니다.

## D. 현재 반영이 확인되는 부분

아래는 해당 예시의 표현·구성이 정책과 맞는 부분입니다. 해당 기능의 실서비스 구현 완료를 뜻하지 않습니다.

- 일반 페이백 출금 목록은 CEX·DEX 통합이며 탭이 없습니다.
- CEX 예시의 A=5, B=232에서 출금 가능 10이라는 매칭 예시는 맞습니다.
- 사용자 소유권 중복 화면은 소유권 신청 대신 CS 문의로 안내합니다.
- Standard 전용 상태는 경고 없이 다음 단계로 진행하도록 표현합니다.
- 챌린지 수령 계정 모달과 부스트 목록에는 DEX가 없습니다.
- 일반 쿠폰과 일반 회원 초대 출금에는 DEX 지갑이 포함됩니다.
- 백오피스 생성 폼에서 DEX 소유 확인 유튜브를 해당 없음으로 처리합니다.
- 수동 연동 설명에는 원장 존재 조건과 운영자 임의 승인 금지가 있습니다.
- 계산기 설정은 최소·최대 범위만 남기고 별도 요율 입력 표를 제거했습니다.
- 최신 연동 한도 화면은 CEX 기존 규칙과 DEX 명세의 관계를 미결정으로 표시합니다.

## E. 미결정·추가 확인 목록

별도 파일 `미결정_목록_20261023.md`에 기존 보류 사항, 방금 추가된 N-1~N-6, 이번 검토에서 추가로 드러난 사항을 모았습니다. 이번에 확정된 부분 성공 유지·계정별 결과 이메일은 보류 목록에서 제외했습니다.

## F. 수정 순서 제안

1. **정책 오해를 만드는 본문부터 수정:** 지급 주체, 초대/챌린지/소유권, 회원·계정 잔액, Affiliate 선택 범위.
2. **출금 흐름 연결:** 동일 데이터의 합계·건수 → 회원 인증/비회원 단일 흐름 → 요청 접수 → 계정별 결과·메일 예시.
3. **주요 조작 연결:** 주소 입력, 거래소 선택, 계산기, 필터, 저장 후 결과. 외부 서비스 연결은 제외한 시연용 구현.
4. **설명 정리:** 변경 후 예시를 기본으로, 내부 경위 제거, 쉬운 업무 명칭, 미결정 한곳에 정리.
5. **브라우저 검증:** PC·모바일, 한국어·영어, 밝은/어두운 테마에서 실제 클릭·줄바꿈·스크롤·키보드 동작 확인. 이번 검토에서는 이 단계가 완료되지 않았습니다.
