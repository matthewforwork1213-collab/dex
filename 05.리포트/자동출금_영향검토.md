# 자동 출금(10분 주기) 정책 변경 — 영향 검토

작성일: 2026-11-16
상태: **결정 완료 · 반영 완료** — 정책(`00_DEX_최종정책.md`) → 요구사항정의서 → 기능명세서 4종 → API스펙 2종 → 정보구조도 2종. 남은 것: 문구 재작성 G-419 · 법무 G-425.

## 1. 확정된 내용 (사용자 결정 2026-11-16)

| 항목 | 내용 |
|---|---|
| 방식 | **신청 없이 자동 지급.** 10분마다 계정별 출금 가능액을 확인해 기준(10 USDT) 이상이면 시스템이 **기존 출금 신청 API를 자동으로 호출**합니다. 회원이 테더맥스에 들어오지 않아도 출금됩니다 |
| 적용 범위 | **회원의 CEX·DEX 모두** |
| 출금 화면 | **유지.** 잔액·계정 카드·상태 표시용 |
| 출금 버튼 | **캐시백 출금 버튼은 전부 `Auto Claim`, 비활성(클릭 불가).** 홈 `Total Cashback Balance` · 캐시백 허브 패널 · 거래소/DEX 상세 · DEX 카드 · 지갑 상세 · 출금 화면 모두 같음. 출금 팝업·확인 다이얼로그·보안 인증 화면은 진입점이 없어져 회원 화면에서 빠짐 |
| 버튼 주변 안내 | **현재 화면 그대로 둠.** 자동 지급 안내 문구를 새로 넣지 않음 |
| 보안 제한 | **자동 지급에는 걸지 않음.** 비밀번호 변경 후 72시간 · 이메일 인증 실패 24시간 등 회원 신청 시의 보안 제한으로 자동 지급을 보류하지 않음 |
| 처리 결과 표시 | **회원이 볼 수 있는 UI 없음.** 처리 중·완료·실패 화면, 신청 완료 화면, 공유 카드를 두지 않음 |
| 초대 리워드 출금 | **초대 리워드도 `Auto Claim`(비활성).** 받을 계정은 관리자가 그 회원의 연동 계정으로 지정(3장 G-410) |
| 게스트(비회원) | **DEX 배포와 함께 게스트 기능 자체를 없앰.** CEX 포함, 비회원은 테더맥스를 쓸 수 없음 — 자동 지급 대상 문제 자체가 없어짐 (영향은 5장) |

### 1.1 STG 현재 화면 (www-dev, 회원, 2026-11-16 확인)

| 위치 | 현재 모습 | 자동 지급과의 관계 |
|---|---|---|
| 출금 화면 `/withdrawal-apply` (제목 `Claim`) | 상단 `Total Claimable Cashback` · UID별 카드(`Exchange Cashback` · `Event Reward` · `Unclaimable` 칩 · `You can claim cashback if you receive an additional N USDT in exchange Cashback.`) · 하단 `No UIDs are eligible to claim.` · **`Auto Claim` 버튼** · `Back to Home` | 기존에 회원이 출금을 신청하던 버튼. 자동 지급으로 바뀌면서 **비활성으로 막아 둔 상태이며 없애지 않음** |
| 회원 홈 `/` | `Auto Claim` 버튼 노출 | 같음 |
| 카드의 남은 금액 | 이벤트 리워드가 충분한 계정은 5.00, 리워드가 없는 계정은 10.00으로 표시 | 매칭 공식 `A + MIN(B, A)` ≥ 10과 일치 |

## 2. 요구사항별 처리

| 영역 | 해당 요구사항 | 처리 |
|---|---|---|
| 출금 진입·출금 창 | REQ-133 진입 · REQ-134~150 출금 창·카드·합계·상태 · REQ-270 홈 출금 진입 · REQ-302 허브 패널 `Withdraw` | 진입 버튼 = 비활성 `Auto Claim`. 출금 화면은 잔액·카드·상태 표시만. 안내 문구 추가 없음 |
| 확인·보안 인증 | REQ-151~157 (확인 다이얼로그 · 캡차 · OTP/이메일 · 24h/72h · KYC) | 회원 화면에서 **제거.** 보안 제한을 자동 지급 보류로 옮기지 않음. KYC 미완료 UID 처리(거래소 규칙, 예: `withdrawal of cashback will not proceed for UIDs that have not completed KYC`)는 현행 정책(3장 G-415) |
| 신청 생성·선차감·멱등 | REQ-158~161 · REQ-169 · REQ-258(출금 서비스) · API-011 | 시스템이 10분마다 같은 신청 API 호출. 계정별 1회 지급·선차감·멱등 원칙 유지 |
| 결과 전달 | REQ-162~168 · REQ-172 (결과 · 완료 화면 · 공유 카드 · 출금 후 흐름) | **제거**(볼 수 있는 UI 없음) |
| 출금 메일·푸시 | REQ-170·673 출금 메일 · REQ-665·666 (FCM 104·105) · REQ-674 FCM 26 「출금 가능 알림」 | 현행 정책을 따름(3장 G-405 · G-277) |
| 지급 운영 | REQ-231~255 (Wallet B · 리밸런싱 1일 1회 · 잔액 부족 = 지연 · 재시도 · 실패 복원) · JOB-D10 | Wallet B 충전은 운영팀 소관 · 실패 복원액 재지급은 현행 정책(3장 G-407 · G-408) |
| 연동 전 잔액 | REQ-107 · REQ-108 · REQ-720 | 연동을 막지 않고 연동 전 잔액 10 USDT 이상이면 그 계정으로 출금한 뒤 자동 연동(3장 G-409) |
| 초대 리워드 출금 | REQ-414~416 (전액·1곳 선택·최소 50 USDT·보안 확인) | 버튼 비활성 `Auto Claim`. 계정 선택 모달·보안 확인 제거. 받을 계정은 관리자 지정(3장 G-410) |
| 출금이 트리거인 기능 | REQ-171·398 첫 출금 혜택 · REQ-411·412 초대 리워드 실적 · REQ-450 TP 적립 · REQ-285 실시간 출금 피드 | 자동 지급 완료 = 출금(3장 G-411) |
| 게스트 | REQ-180 CEX 게스트 경로 · 게스트 관련 요구사항 전부 | 게스트 기능 폐지(5장) |

## 4. 결정 없이 유효한 원칙

- 계정별 1회 지급 · 멱등 · 요청액 = 도착액 · 가스비 테더맥스 부담 · 목적지는 연동 계정 고정.
- 지급 단위는 계정(CEX UID / DEX 지갑)이며, 한 계정의 실패가 다른 계정에 영향을 주지 않습니다.

## 5. 게스트 기능 폐지의 영향

DEX 배포와 함께 비회원 기능(CEX 포함)을 없애므로, 산출물의 「게스트는 DEX 불가」 예외 규칙은 「게스트 기능 없음」으로 바뀝니다.

| 대상 | 현재 | 바뀌는 것 |
|---|---|---|
| 게스트 조회·출금 화면 | `/search`(`Get your cashback, no sign-up needed`) · 홈 게스트 조회 카드(`Claim cashback`) · `/withdrawal` 게스트 진입 | 화면·진입점 제거, 회원가입·로그인으로 안내 |
| 게스트 API | `/guest/get-guest-search-uid` · `/guest/payback-init-withdrawal` · `/guest/payback-withdrawal` (API-023) | 폐기. 다른 `/guest/*`는 비로그인 공개 콘텐츠 API라 별개 |
| 요구사항 | REQ-180 게스트 경로 · 게스트 DEX 거부 규칙 · 게스트용 지갑 다이얼로그 언급 | 「게스트 기능 폐지」 하나로 정리 |
| 개인정보처리방침 | (c) `information of Non-Member collected when using the cashback service` | 수집 항목 삭제 — 법무 검토 (STG_대조_점검 S-08) |
| 콘텐츠 문구 | 홈 FAQ 비회원 답변 · `Cashback Basics` `Guest can select their exchange…` · `/search` 문구 | 삭제 (S-10·S-11) |
| 이메일·알림 | 게스트 이메일 인증·출금 메일 | 폐기 |
| 기존 게스트 잔액 | 게스트로 조회만 하고 출금하지 않은 UID의 잔액 | 그 UID로 회원가입 후 연동할 때 10 USDT 이상이면 그 UID로 출금한 뒤 연동, 미만이면 이관(G-416) |
| 비회원 `/payback` 계산기 | 비로그인 캐시백 테스트 | 공개 화면으로 비로그인도 열람 — 캐시백 조회·출금만 막음(G-417) |
