### 2-2. 출금 인증·접수·취소 메일의 발송 기준

자동 지급 접수 메일(T11)은 현행 발송 경로를 사용한다. 회원이 직접 출금을 요청할 때 쓰던 인증(T10)과 취소(T12)는 신규 발송하지 않는다. 과거 발송 이력은 보존한다.

| # | 템플릿 (EN / KO) | 이유 |
|---|---|---|
| T10 | Cashback withdrawal request verification code (`12727:391621` / `14849:433982`) | 출금 이메일 인증 없음(정책 A-25) |
| T11 | Cashback application received successfully (`12727:391696` / `14972:296`) | 자동 지급 접수 시 기존 운영과 같은 기준으로 발송(G-405). 회원이 신청했다는 표현을 제거하고 거래 계정은 1장 규칙으로 표시 |
| T12 | Cancel Cashback Request (`12727:391764` / `14972:698`) | 회원 신청·취소 없음. 출금 취소 메일은 원래 미채택(REQ Won't) |

## 4. 시안과 발송 구현 확인

1. [DEX 수정본 이메일 섹션](https://www.figma.com/design/hsa3bSV9QmFTe2jsf6tzTm/UI-UX-Design?node-id=29060-101537)에서 EN·KO 데스크톱·모바일 시안을 확인한다. 표 안의 개별 노드 번호는 변경 전 원본을 가리킨다.
2. T6·T7에서 이전 72시간 제한이 발송 본문에 남아 있는지 확인한다.
3. KO 템플릿은 `캐시백` 용어, T14 거래소·계정 라벨, T35 탈퇴 안내 오자를 확인한다.
4. 접수(T11)와 결과(T13·T14·T33)는 G-405의 운영 트리거를 따른다. 기존 운영에서 여러 결과를 묶을 때만 T33을 사용한다.
5. T10·T12의 신규 발송을 중단하고 과거 이력은 조회할 수 있도록 한다.
6. EMAIL 30·31은 DEX 수정본을 기준으로 구현한다. EMAIL 31에서 운영자 거절 사유와 자동 거절 안내를 구분한다.
7. 나머지 4개 언어판 — 번역 확정 후.
