# 기존 디자인 카탈로그 작성 지시 (담당 공통)

## 목적
Figma `UI-UX Design`의 기존 사용자 화면 페이지를 **실제 화면(캡처)으로** 확인해, DEX(revision) 페이지를 고칠 때 근거로 쓸 「현행 기존 디자인」 카탈로그를 만든다. 프레임 이름·색인만 보고 판정하지 않는다.

## Figma
fileKey `hsa3bSV9QmFTe2jsf6tzTm`, 세션 id `660d3975-179e-4fff-85af-c8c8424ba17b`(모든 호출에 sessionId). **읽기 전용 — 노드를 바꾸지 않는다.** 페이지 구조는 `_프로토타입_전체/ref/figma_pages/<pageid>.xml`(오프라인 메타데이터)과 색인 `_프로토타입_전체/ref/figma_index.tsv`, `python -I _프로토타입_전체/tools/figfind.py`로 먼저 파악하고 Figma 호출은 캡처·텍스트 확인에만 쓴다. 한도에 걸리면 30~60초 기다렸다 재시도.

## 방법
1. 담당 페이지마다 **라이트 모드 섹션** 목록을 만든다(다크·숨김·QA 스크린샷 보드·아이디어 덤프는 제외하되 존재는 기록).
2. 섹션마다 `get_screenshot`을 큰 해상도(섹션 크기에 맞춰 maxDimension 3000~6000, 글자·라벨이 읽히게)로 받아 저장한다. 섹션이 너무 크면(예: 랜딩 전체) 하위 section 단위로 나눈다. 저장: `05.리포트/기존디자인_카탈로그/img/<pageid>__<sectionid>.jpg`(Pillow로 jpg 품질 80, 긴 변 4000 이하로 줄이되 라벨이 읽혀야 함).
3. 캡처를 **직접 보고** 섹션 안 화면들을 판정한다: 각 화면 = 라벨(상태 이름) · 노드 id · 플랫폼(Web/mWeb/mAPP) · 무엇을 보여 주는 화면인지 한 줄.
4. **판이 여러 개인 화면**(같은 화면의 개정안·MAXOP 개정·QA 수정판·Lo-fi 등)은 따로 표로 묶는다: 판 이름 · 섹션 · 노드 · 날짜/MAXOP 번호(섹션 이름에 있으면) · 차이 한 줄 · **현행으로 보이는 판과 그 근거**(섹션 이름의 날짜, 「Ready for Dev」·「QA」 표시, 최신 MAXOP 번호, DEX(revision)이 인스턴스로 쓰는 판 등). 근거가 약하면 「사용자 확인 필요」.
5. DEX 작업에 쓸 만한 **상태 컴포넌트**(빈 상태·로딩/스켈레톤·오류 토스트·스낵바·다이얼로그·바텀시트·인라인 오류·비활성 버튼·배지/칩)를 따로 모아 표로: 종류 · 페이지 · 노드 · 캡처 파일.

## 산출물
- `05.리포트/기존디자인_카탈로그/<묶음>.md` 하나(다른 파일 수정 금지). 페이지별 절: 섹션 표(섹션 · 노드 · 캡처 이미지 링크 `![](img/…jpg)` · 화면 수) → 화면 판정 표 → 판이 여러 개인 화면 표 → 상태 컴포넌트 표.
- 맨 위 요약: 페이지 수 · 섹션 수 · 캡처 수 · 판이 여러 개인 화면 수 · 「사용자 확인 필요」 목록.
