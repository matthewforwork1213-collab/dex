# 1. 맥스보드란

```
3×3 빙고판, 거래소 1곳 단위로 반복 운영

  금액 칸 — 페이백 목표액 도달 시 게이지를 써서 체크
  연속 칸 — N일 연속 페이백 시 활성화 (게이지 소모 없음, 한 번 열리면 영구 유지)

리워드  가로 3줄 + 세로 3줄 + 빙고판 완성 1 = 최대 7개, 인원 무제한
랭킹    빙고판별 ON/OFF. 완성자 한정, 총 페이백 순위, 매일 갱신
자격    참여 시작일 30일 전부터 테더맥스 DB에 등록된 UID (TUID 아닌 UID 기준)
소급    참여 시작일부터 자동 적립. 비회원 기간도 인정
```

> PRD 한 줄 요약: *"새로 등록한 UID로 거래하면 받는 **페이백이 그대로 빙고 게이지**가 되고,
> 가로·세로 줄과 빙고판을 완성할 때마다 **인원 제한 없이** USDT 리워드를 받는 신규 활성화 이벤트"*

## 1-1. 단계 구성

| 랭킹 ON | 랭킹 OFF |
|---|---|
| 사전공개 → 참여 → 집계 → **결과 발표** → 지급 (5단계) | 사전공개 → 참여 → 집계 → 지급 (4단계) |

- 단계 전환은 **UTC 00:00** 자동
- 첫 단계 시작일만 입력, 이후는 자동 연결. **단계 생략 불가**
- 등록 후 사전공개 전까지는 `노출 전` (사용자에게 404)
- 지급 기간 종료 후 페이지 삭제

# 2. ✅ DEX 적용 가능 — `volume` 불필요

기존에 맥스보드를 *"`symbol`·`volume` 제공 시에만 작동"* 으로 분류했으나 **오류였습니다.**

| 요소 | 산정 기준 | 근거 |
|---|---|---|
| 빙고 게이지 | **페이백 금액** | 서비스기획서 §1.1 |
| 금액 칸 체크 | **페이백 목표액** | REQ-078 |
| 연속 칸 | **페이백 배치 반영일 기준 연속 일수** | REQ-040 |
| 랭킹 | **총 페이백 순위** | §4.2 MVP |
| 리워드 설계 | *"칸 목표 금액은 페이백 금액"* | §6.2 |

**거래량이 쓰이는 곳이 한 군데도 없습니다.** DEX도 커미션 페이백 금액을 산출할 수 있으므로 그대로 성립합니다.

→ 거래소 API 요청서에서 `symbol`·`volume` 요청을 **철회**했고,
→ V2 재판정에서 맥스보드를 **조건부 → O** 로 승격했습니다.

# 3. ⚠️ 충돌 1 — Lighter 연속 칸이 열리지 않습니다

## 3-1. 문제

> **REQ-040**: 연속 칸은 **페이백 배치 반영일 기준 N일 연속** 페이백을 받으면 활성화된다.
> 기준일은 **페이백 배치 반영일**(빙고 Batch 실행일 아님). 하루 금액 조건 없음(**0.01 이상**이면 인정).

**Lighter는 주 1회(월요일, 전주 월~일) 정산**입니다.
7일 중 1일만 페이백이 찍히므로 **2일 연속조차 성립하지 않습니다.**

| 거래소 | 정산 주기 | 연속 칸 | 금액 칸 |
|---|---|:-:|:-:|
| **Lighter** | **주 1회 (월)** | **❌ 영구 불가** | ✅ |
| ApeX | 시간당 | ✅ | ✅ |
| EdgeX | 일 1회 00:00 UTC | ✅ | ✅ |
| Aster | 일 1회 (09:00 공개) | ✅ | ✅ |

## 3-2. 대응 — **정산 주기 변경이 전제** (2026-10-21 확정)

> **결정:** Lighter 맥스보드는 **정산 주기가 바뀌지 않으면 하지 않습니다.**

```
전제 조건 — Lighter에 일 단위 원장 제공 요청
   지급은 주 1회로 유지해도 됨.
   연속 판정은 "지급일"이 아니라 "원장 반영일" 기준이므로
   일별 원장만 있으면 해결됨.
   → 거래소 API 요청서 4-3 Lighter 6번에 반영 완료

변경 불가 시 → Lighter 빙고판을 열지 않음
```

### 선택지로만 남겨두는 것 — 금액 칸만 구성

PRD는 금액 칸만으로 구성하는 것도 지원합니다.

> **REQ-113**: *"금액 칸만이면 연속 카드를 숨기고 남은 카드를 전체 폭으로 표시"*
> **REQ-122**: *"금액 칸: 사용 가능 게이지 ≥ 목표 금액인 미체크 칸 수"*

**기술적으로는 가능하지만 운영 판단으로 하지 않기로 했습니다.**
연속 칸은 *"거래 습관을 만드는 장치"*(서비스기획서 §4.1 차별점 4)이고,
이것이 빠지면 맥스보드의 핵심 가치 중 하나가 사라지기 때문입니다.

> 추후 정책이 바뀌면 **백오피스 설정만으로** 금액 칸 전용 빙고판을 만들 수 있습니다.
> 별도 개발은 필요 없습니다.

## 3-3. (참고) 금액 칸만 구성 시의 화면 차이

향후 정책이 바뀔 경우를 대비해 기록만 해 둡니다.

| 요소 | 혼합 구성 | **금액 칸만** |
|---|---|---|
| 게이지 카드 | 표시 | 표시 (전체 폭) |
| 연속 기록 카드 | 표시 | **숨김** |
| 연속 진행 막대 | 표시 | **숨김** (REQ-113: *"연속 칸이 없으면 막대 없음"*) |
| `체크 가능한 최대 칸` | 금액 + 연속 합산 | 금액 칸만 집계 |
| 칸 표시 | `5 USDT` / `4일` 혼재 | `5 USDT` 만 |

# 4. ⚠️ 충돌 2 — 빙고 Batch 시각 ↔ Aster 09:00

## 4-1. 문제

> **REQ-036**: 빙고 Batch는 페이백 배치 결과를 불러오는 맥스보드 전용 일 배치로,
> **하루 1회 모든 거래소 공통 고정 시각**(설정값, **Bitget 페이백 배치 이후**, 구체 시각 미정 `#BATCH`)에
> 게이지·연속 기록·연속 칸 활성화·랭킹을 함께 갱신한다.

**Aster는 00:00 UTC 산정 → 09:00 이후 공개**입니다.
빙고 Batch가 09:00보다 빠르면 **Aster 페이백이 매일 하루씩 밀리고, 연속 판정도 같이 밀립니다.**

## 4-2. 현재 기본값은 안전합니다

PRD의 Open Issue `#BATCH` 에 **개발 기본값이 `12:30 UTC`** 로 적혀 있습니다.

```
Aster 공개  09:00 UTC
빙고 Batch  12:30 UTC   ← 3시간 30분 여유. 현재 기본값은 안전
```

**다만 확정값이 아닙니다.** 빙고 Batch 시각을 최종 확정할 때 조건이 하나 늘어야 합니다.

```
기존 조건  Bitget 페이백 배치 이후
추가 조건  + Aster 09:00 UTC 이후        ← DEX 반영 시 필수
```

## 4-3. 완충 장치는 이미 있습니다

> **REQ-040**: 빙고 Batch 시점에 그날 페이백 배치가 아직 끝나지 않았으면
> **그 날짜를 끊김으로 판정하지 않고 다음 빙고 Batch에서 판정**한다.
> (페이백 시스템이 거래소별·날짜별 완료 상태를 내려줌)

→ Aster가 늦어도 **연속이 곧바로 끊기지는 않습니다.** 판정이 하루 미뤄질 뿐입니다.
다만 사용자 화면의 게이지 반영은 하루 밀리므로, **REQ-063 지연 안내**가 매일 뜨게 됩니다.

> **REQ-063**: 빙고 Batch 지연 시 *"페이백 반영이 지연되고 있어요"* 안내 표시.
> 지연 = 빙고 Batch 예정 시각 + 3시간이 지나도 미완료인 동안.

# 5. 📝 표현 수정 — "UID" → "지갑"

맥스보드 PRD는 **거래소명을 변수로 쓰되 "UID"는 고정 표현**으로 두고 있습니다.

> **REQ-077**: 자격 UID 없음 문구는 거래소명을 변수로 씀
> (제목 *"참여할 수 있는 **{거래소} UID**가 없어요"*, **하드코딩 금지**)

DEX는 UID가 없고 **지갑 주소**가 식별자입니다. 다음 문구들이 분기되어야 합니다.

| REQ | 현재 문구 | DEX |
|---|---|---|
| REQ-077 | *"참여할 수 있는 {거래소} UID가 없어요"* | *"참여할 수 있는 {거래소} 지갑이 없어요"* |
| REQ-030 | *"참여 중이던 UID로 더 이상 참여할 수 없어요"* | *"…지갑으로…"* |
| REQ-030 | *"새 UID를 연동하면 다시 참여할 수 있어요"* + `[UID 연동하기]` | *"새 지갑을…"* + `[지갑 연동하기]` |
| REQ-028 | *"새 UID를 선택하면 이 빙고판의 진행이 처음부터 다시 시작돼요"* | *"새 지갑을…"* |
| REQ-124 | `UID 연동하기` 버튼 | `지갑 연동하기` |

**EN도 동일합니다** — `UID` → `wallet`, `You Can No Longer Participate with This UID` → `…This Wallet`.

> 이 문구들은 **하드코딩 언어팩(15개 언어)** 영역입니다. 거래소 타입별 분기가 필요합니다.

# 6. ✅ 그대로 적용되는 규칙

DEX에 특별한 처리가 필요 없는 항목들입니다.

| REQ | 규칙 | DEX 적용 |
|---|---|---|
| REQ-022 | 자격 판정은 **TUID가 아니라 UID 기준** | 지갑 단위로 판정 |
| REQ-023 | 참여 시작일 **30일 전**부터 DB 등록된 UID만 참여. 기준일 = **테더맥스 DB 최초 등록일**(재연동해도 불변) | 동일 |
| REQ-028 | 참여 UID 등록 후 **변경 불가** | 동일 |
| REQ-030 | **소유권 이전·이슈 UID 지정 → 초기화(`RESET`)**, 새 UID 선택 가능 | **DEX는 소유권 경로가 없어 `OWNERSHIP_TRANSFER` 분기가 발생하지 않습니다.** `ISSUE_UID` 분기만 적용 |
| REQ-031 | 집계 시작 이후~지급 전에 잃으면 **소멸(`FORFEITED`)**, 리워드 없음 | 동일 |
| REQ-032 | 소유권 이전돼도 **참여가 새 TUID로 넘어가지 않음** | 동일 |
| REQ-035 | **비회원 UID도 게이지 기록**, 연동 시 소급 | 비회원 지갑도 동일 |
| REQ-114 | **이슈 UID는 참여 UID로 선택 불가** | 이슈 지갑도 동일 |
| REQ-108 | 유의사항 **15개 언어** | 동일 |
| REQ-053 | 단계 전환 **UTC 00:00**, 사용자 화면은 **기기 로컬 시간으로 변환** | 동일 |

## 6-1. ★ 소유권 이전 연계 — DEX에는 해당 없음 (2026-10-22)

맥스보드는 **소유권 이전을 직접 확인**합니다 (REQ-032).

```
확인 시점  ① 사용자 요청 시
           ② 매일 빙고 Batch (참여 기간 이후에도 지급 완료까지 계속)
           ③ 리워드 확정·적립 직전
판정 시각  테더맥스 계정 DB 이력의 시각
```

**DEX는 소유권 인증을 지원하지 않기로 확정**되었으므로(V2 재판정 2-2),
**DEX 지갑에서는 `OWNERSHIP_TRANSFER` 로 인한 초기화·소멸이 발생하지 않습니다.**

| 사유 | CEX UID | DEX 지갑 |
|---|:-:|:-:|
| `OWNERSHIP_TRANSFER` | ✅ | **해당 없음** |
| `ISSUE_UID` | ✅ | ✅ |

→ DEX 지갑이 참여 UID 자격을 잃는 경우는 **이슈 지갑 지정 한 가지**로 좁혀집니다.
→ 그만큼 **DEX 참가자의 초기화 리스크가 CEX보다 낮습니다.**

# 7. 백오피스 — DEX 반영

## 7-1. 빙고판 생성 (REQ-001)

> **빙고판 1개는 거래소 1개에 대응.** 생성 시 거래소 1곳만 선택 가능.

→ **거래소 드롭다운에 DEX 4곳을 추가**해야 합니다.
(글로벌리그 생성 폼과 같은 성격의 작업입니다 — 백오피스 문서 7-2 참조)

## 7-2. 메뉴 위치

```
리그/보드                    ← 기존 "리그" 에서 변경됨
 ├─ 글로벌 리그 목록
 ├─ 글로벌 리그 팀 목록
 └─ 맥스보드 목록            ← 여기
```

## 7-3. 등록 후 수정 불가 항목

> 확인 팝업: *"등록하면 **거래소, 랭킹 ON/OFF, 기간, 칸 조건, 리워드 금액**은 수정할 수 없습니다"*

**Lighter 빙고판을 금액 칸만으로 만들지 여부는 등록 전에 결정해야 합니다.** 나중에 못 바꿉니다.

## 7-4. 운영 모니터링

| 지표 | 내용 |
|---|---|
| 상단 요약 | 빙고판명, 현재 상태, **거래소**, 랭킹, 단계별 기간, **1인당 비용 합계**, [수정]·[강제 종료] |
| 현황 탭 | 참여 UID, 완성자, **연속 칸 활성화 수**, 줄별 달성 수(6줄), 예상 지급액 |

> **Lighter 빙고판에서 "연속 칸 활성화 수"는 항상 0입니다.** (금액 칸만 구성 시 지표 자체가 무의미)

# 8. 운영 주의 — 같은 거래소 기간 중복

> **REQ-002**: 같은 거래소 빙고판을 참여 기간이 겹치게 열면
> **같은 UID가 같은 페이백으로 리워드를 이중으로 받으므로** 운영에서 겹치지 않게 한다.
> (시스템이 막지 않음 — **운영 원칙으로 관리**)

**시스템 차단이 없습니다.** DEX 빙고판을 반복 운영할 때 특히 주의해야 합니다.
