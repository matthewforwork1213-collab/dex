#### ★ 26행 — 출금이 안 되는데 "출금 가능해요" 가 나갑니다 🔴

시트의 발송 조건이 이렇게 적혀 있습니다.

> *"When the linked/owned UID reaches **50 or more** due to **commission updates and event reward payments**"*

**커미션 + 이벤트 리워드의 단순 합이 50 이상**이면 발송입니다. 그런데 실제 출금 자격은 **`A + MIN(B, A) ≥ 10`** 입니다(A = 거래소 캐시백, B = 이벤트 리워드).

| 계정 상태 | 단순 합 | 발송? | 실제 출금 가능액 | 결과 |
|---|---|---|---|---|
| A = 0 · B = 992.44 | 992.44 | **발송됨** | `0 + MIN(992, 0)` = **0** | 🔴 **"출금 가능해요" 를 받고 열었는데 `출금 가능한 UID가 없습니다`** |
| A = 5 · B = 232 | 237 | 발송됨 | `5 + MIN(232, 5)` = 10 | ✅ 정상 |

실제 운영 화면 캡처(`_캡처자료/_추가요청/D_사용자화면/D-1a`)에 **거래소 페이백 0.00 / 이벤트 리워드 992.44 / 출금 가능 0.00** 상태가 그대로 찍혀 있습니다. **CEX에서 이미 발생하는 오발송입니다.**

**DEX가 이것을 훨씬 흔하게 만듭니다.** DEX 유입 경로가 `지갑 연동 → 이벤트 확인 → 참여` 순이라, **거래 전에 이벤트 리워드부터 받는 것이 예외가 아니라 정상 경로**이기 때문입니다.

> **조치** — 발송 조건을 `A + MIN(B, A) ≥ 임계값` 으로 바꿔야 합니다. 임계값 50을 유지할지도 함께 결정이 필요합니다(최소 출금액은 10).

| **페이백 챌린지** | 챌린지 전용 알림 행이 **시트에 아예 없습니다** | 🟢 **없음.** 다만 신설한다면 **CEX 전용**으로 |

## 4. 이메일 템플릿 — DEX에서 별도로 만들어야 하는 것

실물 메일 2종(`_캡처자료/_추가요청/E_알림_실물/`)과 **피그마 템플릿 라이브러리**를 대조한 결과입니다.

### 4-0. ✅ 피그마 템플릿 라이브러리 확인 (2026-10-22)

`UI-UX-Design` 파일의 이메일 템플릿 구역을 전수 확인했습니다. 🔄 **작업 파일이 `UIUX Design 2.0` 으로 옮겨졌으므로 템플릿이 그대로 따라왔는지 재확인이 필요합니다.** **앞서 열어 둔 질문 두 개가 닫혔습니다.**

| 템플릿 | 비고 |
|---|---|
| `UID 연동 완료` | 이번 DEX 대응의 기준 |
| **`UID 연동 실패`** | ✅ **존재합니다.** `EMAIL 31행`을 빼지 않아도 됩니다 |
| **`UID 연동 실패(2개 이상 들어올 경우, 자동 거절건)`** | ★ **별도 템플릿입니다.** 본문은 같고 트리거만 다릅니다 |
| `UID 연동 해제` | 소유권 이전용. **DEX 해당 없음** |
| **`페이백 출금 실패`** | 출금 실패 메일에는 **`중요 참고 사항`(피싱 경고) 블록**이 추가로 들어갑니다 |
| `구글 OTP 연동 해제 인증번호` | DEX 무관 |

**각 템플릿이 5개 언어로 그려져 있습니다** (ko·en·tc·ru·vi 확인). 시트는 ko·en만 채워져 있는데 **디자인은 5개 언어가 전부 존재합니다.**

> 🔴 **그래서 작업량이 달라집니다.** 4-5의 `신규 문구 8개`는 **ko·en 기준**입니다. 템플릿 기준으로 맞추면 **4문구 × 5언어 = 20개**가 됩니다. **시트를 따를지 템플릿을 따를지 한 번 정해야** 합니다 — 지금은 둘이 어긋나 있습니다.

**한국어 실물 문구**(DEX 대응의 출발점)

```
제목  UID 연동 완료
본문  UID가 테더맥스에 연동되었습니다. 자세한 내용은 다음과 같습니다.
      거래소   MEXC
      UID     1234567
      추가 지원이 필요한 경우 테더맥스 고객센터를 통해 문의하시기 바랍니다.
```

→ DEX는 `UID` 두 곳이 **`지갑 주소`** 가 되고, 값이 42자가 됩니다.

> 🔄 **`페이백 출금 실패` 템플릿이 한국어에서 `페이백`을 씁니다.** 그런데 **확정 용어는 한국어도 「캐시백」**입니다(영문 `cashback`). 이 템플릿 제목도 **교체 대상**입니다. 기존 CEX 메일까지 같이 바꿀지, DEX 신규분만 캐시백으로 쓸지 정해야 합니다 — **섞이면 같은 서비스에서 두 단어가 동시에 나갑니다.**

> ⚠️ **배너가 디자인과 실물이 다릅니다.** 피그마는 일러스트 배너, 실제 발송 메일은 앰배서더(윤시윤) 배너입니다. 배너가 교체된 뒤 피그마가 갱신되지 않았습니다. **결론은 그대로입니다** — 어느 쪽이든 거래소와 무관한 공용 자산이라 DEX용 신규 제작은 없습니다.

### 4-1. 템플릿은 공용입니다 — 새로 그릴 게 없습니다

로그인 인증코드 메일과 UID 연동완료 메일이 **완전히 같은 껍데기**를 씁니다.

```
┌─────────────────────────────────┐
│  파란 배너 — ∞ TetherMax + 윤시윤   │  ← 공용. DEX도 그대로
├─────────────────────────────────┤
│  H2 제목                         │  ← 바꿔야 함
│  본문 한 줄                       │  ← 바꿔야 함
│  [ 가변 영역 ]                    │  ← 메일마다 다름
│     로그인 메일 → 코드 박스         │
│     연동완료 메일 → 라벨·값 2쌍      │  ← 여기가 핵심
│  고객센터 링크                     │  ← 공용
├─────────────────────────────────┤
│  소셜 4종 · 안내문 · © 2026        │  ← 공용
└─────────────────────────────────┘
```

> **🟢 배너 이미지는 다시 만들 필요가 없습니다.** 앰배서더 배너는 거래소와 무관한 브랜드 자산이고, CEX·DEX를 가리지 않습니다. **디자인 신규 제작 0건**입니다.

### 4-2. 바꿔야 하는 곳은 넷입니다

| # | 위치 | CEX 현재 | DEX |
|---|---|---|---|
| 1 | **메일 제목** | `[TetherMax] UID Binding Success` | `[TetherMax] Wallet Binding Success` |
| 2 | **H2** | `UID linkage completed` | `Wallet linkage completed` |
| 3 | **본문** | `The UID has been linked to TetherMax. Here are the details.` | `The wallet has been linked to TetherMax. Here are the details.` |
| 4 | **상세 블록 라벨** | `Exchange` / `UID` | `Exchange` / **`Wallet address`** |

> **1번이 가장 중요합니다.** 제목은 받은편지함에서 **열기 전에** 보이는 유일한 문구입니다. `UID Binding Success` 가 지갑 연동에 오면 사용자는 자기 메일이 아니라고 생각합니다.

> 🟢 **CEX 메일은 건드리지 않습니다.** 네 군데 전부 `UID` 그대로이고 값도 짧은 숫자 UID입니다. **DEX는 이 템플릿을 고치는 것이 아니라 별도 템플릿**입니다 — 한 메일이 분기하는 것이 아니라 두 메일이 각자 나갑니다.

> **`Exchange` 라벨은 그대로 둡니다.** Lighter·Aster도 제품 전체에서 "거래소"로 부르기로 했으므로 여기만 다르게 할 이유가 없습니다.

### 4-3. 🔴 값의 길이가 블록 전제를 깹니다

```
CEX   UID              DEX   Wallet address
      1234567                0x7a3F9c2b4D8e1A5f6C0b3E2d9A8c7B6a5F4e3D21
      └ 7자                   └ 42자 (6배)
```

기존 블록은 **짧은 값 전제**로 만들어졌습니다. 42자 16진수는 데스크톱 폭(약 580px)에는 들어가지만 **모바일에서 깨집니다.** 지정이 필요한 것은 셋입니다.

| # | 결정할 것 | 권고 |
|---|---|---|
| 1 | 줄바꿈 처리 | `word-break: break-all` + 고정폭 폰트. 주소는 **의미 단위가 없어** 아무 데서나 끊어도 됩니다 |
| 2 | 전체 표기 vs 마스킹 | **전체 표기.** 🔄 확정에 따라 **제품 화면도 주소 전체를 노출**합니다. 마스킹은 **알림 문구(푸시)에만** 해당합니다 |
| 3 | 폰트 크기 | 본문보다 한 단계 작게. 굵게는 유지 |

> 🔄 **확정으로 정리된 부분입니다.** 지갑 주소는 **화면·이메일 모두 전체 노출**이고, **마스킹은 푸시 알림 문구에만** 적용합니다. 푸시는 잠금화면에 뜨고 길이 제한도 있기 때문입니다(5-3 ③).<br>CEX UID 마스킹(*"Last 4 digits of UID masked"*)은 **지금 그대로 둡니다.** 바뀌는 것은 DEX 지갑 주소뿐입니다.

### 4-4. 체인 표기 — 넣을지 결정이 필요합니다

같은 주소가 여러 체인에 동시에 존재합니다. 현재 블록에는 체인 행이 없습니다.

| 안 | 내용 | 평가 |
|---|---|---|
| A | 체인 행 **추가** (`Network` / `Arbitrum`) | 출금 메일과 표기가 맞아떨어집니다. 가스비 체인이 결정되면(`D-2`) 그 값을 씁니다 |
| B | 넣지 않음 | 연동 시점에는 DEX가 체인을 고정하므로 정보 가치가 낮습니다 |

> **권고 — A.** 출금 완료 알림에서 체인을 말해야 하는데 연동 메일에만 없으면 사용자가 두 메일을 대조할 수 없습니다.

### 4-5. 작업량

| 항목 | 건수 | 비고 |
|---|---|---|
| 신규 **이미지** 제작 | **0** | 배너·소셜·푸터 전부 공용 |

## 5. 백엔드에서 새로 연결해야 하는 것

DEX 알림 12종은 **기존 트리거를 재사용할 수 없습니다.** CEX 알림은 전부 테더맥스 내부 이벤트(어드민 승인·원장 변경)에서 나오지만, DEX는 **절반이 외부에서 들어옵니다.**

### 5-1. 트리거 출처가 다릅니다

| 출처 | CEX | DEX |
|---|---|---|
| 테더맥스 내부 | 연동 승인 · 출금 승인 · 원장 변경 | 출금 신청 접수 |
| **파트너 API 응답** | — | **지갑 연동 귀속 확인** |
| **주간 CSV 수신** | — | **Lighter 보류 해제 · 어뷰징 보류 판정** |
| **온체인 트랜잭션 영수증** | — | **출금 도착 · 전송 실패** |

### 5-2. 신규로 깔아야 하는 연결 — 5개

| # | 연결 | 발화하는 알림 | 비고 |
|---|---|---|---|
| 1 | **파트너 레퍼럴 귀속 확인 응답** → 연동 완료/실패 | FCM 100·101 · EMAIL 30·31 | 동기 응답. 거부 사유를 **영구 거부와 재시도 가능**으로 나눠서 넘겨야 문구가 갈립니다 |
| 2 | **Lighter 주간 CSV 파서** → 보류 해제 | FCM 102 · EMAIL 32 | 월요일 1회. 최장 7일 지연 |
| 3 | **Lighter 주간 CSV 파서** → `Withheld` 판정 | FCM 106 | 같은 파일에서 나오지만 **반대 결과**입니다 |
| 4 | **DEX 정산 수신 → 원장 반영** | FCM 103 | 거래소마다 주기가 다릅니다 — Lighter 주 1회(월) · EdgeX 일 1회(00:00 UTC) · Aster 일 1회(09:00 UTC 이후) · ApeX 시간당 |
| 5 | **온체인 전송 영수증 확인** | FCM 104·105 | 성공·실패 모두. **RPC 타임아웃은 둘 중 어느 쪽인지 모르는 제3의 상태**라 별도 처리가 필요합니다 (`N-3`) |
> 🔄 **6번 `Aster 만료 웹훅(R8) 수신` 은 삭제했습니다.** 바인딩 연속 유지 확정(3-2)으로 발화할 알림이 없어졌습니다. **서면 확인 전까지는 되살릴 수 있게 기록만 남깁니다.**

### 5-3. 🔴 식별자가 바뀌면서 깨지는 것

**DEX는 UID를 쓰지 않고 지갑 주소만 씁니다.** 알림 페이로드가 `{UID}` 를 전제로 만들어져 있으면 전부 걸립니다.

| # | 항목 | 내용 |
|---|---|---|
| 1 | **변수명** | `{UID}` → `{지갑주소}`. 같은 알림의 CEX·DEX 행을 **나눠 쓴 이유**입니다(100행 대 22행). 한 행에서 분기시키려면 변수를 중립어로 바꿔야 합니다 |
| 2 | **마스킹 규칙** | CEX는 *"뒤 4자리"*, DEX는 **앞 6자 + 뒤 4자**(`0x7a3F…c51E9`). 앞 `0x` 만 보이면 어느 지갑인지 구분이 안 됩니다 |
| 3 | **길이 제한** | 푸시 본문은 플랫폼별 길이 제한이 있습니다. 42자 전체를 넣으면 **거래소명·금액이 잘립니다** → 푸시는 마스킹 필수 |
| 4 | **대소문자** | EIP-55 체크섬 주소는 대소문자가 의미를 가집니다. **소문자로 정규화해 저장하고 표시할 때 복원**하면 사용자가 자기 주소와 대조할 때 달라 보입니다 |
| 5 | **딥링크** | `L` 컬럼(in-app 이동 경로)이 CEX는 UID 상세로 갑니다. DEX는 **지갑 상세 라우트**가 따로 필요합니다 |

### 5-4. 발송 동의 구분

| 종류 | 동의 필요 | DEX 신규 행 |
|---|---|---|
| `Essential` | 불필요 | FCM 100~106 **전부** |
| `- (Sent regardless of consent)` | 불필요 | EMAIL 28~32 **전부** |

> **DEX 알림은 전부 서비스 안내입니다.** 마케팅 동의와 무관하게 나가야 합니다 — 연동 실패·출금 실패·캐시백 보류는 동의하지 않은 회원에게도 알려야 하는 내용입니다.
