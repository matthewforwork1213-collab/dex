## 2-1. 필수 5

| # | 필드 | 설명 |
|---|---|---|

## 2-2. 선택 (2026-10-21 개정)

| # | 필드 | 용도 | 협상 강도 |
|---|---|---|---|
| 1 | `UID / AID` | CS 교차확인 · 중복·누락 추적 | 보통 |
| 2 | `network (EVM)` | Wallet B 지급 네트워크 결정 | 높음 |
| 3 | `account_tier` | Lighter Standard/Plus/Premium 등급 추적 | **선택** — 2026-10-22 하향. 경고를 띄우지 않기로 확정돼 **필수가 아닙니다** |

> ### ❌ `symbol` · `volume` — 요청에서 **삭제**했습니다 (2026-10-21)
>
> 기존에 *"글로벌리그 · 맥스보드 작동 전제"* 로 분류해 협상 강도 **높음**으로 두었으나,
> **세 서비스 모두 거래량이 아니라 페이백(페이백) 금액을 기준으로 산정**하는 것이 확인되었습니다.
>
> | 서비스 | 산정 기준 | 근거 |
> |---|---|---|
> | 글로벌리그 | `1 USDT 커미션 페이백 = 1 point` | MAX-8 §3 Score Logic |
> | 페이백 랭킹 / 월간 랭킹 | 페이백 금액 순위 | 2026-10-21 확정 |
> | 맥스보드 | 게이지·연속·랭킹 **전부 페이백 기준** | 맥스보드 PRD 서비스기획서 §1.1 |
>
> **거래량은 테더맥스가 기록하는 곳 자체가 없습니다.** 처음부터 불필요했던 항목입니다.

### ~~★ `account_tier` 추가 사유 (Lighter)~~ → **선택으로 하향 (2026-10-22)**

> **경고를 띄우지 않기로 확정**됐습니다. 등급을 몰라도 제품이 성립합니다 — Lighter 상세 페이지가 이미 *"페이백은 Premium과 Plus에 적용, Standard는 쌓이지 않음"* 을 말하고 있고, 거래소 유의사항 필드에 같은 문장을 넣으면 됩니다. **받으면 좋지만 받지 못해도 막히지 않습니다.**

아래는 하향 전 사유입니다.


Lighter는 **Standard 계정의 페이백이 0%** 입니다.
연동 시점에는 등급 판별이 가능하지만(연동 모달이 Standard 주소에 경고 표시),
**연동 이후 등급이 내려가면 감지할 수단이 없습니다.**
유저의 페이백이 조용히 끊기고 CS로만 발견됩니다.

## 2-3. 갱신 규칙

```
D일 거래 발생 → 24h 집계 → D+1 지정 시각 노출 → 테더맥스 수신
```

**00:00 UTC 기준**이며 Aster만 09:00 공개 이후로 권고했습니다.

### ★ 2-3-1. 시간당(hourly) 타임스탬프 보존 — **신규 요건**

> **일 단위 합계만으로는 부족합니다.**
> 각 레코드에 **거래 발생 시각의 UTC 타임스탬프**를 함께 제공해 주십시오.

**사유:** 테더맥스는 전 세계 15개 언어권에 서비스하며, 모든 날짜·시각을 **사용자 디바이스의 로컬 타임**으로 표시합니다. "오늘"의 정의가 타임존마다 다르므로, 서버 UTC 날짜로 묶은 합계는 사용자가 보는 "오늘"과 일치하지 않습니다.

```
요청:  1시간 단위 집계 + 각 레코드에 UTC 타임스탬프
용도:  클라이언트가 사용자 로컬 날짜 기준으로 재집계
근거:  MAX-431 P-2 / MAX-466 Backend 공통 정책
```

예) UTC 2026-10-19 23:30 거래는
- 한국(UTC+9) 사용자에게는 **10월 20일** 거래
- 미국 동부(UTC−5) 사용자에게는 **10월 19일** 거래

일 단위 합계만 받으면 이 구분이 불가능합니다.

## 2-5. 정산 주기·시각 (`update_time`) — **신규 요건**

테더맥스 어드민의 **`Exchange Management > 업데이트(UTC)`** 필드에 등록해야 합니다.
연동 성공 화면에서 사용자에게 **"다음 정산일 / 정산 시각"** 을 로컬 타임으로 안내하는 데 쓰입니다.

| 거래소 | 현재 정산 주기 | 필요한 표기 |
|---|---|---|
| Lighter | 주 1회 (월요일) | **Weekly** + 요일 + 시각 |
| ApeX | 시간당 | Daily (롤업 합의 시) + 시각 |
| EdgeX | 일 1회 00:00 UTC | Daily + 시각 |
| Aster | 일 1회 (00:00 산정 / 09:00 공개) | Daily + **09:00** |

> **요청:** 각 거래소의 정산 주기와 **고정 시각(UTC)** 을 명시해 주십시오.
> 테더맥스는 이 값을 사용자 로컬 시간으로 변환해 노출합니다.

| 4 | 외부 지급 검증 수단 없음 | **검증값 제공** |
| **5** | **만료 후 상태 미정 (신규)** | **만료 후에도 커미션이 적립되는지 / 끊기는지** |

> **3번이 TOP PRIORITY입니다.** 요청서 원문: *"갱신 규칙이 합의되기 전까지, 12개월 뒤 지급이 소멸합니다."*

### ★ 5번 추가 (2026-10-21)

만료 **임박** 화면(`Expires in 30 days` 배지)은 디자인이 있으나, **만료된 이후**의 처리가 정의되어 있지 않습니다.

```
D-30  만료 임박 배지        → 디자인 있음
D-0   만료                  → ★ 화면 없음 (신규 제작 확정)
D+1~  만료 후 거래의 커미션  → ★ 정책 없음 — Aster에 확인 필요
```

**Aster에 물어야 할 것:** 레퍼럴이 만료된 뒤 해당 지갑의 거래에서
- (a) 커미션이 계속 적립되나요?
- (b) 적립이 멈추나요?
- (c) 재연동하면 만료 기간 중의 거래가 소급 적립되나요?

(a)/(c)에 따라 테더맥스 화면의 안내 문구와 재연동 CTA 동작이 달라집니다.
**테더맥스 측 결정:** 자동 연장은 없으며, *"연결이 끊겼으니 다시 연결해 달라"* 는 안내 + 재연동 CTA를 제공합니다.

### ★ 6번 추가 (2026-10-21) — 1번 요청의 중요도가 올라갑니다

맥스보드(빙고)의 **연속 칸**은 *"페이백 배치 반영일 기준 N일 연속 페이백"* 으로 활성화됩니다 (맥스보드 PRD REQ-040).

**주 1회 정산이면 7일 중 1일만 페이백이 찍히므로, 2일 연속조차 성립하지 않습니다.**

| 거래소 | 정산 주기 | 연속 칸 |
|---|---|---|
| **Lighter** | **주 1회 (월)** | **❌ 영구 불가** |
| ApeX | 시간당 | ✅ |
| EdgeX | 일 1회 | ✅ |
| Aster | 일 1회 | ✅ |

**요청:** 실제 **지급**은 주 1회로 유지하더라도, **원장(ledger)만은 일 단위**로 제공해 주실 수 있는지 확인 부탁드립니다. 연속 판정은 *지급일*이 아니라 *원장 반영일* 기준이므로, 일별 원장만 있으면 해결됩니다.

**불가 시 테더맥스 측 대응:** Lighter 빙고판은 **금액 칸만으로 구성**합니다.
(맥스보드 PRD REQ-113이 이미 지원: *"금액 칸만이면 연속 카드를 숨기고 남은 카드를 전체 폭으로 표시"*)

## 4-4. EdgeX — 엔드포인트 + 선택 API

### 요청 엔드포인트 5개 (4곳 중 EdgeX만 구체안 제시)

```
GET  /v1/referral/code/{user_id}
GET  /v1/trade/fees/{user_id}?window=24h
GET  /v1/ledger/entries/{user_id}?type=fee
POST /v1/cashback/credit

```

**원칙: 읽기는 조회만, 쓰기는 페이백만, 출금 권한 없음.**

| **멱등성** | 같은 `trade_id`는 단 1회만 credit — 이중 지급 차단 |
| **취소** | 24시간 내 revoke로 원장 마감 전 정정 |
| **권한 분리** | Wallet A(수취) / Wallet B(지급) 분리 |

### 선택 API 5종 (EdgeX에만 제안)

| Phase | 항목 | 내용 |
|---|---|---|
| 1 | **Webhook** | 30초 폴링 → 실시간 푸시 (30일 내) |
| 2 | 추천 트리 | 다단계 레퍼럴 간접 귀속 |
| 2 | 스테이킹 연동 | 거래 시점 스테이킹 보유량 반영 |
| 3 | ~~거래량 티어링~~ | ~~30일 거래량 기준 비율 상승 (3단계)~~ **→ 거래량 미수집으로 보류** |
| 4 | 글로벌리그 · 맥스보드 | EdgeX 화면에 토너먼트 연동 **(페이백 금액 기준으로 성립)** |
