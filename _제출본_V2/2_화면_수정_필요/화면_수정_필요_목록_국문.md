## 1. 전역 / 공통

### 1-1. 🔴 "Available Cashback" 명칭 재정의

**현재:** DEX 카드가 `Available Cashback`으로 표시하지만 값은 **누적 적립액**입니다.

**문제**
- ~~사용자가 DEX에서 출금해도 이 숫자는 줄지 않습니다~~ → **V2 폐기.** 테더맥스 잔고이므로 출금하면 감소합니다
- DEX마다 의미가 다릅니다

| DEX | 실제 값 |
|---|---|
| Lighter | 주간 CSV 기준 누적 Paid |
| ApeX | 누적 Paid. 별도로 `Available on ApeX`가 실제 잔액 |
| EdgeX | `totalPaidAmount` — 누적 지급액 |
| Aster | 정의 없음 |

**ApeX 카드에는 "Available"이 두 개 있어** 어느 쪽이 실제로 뺄 수 있는 돈인지 알 수 없습니다.

**수정안:** 전 DEX에서 `Paid` 계열 명칭으로 변경. ApeX의 `available_balance`만 `Available on ApeX`로 유지 (이것만 실제 출금 가능액).

**영향 화면:** DEX 선택 카드, Hub 잔액 패널, 출금 드로어, 비회원 My Cashback, Cashback Summary 필터

**현재:** DEX 카드와 비회원 카드에 `Total Claimed`가 있습니다.

**문제:** **4개 DEX 모두 누적 출금액을 제공하지 않습니다.** 구조적으로 제공할 이유도 없습니다 — 출금은 DEX 내부에서 사용자가 직접 하는 일이고 테더맥스는 당사자가 아닙니다. EdgeX만 `Paid to your EdgeX account` / `On the way`로 대체돼 있습니다.

### 1-3. 🟠 상태 칩 마스터 목록 수립

**현재:** 상태 칩이 문서 곳곳에 흩어져 있고 **마스터 목록과 우선순위가 없습니다.**

발견된 상태: `Active` / `Processing` / `Unavailable` / `Standard account, no cashback` / `Expires in {n} days` / `Referral expired` / `Inactive` / `Ownership verification in progress` / `This wallet has been unlinked` / `Ownership verification was unsuccessful` / `Data delayed`

**문제**
- 두 개 이상 동시 해당 시 우선순위가 없음 (예: Aster 만료 임박 + 데이터 지연, Lighter Standard + Processing)

- EdgeX·ApeX 고유 상태(AccountID 미반환, 제한 IP 거래)는 칩 자체가 없음

**참고:** 기존 테더맥스에 **UID 상태 우선순위 1~7**이 있습니다. 전역 규칙은 이것 하나뿐이므로 같은 형식(정수 priority)으로 확장하는 것이 일관성 측면에서 낫습니다.

**수정안:** 상태 정의표를 별도 작성. 열 = 상태명 / 조건 / 우선순위 / 행 표시 / 카드 표시 / 금액 표시 여부 / 액션 상태 / 적용 DEX.

## 3. DEX 랜딩 페이지

### 3-1. 🔴 히어로 리드 문구

**현재:** `No KYC checks. Connect a wallet, and start trading!`

**문제:** 문서 전체가 "지갑 연결을 절대 요구하지 않는다"를 반복 강조하는데, **사용자가 처음 보는 문장이 그것을 뒤집습니다.** 엣지케이스 문서도 미해결 항목 #16으로 올려놨습니다.

**수정안:** DEX에서 하는 일(지갑 연결, 거래)과 테더맥스에서 하는 일(주소 붙여넣기)을 문장으로 분리합니다.

### 3-2. 🟠 DEX 노출 순서가 4가지

| 위치 | 순서 |
|---|---|
| `DX-11` 요약 타일 | Lighter, Aster, EdgeX, ApeX |
| `DX-4` 벤처 카드 | Lighter, ApeX, EdgeX, Aster |
| `LK-2` 연동 모달 | Lighter, ApeX, EdgeX, Aster |

**일부는 수락 기준에 순서를 고정해 놨습니다.** 백오피스 노출 순서를 단일 소스로 삼아야 합니다.

> ✅ **단일 소스는 이미 있습니다 (2026-10-22 확인).** 어드민 `거래소 리스트 > 거래소 순위 수정` 이 **전역 1..N 순서**를 관리합니다
> (현재 1 WOO X Pro · 2 Bitget · 3 Binance · 4 Bybit · 5 OKX · 6 MEXC · **7 test** · 8 Flipster …).
> **신규 API가 필요 없습니다.** DEX 4곳을 이 목록에 넣으면 됩니다.
>
> 🔴 **그래서 문제가 더 선명해집니다.** 단일 소스가 있는데도 제품에 순서가 4가지라면, **소스가 없는 문제가 아니라 화면들이 각자 목록을 그린 문제**입니다. DEX를 넣기 전에 **어느 화면이 실제로 이 값을 읽는지** 확인해야 합니다. 안 그러면 아무도 읽지 않는 목록에 4행을 넣게 됩니다.
>
> 🔴 **그룹 구분 규칙과 충돌합니다.** 출금 외 전 화면이 CEX·DEX를 그룹으로 나눠야 하는데 이 목록은 **그룹을 표현할 수 없는 1..N 단일 수열**입니다.
> → 성립하는 해석: **그룹이 바깥 구조이고, 이 목록은 각 그룹 안의 순서를 공급**합니다. 9위인 DEX는 전체 9번째가 아니라 **DEX 중 첫 번째**로 뜹니다. **문서에 명시하지 않으면 화면마다 다르게 해석해 다시 네 가지 순서로 돌아갑니다.**

## 4. DEX 상세 페이지 — 가장 많은 수정 필요

### 4-1. 🔴 계산기가 돈의 흐름을 반대로 설명

**현재 `VD-5` 흐름도**
```
You → Trading fee → {venue} → Partner settlement → TetherMax → "Cashback returned to you"
```

**현재 설명 카드**
> `TetherMax gives cashback` — TetherMax returns {cashback} to you, so your effective fee becomes {effective fee}.

**현재 `VD-6` 설명 서랍**
> 거래소가 테더맥스에 정산금을 지급하고 테더맥스가 대부분을 돌려준다

**같은 페이지의 FAQ(`VD-8`)는 정반대입니다.**
> Lighter pays your cashback in USDC **into your own Lighter account**, and you withdraw it on Lighter.

랜딩(`DX-3`, `DX-12`)도 "Paid by the DEX, into your account"입니다.

**영향:** 사용자가 테더맥스 잔액에 쌓인다고 믿고 출금하러 갔다가 찾지 못합니다. CS 문의와 신뢰 손상으로 직결됩니다.

**원인:** CEX 템플릿을 그대로 복사했습니다. 카피 수정이 아니라 **흐름도 구조 자체를 다시 설계**해야 합니다.

**수정안**
- 흐름도를 `You → Trading fee → {DEX} → {DEX}가 당신의 {DEX} 계정으로 지급` 구조로 변경
- 테더맥스를 "추적하고 보여주는 주체"로 표현
- `Partner settlement`라는 CEX 용어 제거
- 디스클레이머의 "exchange partner settlements"도 CEX 용어라 수정 필요

### 4-2. 🔴 단계별 가이드 기본 문구

**현재 `VD-7` 2단계 라벨:** `Deposit {currency} into your TetherMax wallet`

**문제:** 테더맥스에는 지갑이 없습니다. 사용자가 이 지시를 따를 방법이 없습니다.

**수정안:** "거래소나 지갑에서 {DEX}로 {currency} 전송"으로 변경. 백오피스에서 단계별로 운영자가 작성하는 구조이므로 기본값만 고치면 됩니다.

### 4-3. 🟠 계산기 거래량 범위

Hub(1K~250K)와 다릅니다. 2-3 참조.

### 4-4. 🟠 계정 등급 선택 UI 없음

`VD-5` 설명 카드가 `{account tier}`를 참조하는데, 사용자가 등급을 고르는 UI가 정의되지 않았습니다.

### 4-5. 🟠 안전 메시지 3종의 배치와 강제 방식

필수 안전 메시지 3개가 있습니다.
1. 12단어 복구 문구를 보관하고 아무에게도 공개하지 말 것

**문제:** 자유 텍스트에서 탐지해 저장을 차단할지(`EDC-17`), 시스템 고정 문구로 넣을지(백오피스 엣지케이스) 두 안이 상충합니다. **다국어 자유 텍스트에서 메시지 존재를 탐지하는 것은 현실성이 낮습니다.**

**수정안:** 고정 문구를 시스템이 삽입하고 운영자는 위치만 지정합니다.

### 4-6. 🟠 EdgeX 헤드라인 요율 검증 방식

**수정안:** DEX별 정산 주기를 그대로 노출합니다. CEX의 cut-off 개념을 억지로 끼우지 않습니다.

### 5-6. 🔴 마일스톤 진행바 — **A-18의 전제가 무너졌습니다. 재확인 필요**

## 6. 출금 모달 — ★ V2로 전면 재작성 (2026-10-22)

> **이 장은 통째로 다시 썼습니다.** V1 기준 내용(`Withdraw on {DEX}` 딥링크 · 새 탭 이동 · "적립액은 출금해도 줄지 않는다")은 **전부 폐기**입니다. V2에서는 **테더맥스가 직접 온체인으로 출금**하므로 DEX가 CEX와 같은 출금 모달을 씁니다.
>
> 실물 화면 확인 완료 — `_캡처자료/_추가요청/D_사용자화면/D-1a · D-1b · D-2 · D-2b`

### 6-0. ✅ 확정 — 탭을 나누지 않습니다

| 항목 | 확정 |
|---|---|
| CEX·DEX 분리 | **하지 않습니다.** 연동된 전 계정이 우선순위 순 **한 목록** |
| 부분 출금 | **구조적으로 불가능.** 한 번의 신청이 자격을 갖춘 전액을 가져갑니다 |
| 정렬 | **출금 가능이 위, 출금 불가가 아래** (실물 확인) |
| 상단 합계 | **출금 가능한 계정만 합산** (실물: `10.00 + 31.68 = 41.68`) |
| 마일스톤 게이지 | **이 모달에 없습니다** (실물 확인) |

### 6-1. ✅ 출금 공식이 실데이터로 검증됐습니다

```
신청 가능한 페이백 = A + MIN(B, A)      A = 거래소 페이백 · B = 이벤트 리워드
출금 자격 = A + MIN(B, A) ≥ 10 USDT     ※ 계정 단위 판정
```

| 실물 사례 | A | B | 신청 가능 | 검증 |
|---|---|---|---|---|
| Bitget UID 1432873105 | 5.00 | 232.00 | **10.00** | `5 + MIN(232,5)` = 10 ✅ |
| OKX UID 617755618866586639 | 31.68 | 0.00 | **31.68** | `31.68 + MIN(0,31.68)` = 31.68 ✅ |
| Bitget UID 2404441483 | 0.00 | **992.44** | **0.00** | `0 + MIN(992,0)` = 0 ✅ |

> 단순 합(`A + B`)이 아닙니다. **이벤트 리워드는 거래소 페이백을 절대 초과할 수 없습니다.**

### 6-2. ✅ 부족분 안내 문구는 계산값입니다

실물 문구 — `거래소 페이백을 {n} USDT 더 받으면 출금할 수 있어요.`

| B (이벤트 리워드) | 필요한 추가 A | 근거 |
|---|---|---|
| B ≥ 5 | **5.00** | `5 + MIN(B,5)` = 10 |
| B = 0 | **10.00** | `10 + MIN(0,10)` = 10 |

**기존 문구를 그대로 씁니다.** 언어팩 신규가 아닙니다. DEX 카드도 같은 문구가 동작해야 합니다.

### 6-3. 🔴 DEX 카드에서 바뀌는 것 — 3가지뿐

| 요소 | CEX | DEX |
|---|---|---|
| 식별자 | `UID 1432873105` (18자리) | **`지갑 0x7a3F…c51E9`** (16진수 42자) |
| 라벨 | `UID` | **중립어 필요** — 연동 모달·이메일 제목과 같은 단어 |
| 배지 | — | **`DEX` 배지** |

> **좌측 연동 패널** — 실물에 `Bitget 14 UIDs`처럼 거래소별로 묶여 접힙니다. **DEX도 지갑을 여러 개 연동할 수 있는지**, 그렇다면 `14 UIDs`에 해당하는 DEX 표현이 무엇인지 결정이 필요합니다.

### 6-4. 🔴 이벤트 리워드만 있고 페이백이 0인 상태 — DEX가 훨씬 흔하게 만듭니다

실물 캡처에 **이벤트 리워드 992.44 USDT를 들고 출금 가능 0.00** 인 계정이 찍혀 있습니다. CEX에서도 이미 발생하지만 **DEX가 이것을 정상 경로로 만듭니다.**

| | CEX | DEX |
|---|---|---|
| 유입 순서 | 가입 → 거래 → 이벤트 | **지갑 연동 → 이벤트 확인 → 참여** |
| 이 상태 | 일시적 | **거래 전까지 지속** |

**연쇄 — 푸시 오발송** `FCM 26행`의 발송 조건이 **`커미션 + 이벤트 리워드 ≥ 50`** 인 단순 합입니다. 위 계정은 992.44로 **"출금 가능해요" 푸시를 받고 열면 "출금 가능한 UID가 없습니다"** 가 뜹니다. 발송 조건을 `A + MIN(B,A)` 로 교정해야 합니다.

### 6-5. 🔴 통합 신청의 다건 표기

| 화면 | 실물 표기 |
|---|---|
| 신청 완료 | `거래소: Bitget +1` · `UID: 1432873105 +1` |
| 공유 카드 | `거래소: Bitget +1` · `UID: ****3105 +1` (**마스킹**) |

**결정 필요** — DEX가 섞이면 식별자 줄에 18자리 UID와 42자 지갑 주소가 혼재합니다. **대표 계정이 무엇인지** 정의해야 합니다(현재는 정렬 결과의 첫 카드로 보입니다).

### 6-6. 🔴 온체인 실패 — CEX에 없던 유형

| 유형 | 비고 |
|---|---|
| 가스 급등 · nonce 충돌 · Wallet B 잔액 부족 · 체인 혼잡 | 재시도 가능 |
| **RPC 타임아웃** | **전송 여부 자체가 불확실.** "다시 시도해 주세요"를 쓰면 이중 전송 요청이 들어옵니다 |

통합 신청에서 **CEX는 성공하고 DEX만 실패**하면 성공·실패 알림이 동시에 도착합니다. `MAX-18 OQ#6`(다중 출금 부분 실패)의 **DEX 전용 정책**이 필요합니다 — 전부 환원해도 **이미 쓴 가스비는 돌아오지 않습니다.**

### 6-7. ✅ 가스비 — 화면에 표시하지 않습니다

실물 신청 완료 화면에 **네트워크 수수료 행이 없고, 그것이 맞습니다.** 테더맥스 전액 부담이며 10을 요청하면 지갑에 정확히 10이 도착합니다.

> 내부: `Wallet B 필요액 = Σ출금액 + Σ가스비`. 건당 2~5 USDT면 10 USDT 출금의 비용이 12~15입니다. 페이백 100%를 유저에게 주므로 **가스비는 전액 손실**이고, 그래서 **건당 가스비가 체인 선택의 결정 요인**입니다.

### 6-8. 🟠 공유 카드의 추천인 코드

공유 카드에 추천인 코드와 **최대 26 USDT 가입 혜택 QR**이 들어갑니다. **DEX 출금 공유는 어디로 보내야 하나요?** 일반 가입 페이지로 보내면 귀속되지 않은 지갑이 되고, **귀속은 나중에 고칠 수 없습니다.**

### 6-9. 🟡 비회원 출금 화면 미디자인

`"Designs exist for members; guest designs to follow"` 상태입니다. 비회원은 **단일 지갑**이라 `+N`이 없고, 통합 목록 구조가 적용되지 않습니다.

### 6-10. ✅ 폐기된 V1 항목

### 9-5. 🔴 친구초대 — DEX 처리 (실물 화면 확인, A-19)

**화면:** `Point > 친구초대 > 초대 리워드`

| 영역 | 조치 | 담당 |
|---|---|---|
| **`거래소 UID 등록 현황` 목록** | **DEX 행을 추가합니다.** 거래소명·UID 등록 개수·누적 초대 리워드 모두 CEX와 동일하게 표시 | 개발 |

#### 왜 비활성이 아니라 미렌더인가

| 방식 | 사용자가 읽는 의미 |
|---|---|
| 비활성(회색) | "지금은 못 고르지만 **조건을 맞추면 고를 수 있다**" |
| **미렌더 (채택)** | "이 목적지는 **존재하지 않는다**" |

DEX 지갑은 조건을 맞춰도 영원히 출금 계좌가 될 수 없습니다. 비활성으로 두면 **"왜 안 되지, 뭘 해야 되지"**가 CS 문의로 옵니다.

#### ⚠️ 디자인이 필요한 새 상태 — 선택지가 0개인 경우

**DEX 지갑만 연동한 사용자**는 출금 모달을 열어도 **선택지가 하나도 없습니다.** 현재 디자인에 이 상태가 없습니다.

빈 모달이 뜨면 사용자는 버그로 읽습니다. **"출금하려면 거래소 UID 연동이 필요합니다" + 연동 링크**가 필요합니다. (B-2-9)

DEX는 KYC가 없어 진입이 쉬우므로 **실제로 발생하는 상태**입니다.

#### 🟠 함께 확인할 것 — `0 USDT` vs `-`

현재 CEX 행도 `0 USDT`로 표시합니다. DEX 행에 금액을 표시하기로 했으므로 충돌은 없지만, **"아직 0"과 "해당 없음"을 구분할 표기가 전체적으로 없습니다.**

## 10. 혜택 / 퀴즈

### 10-1. 🟠 혜택 페이지 상단 금액이 상시 0

혜택 페이지 상단이 회원에게 **이벤트 리워드 총합**을 보여줍니다. DEX 전용 사용자는 **상시 0 USDT**가 노출되어 비회원 화면과 같아집니다.

**참고:** 비회원에게는 금액 영역 자체를 제거한 선례가 있습니다. 같은 패턴을 적용할 수 있습니다.

### 10-2. 🟠 퀴즈 보상 표시

DEX 교육 모듈 2개는 보상이 없습니다(`LE-9`, `LE-10`). 그런데 `LE-1`이 기존 카드와 "구조가 동일"해야 한다고 합니다. **기존 3개 모듈에 보상 표시가 있다면 사용자가 보상을 기대합니다.**

`LE-11`이 결번인 것도 보상 관련 행을 삭제한 흔적으로 보입니다.

**수정안:** DEX 카드에서 보상 영역을 숨기고 결과 화면에도 보상 문구를 넣지 않습니다.

### 10-3. 🟠 퀴즈 거래소 지정 사전 차단

기존 퀴즈는 **참여와 쿠폰 수령이 거래소 계정 없이도 가능**하지만, 쿠폰 **사용**은 지정 거래소 UID가 필수이고 결과가 이벤트 리워드입니다. **DEX를 지정 거래소로 설정하면 쿠폰을 쓸 대상이 없습니다.**

게다가 `Exchange` 필드는 **등록 후 수정 불가**라 되돌릴 수 없습니다.

**수정안:** 백오피스에서 퀴즈 거래소 선택 시 DEX를 사전 차단합니다.

### 10-4. 🟡 퀴즈 콘텐츠 부재

본문·문항·보기·해설이 PRD에 없습니다. **정답 위치만 있습니다** ("모듈 4는 Q1 2번, Q2 3번"). 콘텐츠 제작을 별도 작업으로 분리해야 합니다.

### 10-5. 🟡 퀴즈 완료 기준 미정

제출만 하면 완료인지 2/2여야 하는지, 재응시 가능 여부, 완료 후 버튼 상태가 정의되지 않았습니다.

### 10-6. 🟡 3 USDT 쿠폰 배지

S3 홈 체크리스트의 "Link your wallet with us" 옆에 3 USDT 배지가 붙어 있습니다. **DEX 지갑만 연동한 사용자는 이 쿠폰을 받을 수 없습니다** (기존 쿠폰 규칙이 "연동 완료 UID 1개 이상 필수"). `RT-4`의 "DEX 패널에서 보상을 약속하지 말 것"과도 취지가 충돌합니다.

**확정 (A-14): 배지를 유지하고 안내 문구를 답니다.** 쿠폰은 **받을 수 있지만 DEX에서는 쓸 수 없습니다.** 쿠폰함에 **"CEX UID 연동 시 사용 가능"**을 명시합니다. 리뷰 보상 쿠폰(A-17)도 동일합니다.

### 11-1. 🔴 Spending Estimate 소수점 제한 버그

**수정안:** 소수 4자리로 변경.

### 11-2. 🟠 Aster 연동 섹션 없음

Lighter(`EXT-18`), ApeX(`EXT-19`), EdgeX(`EXT-20`)는 전용 섹션이 있는데 **Aster만 없습니다.** 365일 바인딩, usdtValue, 웹훅 설정을 관리할 화면이 없습니다.

### 🔴 11-3. 지갑 연동 한도 — 설정·조회 화면이 없습니다

**무엇인가** — 한 회원이 **DEX 지갑 주소를 몇 개까지 등록할 수 있는가**입니다.

**지갑 주소는 만드는 데 비용이 0입니다.** 몇 초면 새로 만들어 붙여넣을 수 있고 **연동에 서명도 KYC도 없습니다.** CEX UID는 거래소 계정이 있어야 해서 그렇게 못 늘립니다. → **한도는 DEX 쪽에만 있고, CEX UID는 세지 않습니다.**

```
한도 = 활성 DEX 수 × 3        →  DEX 4곳이면  12개
```

프론트에는 이 규칙이 명시돼 있는데 **어드민에 이걸 다루는 화면이 아예 없습니다.**

| 없는 것 | 왜 필요한가 |
|---|---|
| **설정 위치** | 지금은 코드 안 상수입니다. **5번째 DEX를 게시하면 모든 회원 한도가 12 → 15로 말없이 올라갑니다** |
| **회원별 사용량 조회** | 고객센터가 *"왜 지갑이 연동 안 되냐"* 는 문의를 받는데, 답이 **한도에 걸렸다**일 수 있습니다. **조회할 방법이 없습니다** |
| **예외 처리** | 특정 회원의 한도를 올려줄 수단이 없습니다 |

**🟢 집계 규칙은 대부분 이미 확정돼 있습니다** (`05_연동_출금_플로우` 2-9)

| | |
|---|---|
| 지갑 제거 시 | **칸 반환.** 누적이 아니라 현재 개수 |
| DEX 비활성화로 한도가 내려가면 | **기존 연동 유지 · 신규만 차단** |
| 같은 주소를 두 DEX에 | **각각 1칸** (`EC-LNK-26`) |
| CEX UID | **안 셈.** DEX 지갑만 |
| 검사 시점 | 서버, **연동과 같은 트랜잭션 안** |

**열려 있는 것은 둘입니다**

| # | |
|---|---|
| 1 | **`Processing` 상태를 포함할지** — Lighter 최장 7일 보류. 포함하면 **확정도 안 된 지갑 때문에 회원이 막힙니다** |
| 2 | **운영자 예외 부여** — 규칙에 회원별 예외 개념이 없습니다 |

> **프로토타입 확인 위치** — 백오피스 `신규 구축 > 지갑 연동 한도`

### 🔴 11-3-1. 초안·미리보기가 없습니다 — **별도 화면이 아니라 에디터의 빠진 상태**

### 배지 규칙 — **확정** (2026-10-22)

**`CEX` 배지는 붙이지 않습니다.** 다른 것이 이미 구분을 맡는 곳에서는 배지를 전부 뺍니다.

| 상황 | 배지 | 구분을 맡는 것 |
|---|---|---|
| **식별자가 보임** — 출금 목록 · 내역 · 선택 모달 | **없음** | `UID 1432873105` 대 `지갑 0x7a3F…c51E9` — 혼동할 수 없습니다 |
| **그룹 헤더가 있음** — 필터 드롭다운 · 연동 모달 | **없음** | 헤더가 이미 `CEX` / `DEX`라고 말합니다 |

#### ✅ 확정 — 탭으로 나누지 않습니다 (2026-10-22)

#### ✅ V1에서 "통합 시 깨진다"고 적었던 4가지 — 전부 해소됐습니다

아래 4건은 전부 **"DEX는 테더맥스를 거치지 않는다"** 는 V1 전제 위에 있었습니다. V2에서 전제가 뒤집히면서 **그대로 성립합니다.**

| # | V1 우려 | **V2 결과** |
|---|---|---|
| 1 | `출금 가능 페이백` 합계 — DEX 금액은 "이미 받은 금액"이라 합산하면 안 됨 | **합산이 맞습니다.** DEX 금액도 테더맥스 잔고입니다. 실물 확인 — `10.00 + 31.68 = 41.68`, 출금 가능한 계정만 합산 |

| 4 | `출금 가능한 UID가 없습니다` — DEX만 연동한 회원이 영구히 봄 | **일시적입니다.** 거래해서 페이백이 쌓이면 해소됩니다. 다만 **DEX는 이 상태가 더 흔합니다** — 6-4 참조 |

#### ✅ 해소 — `출금하기` 버튼은 DEX에서도 그대로 동작합니다 (V2, 2026-10-22)

~~V1에서는 DEX에 출금 요청이 없어 카드마다 `{DEX}로 이동`하는 개별 동작뿐이라 일괄 버튼으로 묶을 수 없었습니다.~~ **V2에서 전제가 뒤집혔습니다.**

V1에서는 통합하면 상단 `출금 가능 페이백` 숫자의 정의가 깨진다고 봤습니다. **"테더맥스에서 꺼내는 돈"과 "DEX에서 이미 받은 돈"이 서로 다른 것**이었기 때문입니다.

V2에서는 **둘이 같은 것**입니다. 분리할 이유가 사라졌고, 오히려 분리하면 한 번에 출금한다는 기존 정책이 깨집니다.

### 14-5. 🔴 페이백 요약(페이백 내역) — DEX 추가 필요, 유형 필터 2개가 성립하지 않음

**화면:** `페이백 요약` — 좌측 필터 3종 + 우측 월 캘린더 + 선택일 내역 목록

| 필터 3 | `모든 페이백 유형` → `페이백` / `이벤트 리워드` / `출금 금액` (체크박스 다중) |
| 버튼 | `재설정` / `검색` |
| 캘린더 | 월 단위, 날짜 아래 일별 합계 (`+5.00`) |
| 목록 | `쿠폰 사용` + 거래소명 + UID + `+5 USDT` |

#### 🔴 조치 1 — 거래소 필터와 내역 목록에 DEX를 넣습니다

현재 DEX 건이 **조회 자체가 안 됩니다.** 드롭다운 표기 `WOO X Pro (1 UID)`는 DEX에서 성립하지 않습니다 — UID가 없으므로 `(지갑 1개)` 등 중립 표기가 필요합니다. 14-3의 `UID` 컬럼 건과 같은 뿌리입니다.

#### 🔴 조치 2 — 유형 필터 4개 중 **2개**가 DEX에서 성립하지 않습니다

사용자 지시는 `이벤트 리워드` 1개였으나, **`출금 금액`도 같은 이유로 성립하지 않습니다.**

| 유형 | V1 | **V2** | 비고 |
|---|---|---|---|
| `페이백` | ✅ 있음 (의미 다름) | **✅ 있음, 의미도 동일** | 테더맥스 잔고 |
| `이벤트 리워드` | ❌ A-09 전면 배제 | **✅ 있음** | A-1 확정 — DEX도 이벤트 리워드 대상 |
| `출금 금액` | ❌ 테더맥스 출금 없음 | **✅ 있음** | 테더맥스가 온체인으로 직접 출금 |

→ **세 유형 모두 DEX에서 유효합니다.** 필터를 숨기거나 비활성화할 이유가 없어졌습니다. `B-7-20`은 해소됐습니다.

**다중 선택이므로 규칙을 명시해야 합니다.** CEX와 DEX를 함께 선택한 경우에는 `이벤트 리워드`·`출금 금액`이 유효합니다(CEX 때문). **선택된 거래소가 전부 DEX일 때만** 숨기거나 비활성화합니다.

#### 🟠 조치 3 — 캘린더 일별 합계의 의미가 섞입니다

캘린더 날짜 아래 `+5.00`은 CEX에서 **"테더맥스 잔액이 그날 늘어난 금액"**입니다. DEX 금액을 더하면 **"DEX가 내 계정에 넣어준 금액"**이 섞여 들어갑니다. 1-1(`Available Cashback` 명칭)·5-1(DEX Cashback Balance 정의)과 같은 뿌리입니다.

#### ⚠️ 확인 필요 1 — 날짜 경계가 UTC와 KST로 갈립니다

DEX 레코드는 **UTC 일 기준**입니다 (EdgeX 00:00 UTC, Aster 09:00 UTC 공개). 캘린더가 KST라면 **하루가 밀려서 찍힙니다.** 1-8(시간대 표기 통일)·[03 B-6-4](../../DEX/03_정책_결정_기록.md)와 함께 결정해야 합니다.

#### ⚠️ 확인 필요 2 — Lighter는 캘린더에 월요일만 찍힙니다

주 1회 정산이라 **한 달에 4~5칸만 금액이 있고 나머지는 공백**입니다. 사용자가 "적립이 안 됐나" 오해할 수 있어, 주간 정산 DEX임을 알리는 표시가 필요합니다.

### 🔴 16-1. 출금 공식이 틀렸습니다 — `A + MIN(B, A)`

**대상:** 출금 모달(DW1) · 비회원 지갑 상세 · 페이백 요약

제가 이전에 Figma에서 확인해 기록한 공식은 **오류**였습니다.

```
(구) Available Cashback = Exchange Cashback + Event Reward     ← 오류
(신) Available Cashback = A + MIN(B, A)                        ← 정정
         A = 페이백 · B = 이벤트 리워드
```

화면이 단순 합산처럼 보였던 것은 **예시 데이터에서 B ≤ A 였기 때문**입니다.

**조치**
1. 출금 모달 카드에 `Event Reward` 행 추가 (현재 `Exchange Cashback` 행만 있음)
2. `Available Cashback` 값이 **단순 합이 아님**을 반영
3. `Inactive` 뱃지 판정 기준을 `A + MIN(B,A) < 10 USDT` 로 명시

**사용자 안내 문구 신규 필요**

> **DEX 페이백이 0이면 이벤트 리워드도 출금할 수 없습니다.**
> (MAX-18 표 #4: `A=0, B=50 → 출금 0`)
> DEX에 이벤트 리워드를 지급하기로 했지만(결정 A-1) 이 제약은 그대로 걸립니다.
> **DEX에서 거래를 해야 이벤트 리워드도 뺄 수 있다**는 점을 명시해야 합니다.

### 🟠 16-15. 축약 지갑 주소가 겹치는 경우 (2026-10-22 신규)

**대상:** 쿠폰 사용 · 초대 리워드 출금 · 리그 참여 — **계정 선택 모달 전부**

> **확정 — 사용자 화면은 주소를 축약합니다.** 전체 42자는 노출하지 않습니다.

**업계 표준이고, 우리에겐 전체를 보여줄 자리가 없습니다.** 전체 표시가 필요한 유일한 상황은 「보낼 곳 확인」인데 **출금 목적지가 연동 지갑으로 고정**이라 사용자가 주소를 입력하지 않습니다. 전체 길이는 **어드민과 이메일 기록**에만 남습니다.

**🟠 다만 한 경우에 깨집니다**

```
0x7a3F…c51E9
  └┬─┘  └┬─┘
  앞 6    뒤 4   →  0x 가 고정이므로 실제 구분 문자는 8자
```

**이 충돌은 가정이 아닙니다.** Lighter는 **축약 주소가 겹치면 지갑을 `Processing`으로 보류**합니다 — 우리 시스템 안에서 실제로 일어나는 일입니다.

→ 회원이 **같은 거래소에 지갑 둘**을 연동했고 축약값이 같으면, 선택 모달에 **똑같은 행이 둘** 뜨고 **어느 것이 어느 것인지 구분할 수 없습니다.**

| # | 조치 | 담당 |
|---|---|---|
| 1 | 같은 거래소 안에서 **축약값이 중복되면 더 긴 형태로 확장** | 개발 |
| 2 | 또는 **사용자 별칭**(`내 메인 지갑`) 입력 지원 | 제품 |
| 3 | 그 외에는 **축약 유지** — 전체 표시로 바꾸지 않습니다 | — |

> **권고 — 1번.** 별칭은 입력 단계가 하나 늘고, 대부분의 회원은 거래소당 지갑이 하나라 쓸 일이 없습니다.
>
> **프로토타입 확인 위치** — 사용자 화면 `쿠폰함 > 쿠폰 사용`
