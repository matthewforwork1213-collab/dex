# 1. 구조 개요

## 1-1. 핵심 — 테더맥스가 지급합니다

```
          4개 DEX (Lighter · ApeX · EdgeX · Aster)
                     │
                     │  커미션 100%
                     ▼
        ┌────────────────────────┐
        │  Wallet A              │  커미션 정산 지갑
        │  Commission Settlement │  4곳의 커미션 전액 수취
        └───────────┬────────────┘
                    │  ★ 수동 리밸런싱 · 1일 1회
                    │     전일 예상 지급액 + 가스비만 이동
                    ▼
        ┌────────────────────────┐
        │  Wallet B              │  페이백 전용 지갑
        │  Cashback-Only         │  고객 대면 · 가스비 선충전
        └───────────┬────────────┘
                    │  자동 지급 (가스비 동반)
                    ▼
              고객 EVM 지갑
```

**Wallet A와 B는 절대 같은 풀이 아닙니다.** A는 수취 전용, B는 고객 대면 전용입니다.

## 1-2. CEX·DEX·V1 3자 비교

| 항목 | CEX (현행 17곳) | **DEX V1 (폐기)** | **DEX V2 (신규)** |
|---|---|---|---|
| 식별자 | 거래소 UID | 지갑 + DEX 계정 ID | **지갑 주소** (DEX는 UID 없음) |
| 페이백 지급 주체 | 테더맥스 | ~~DEX~~ | **테더맥스** |
| 테더맥스 역할 | 자금 보유 + 지급 | ~~조회·표시만~~ | **수취 · 계산 · 지급 전체** |
| 출금 장소 | 테더맥스 | ~~DEX 사이트~~ | **테더맥스 앱·웹** |
| 최소 출금액 | 10 USDT | ~~없음~~ | **10 USDT** |
| 적립액 성격 | 통장 잔고 | ~~영수증~~ | **통장 잔고** |
| 이벤트 리워드 | 있음 | ~~없음~~ | **있음 (재판정 대상)** |
| 지갑 연결·서명 | 해당 없음 | 요구 안 함 | **요구 안 함 (유지)** |
| 가스비 | 없음 (내부이체) | 없음 | **테더맥스 부담 (신규)** |

**V2는 CEX와 거의 같습니다.** 다른 것은 식별자(지갑 주소)와 가스비 부담뿐입니다.

## 1-3. 전제조건 2개

| # | 조건 | 설정 위치 |
|---|---|---|
| 1 | 트레이더 캐시백 비율 **0%** — 자동 지급 차단 | DEX 백오피스 |
| 2 | 커미션 **100%를 Wallet A로** 전액 라우팅 | DEX 정산 설정 |

**둘 다 합의되기 전까지 연동 자체가 불가능합니다.** 하나만 빠져도 Wallet B 자동 지급을 포함한 전체 파이프라인이 가동되지 않습니다.

## 1-4. 핵심 원칙 4가지

1. **테더맥스가 페이백을 지급합니다.** 수취·계산·지급·출금을 전부 운영합니다.
2. **지갑 연결이나 서명을 절대 요구하지 않습니다.** 사용자는 주소를 붙여넣기만 합니다.
3. **모든 금액은 USDT로 표시합니다.** USDC는 1:1, Aster는 Aster가 제공한 USDT 환산값을 사용합니다.
4. **가스비는 테더맥스가 부담합니다.** Wallet B에 선충전합니다.

## 1-5. DEX 4곳 — 신규 기준 비교

| 항목 | Lighter | ApeX | EdgeX | Aster |
|---|---|---|---|---|
| 정산 주기 | 주 1회 (월~일) | 시간당 | 일 1회 (00:00 UTC) | 일 1회 (00:00 산정 / 09:00 공개) |
| 통화 | USDC (1:1) | USDT | USDC (1:1) | **수수료 자산 가변** |
| 지급 검증 | **온체인 해시** | 내부 ID | 내부 ID | **없음 — 요청 중** |
| 특이 리스크 | Standard 계정 0% · 어뷰징 보류 | **기존 미수령 잔액** | — | **365일 레퍼럴 만료** |

> **「기존 지급 위치」와 「사용자 행동」 축은 폐기됐습니다.** 자동 페이백이 차단되므로 무의미합니다. 대신 **「정산 주기」와 「통화」가 API 원장 설계 조건**이 됩니다.

# 2. 연동 플로우

## 2-1. 진입

CEX와 DEX가 **같은 Link Account 플로우**를 씁니다.

| 플랫폼 | 진입점 |
|---|---|
| 웹 | 로그인 홈의 `+ Link Account` |
| 앱·모바일웹 | 홈 카드 `Link once and paybacks keep coming` |
| 공통 | DEX 상세 페이지, Cashback Hub |

## 2-2. 거래소 선택

**⬜ 미결정 — CEX·DEX를 구분할지 통합할지** (방침 공표 결정 1번)

| 안 | 내용 |
|---|---|
| (a) 통합 목록 | 한 목록에 섞고 DEX에 배지만 |
| (b) 필터 칩 | `전체` / `CEX` / `DEX` |
| (c) 탭 분리 | 상단 탭으로 완전 분리 |

**결정과 무관하게 확정된 것**
- 모달 제목 `거래소 **UID** 연동하기`에서 **UID를 뺍니다.** DEX는 UID 개념이 없습니다
- DEX 선택 시 부제 `지갑 연결이나 서명이 필요 없습니다` 노출
- `여기서 가입하세요` 링크는 **테더맥스 레퍼럴 가입 경로**여야 합니다

## 2-3. 지갑 주소 입력

- 라벨 `Paste your wallet address` + Paste 버튼
- 헬퍼 `Starts with 0x followed by 40 characters.`
- 입력 후 라벨이 `Wallet address`로 변경
- 주 액션은 형식 검증 통과 전까지 비활성
- **DEX별 안내 블록** `How to find your wallet address` + 스크린샷 최대 5장 (DEX별 × 언어별)

## 2-4. 주소 검증 — 9단계

클라이언트와 서버가 **같은 순서로** 검증하며 **서버가 최종 권한**을 가집니다.

| 순서 | 검증 | 실패 문구 |
|---|---|---|
| 1 | 앞뒤 공백·탭·줄바꿈 제거. 내부 공백은 무효 | — |
| 2 | 빈 값·공백만 거부 | `Enter your wallet address.` |
| 3 | DEX가 선언한 형식과 일치 (현재 4곳 모두 EVM) | `This doesn't look like a {DEX} wallet address.` |
| 4 | 소문자 `0x` 접두사 | `Enter a valid wallet address starting with 0x followed by 40 characters.` |
| 5 | `0x` 뒤 정확히 40자 16진수 | 동일 |
| 6 | `0-9`, `a-f`, `A-F`만 허용 | 동일 |
| 7 | 대소문자 혼용은 **EIP-55 체크섬 유효할 때만** | `This address has an invalid checksum. Copy it again directly from {DEX}.` |
| 8 | ENS·ICAP/IBAN 거부 | `Paste the 0x wallet address, not a name or other format.` |
| 9 | 영주소 거부 | `This address can't be linked.` |

**저장은 소문자, 표시는 EIP-55 체크섬 형식** (`0x7a3F…51e9`). 무효한 체크섬을 조용히 소문자로 바꾸지 않습니다.

## 2-5. 레퍼럴 귀속 확인

원장 API의 `referral_code` 필드로 테더맥스 귀속을 검증합니다. **지갑 주소가 유일한 식별자**입니다.

## 2-6. 실패·보류 상태

| 상태 | 발생 조건 | 액션 |
|---|---|---|
| `Verification Limit Reached` | 짧은 시간에 반복 실패 | Close, Contact Support |
| `Unable to Link Wallet` | 일반 오류 · DEX 거부 | Contact Support |
| `Unable to Link Wallet` (레퍼럴 아님) | DEX가 테더맥스 레퍼럴로 보고하지 않음 | Close, Contact Support |
| `Wallet Already in Use` | 다른 테더맥스 계정에 연동된 주소 | **Contact Support (주 액션)** |
| `You've Already Added This Wallet` | 본인 계정에 이미 연동됨 | Close |
| `You've reached your wallet limit` | 지갑 한도 도달 | Manage Wallets, Cancel |
| `Processing Your Wallet` | 귀속 확인 지연 | Back to Home |

> **`Unable to Link Wallet Yet`("출금 후 연동하세요")는 V2에서 DEX에도 적용될 수 있습니다.** V1에서는 테더맥스 출금이 없어 CEX 전용이었으나, **V2는 테더맥스 잔액이 생기므로 재검토가 필요합니다.**

## 2-7. 지갑 연동 한도

**현재 설계: `3 × 활성 DEX 수`, 전 DEX 합산.** 4곳이면 12개.

> **검토 필요:** DEX 활성화·비활성화가 전 회원 한도에 영향을 줍니다. 2곳으로 줄여 출시하면 6개가 됩니다. 고정 총량 방식도 검토 대상입니다.

# 3. 적립 플로우

## 3-1. 공통 원칙

- 테더맥스가 **서버 측에서** 원장 API를 수집합니다. 페이지가 직접 호출하지 않습니다
- 파트너 키는 **읽기 전용**이며 클라이언트에 노출되지 않습니다
- **4곳 모두 같은 스키마**로 전일 기준 일 단위 원장을 제공합니다
- 레코드는 불변이며, 정정은 24시간 내 취소 API로 처리합니다
- **멱등성** — 같은 `trade_id`는 단 1회만 반영. 이중 지급을 원천 차단합니다

## 3-2. 원장 API 스키마

### 필수 5

| # | 필드 | 설명 |
|---|---|---|
| 1 | `wallet address` | **유일한 식별자** |
| 2 | `trade_type` | `spot` / `perp` |
| 3 | `fee_paid` | 트레이더가 지불한 수수료 |
| 4 | `commission` | 테더맥스에 지급된 커미션 |
| 5 | `referral_code` | 테더맥스 귀속 검증 |

### 선택 3

| # | 필드 | 용도 |
|---|---|---|
| 1 | `UID / AID` | CS 교차확인 · 중복·누락 추적 |
| 2 | **`symbol` · `volume`** | **글로벌리그 · 맥스보드 작동에 필수** |
| 3 | `network (EVM)` | Wallet B 지급 네트워크 결정 |

### 응답 예시

```json
{
  "date": "2026-10-19",
  "wallet": "0x##...##",
  "trade_type": "perp",
  "fee_paid": ##.##,
  "commission": ##.##,
  "referral_code": "TM####"
}
```

## 3-3. 갱신 타임라인

```
 D일        거래 발생 · 수수료 부과
   ▼
 24h 집계   DEX가 하루치 롤업
   ▼
 D+1       지정 시각에 원장 노출 (00:00 UTC 기준 / Aster는 09:00 이후)
   ▼
 테더맥스   수신 → 전 화면 갱신 → A→B 리밸런싱
```

폴링은 30초 주기이며, EdgeX는 Phase 1에서 **webhook 대체**를 제안했습니다.

## 3-4. DEX별 적립 특이사항

### Lighter — 주 1회 정산

| 항목 | 내용 |
|---|---|
| 정산 | 매주 월요일, 전주 월~일 집계 |
| 통화 | USDC → USDT 1:1 |
| **요청 사항** | **주 단위 정산이어도 일별 원장 제공** · 보류 건의 원장 표기 규칙 |
| 특이 | **Standard 계정은 수수료 0%라 커미션 없음** → 연동 시 경고 필요 |
| 검증 | **온체인 해시** (4곳 중 유일) |

### ApeX — 시간당 정산

| 항목 | 내용 |
|---|---|
| 정산 | 시간당 배치 |
| 통화 | USDT (환산 불필요) |
| **요청 사항** | **시간당 배치를 일 단위(D+1)로 롤업** |
| **미결** | **기존 미수령 잔액 처리 — 별도 결정** |
| 해소 | claim 의존이 신규 구조에서 사라짐 |

### EdgeX — 일 1회 정산

| 항목 | 내용 |
|---|---|
| 정산 | 매일 00:00 UTC |
| 통화 | USDC → USDT 1:1 |
| **요청 사항** | 회원당 일 1건 원장 + 지급 식별 ID |
| 해소 | **출금 가능 잔액 미제공 문제가 사라짐** — 테더맥스가 출금을 집행하므로 |

### Aster — 일 1회 정산

| 항목 | 내용 |
|---|---|
| 정산 | 00:00 산정 → 09:00 공개 |
| 통화 | **수수료 자산 가변** (USDT·ETH·BTC 등) |
| **요청 사항** | **USDT 환산값을 Aster가 계산해 제공** · 지급 자산·네트워크 명시 |
| **최우선 리스크** | **레퍼럴 365일 만료 · 갱신 방식 미정** |

> **Aster 갱신 방식이 확정되지 않으면 12개월 후 Aster 연동자 전원의 적립이 중단됩니다.** 만료 30일 전 알림은 설계에 반영돼 있습니다.

# 4. 출금 플로우

## 4-1. 핵심 — 테더맥스에서 출금합니다

**V1과 정반대입니다.** 페이백은 테더맥스 잔액에 쌓이고, 고객은 테더맥스 앱·웹에서 출금을 신청합니다.

## 4-2. 회원 출금 플로우

| # | 단계 | 주체 |
|---|---|---|
| 1 | 홈 또는 출금 화면에서 잔액 확인 | 고객 |
| 2 | **10 USDT 이상**이면 출금 신청 (클릭 1회) | 고객 |
| 3 | Wallet B가 지급액 + 가스비 보유 확인 | 자동 |
| 4 | 온체인 EVM 전송 + tx 로그 기록 | 자동 |
| 5 | 고객 EVM 지갑 도착 · 해시 기록 | 자동 |
| 6 | 6개 화면에 변동값 반영 | 자동 |

```
고객: 잔액 확인 → 10 USDT 이상 → 출금 신청 (수동 1회)
                                      │
            Wallet B: 지급액 + 가스비 ─┤
                                      ▼
                            온체인 EVM 전송 + tx 로그
                                      ▼
                            고객 지갑 도착 · 해시 기록
                                      ▼
                        6개 화면에 변동값 즉시 반영
```

## 4-3. ★ 출금 금액 공식 — 매칭 출금 (2026-10-21 확정)

**DEX도 CEX와 동일한 매칭 공식을 적용합니다.**

```
실제 출금액 = A + MIN(B, A)

   A = 페이백 (거래 수수료 기반)
   B = 이벤트 리워드

Eligible 조건 = A + MIN(B, A) ≥ 10 USDT      ※ 지갑(UID) 단위로 판정
소수점       = 2자리, 3자리에서 버림 (floor)
```

**이벤트 리워드는 페이백 금액을 절대 초과할 수 없습니다.**
도입 사유: 거래 없이 이벤트 리워드만 빼가는 어뷰징 차단 (MAX-18 Problem Statement).

| # | 페이백 A | 이벤트 B | 실제 출금 | Eligible |
|---:|---:|---:|---|:--:|
| 1 | 5 | 5 | 5 + 5 = **10** | ✅ |
| 2 | 2 | 8 | 2 + 2 = 4 | ❌ |
| 3 | 10 | 0 | 10 + 0 = 10 | ✅ |
| 4 | **0** | 50 | 0 + 0 = **0** | ❌ |
| 6 | 7 | 100 | 7 + 7 = **14** | ✅ |
| 10 | 9.5 | 0.4 | 9.9 | ❌ |

### ★ DEX에 중요한 귀결 — #4 케이스

> **DEX 페이백(A)이 0이면 이벤트 리워드도 출금할 수 없습니다.**

V2에서 DEX에 이벤트 리워드를 지급하기로 했지만(결정 A-1), 이 제약은 그대로 걸립니다.
**DEX에서 거래를 해야 이벤트 리워드도 뺄 수 있습니다.** 사용자 안내 문구에 반영해야 합니다.

### 기존 기록 정정

```
(구) Available Cashback = Exchange Cashback + Event Reward     ← 오류
(신) Available Cashback = A + MIN(B, A)                        ← 정정
```
화면이 단순 합산처럼 보였던 것은 예시 데이터에서 B ≤ A 였기 때문입니다.

## 4-4. 표시 규칙

| 항목 | 규칙 |
|---|---|
| 최소 출금액 | **10 USDT** — `A + MIN(B,A)` 기준. 미만이면 `Inactive` 뱃지 + 카드 dimmed |
| 판정 단위 | **지갑 1개 단위.** 지갑마다 Eligible 여부가 다름 |
| 사용자 행동 | **클릭 1회.** Claim 버튼도 후속 단계도 없음 |
| 가스비 | **테더맥스 전액 부담.** 고객에게 청구하지 않으며 **화면에 표시하지 않음** |
| 수령액 | **고객이 10을 요청하면 고객 지갑에 정확히 10이 도착** |
| 적립액 | **출금하면 줄어듭니다** (V1과 반대) |

> **V1의 "적립액은 출금해도 줄지 않습니다" 문구는 폐기합니다.** V2는 테더맥스 잔고이므로 출금하면 감소합니다.

### 상태 표시

| 조건 | 표시 |
|---|---|
| `A + MIN(B,A)` ≥ 10 | `Available` 뱃지 (초록) |
| `A + MIN(B,A)` < 10 | `Inactive` 뱃지 (회색) + 카드 dimmed + 상호작용 차단 |
| 전체 Inactive | `Not eligible to withdraw` 뱃지 + Confirm 버튼 비활성 |

**단, 균형점인 버퍼 비율은 체인이 확정되기 전에는 산정할 수 없습니다.** 가스비 변동폭이 체인마다 전혀 다르기 때문입니다. (결정 I-2)

## 5-4. ★ 가스비 — 정책 확정 (2026-10-21)

```
기존 구조    테더맥스가 송금 안 함        → 가스비 항목 자체가 없음
CEX         거래소 내부이체             → 온체인 수수료 없음
신규 DEX    출금 1건마다 온체인 EVM 전송 → 건당 실비 발생 ★
```

### 확정된 4가지

| # | 결정 | ID |
|---|---|---|
| 1 | **테더맥스가 가스비 전액을 부담한다** | F-1 |
| 2 | **가스비를 확인해 함께 출금한다.** 고객이 10을 요청하면 **고객 지갑에 정확히 10이 도착해야 한다** | F-2 |
| 3 | **사용자 화면에 수수료를 표시하지 않는다** (Confirm 모달에 `Network fee` 행 없음) | F-3 |
| 4 | **가스비는 순수 손실로 처리한다.** 사업 쪽 결정 | F-5 |

### 귀결 — Wallet B 소요액

```
Wallet B 필요액 = Σ(고객 출금액) + Σ(가스비)
```

가스비가 건당 2~5 USDT라면:

```
고객 수령     10.00 USDT
가스비        +2~5 USDT   ← 테더맥스 부담
─────────────────────────
건당 총비용   12~15 USDT
```

**페이백 100%를 유저에게 지급하는 구조이므로 가스비는 전액 손실입니다.**

### → 네트워크 리서치의 핵심 평가 기준

A-3(체인 리서치) 담당자에게 다음 산정을 요청해야 합니다:

```
월 손실액 = 건당 가스비 × 예상 월 출금 건수
```

저렴한 체인을 고르는 기술 선택이 아니라 **사업성이 직결된 결정**입니다.
체인별 건당 가스비 차이가 월 손실액을 수 배 단위로 바꿉니다.
