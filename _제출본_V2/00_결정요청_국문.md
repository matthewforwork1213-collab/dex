## 1-3. `D-7` 지갑 주소 — **축약이 맞습니다**

*"이거 지갑 주소 꼭 끝까지 나와야 할까요? 다른 서비스에선 어떻게 하나요?"*

### 업계 표준은 **축약**입니다

| 자리 | 업계 관행 |
|---|---|
| **목록 · 계정 선택 · 카드** | **축약.** 지갑·DEX·마켓플레이스 전부 `0x7a3F…c51E9` 형태 |
| **보내기 직전 목적지 확인** | 전체 + QR + 복사 버튼 |
| 블록 익스플로러 | 전체 |

**이유는 단순합니다 — 42자를 눈으로 대조하는 사람이 없습니다.** 실제로는 앞뒤 몇 자만 봅니다. 그래서 전체를 띄워도 **대조 정확도가 올라가지 않고 화면만 깨집니다.**

### 우리는 전체를 보여줄 자리가 **아예 없습니다**

전체 표시가 필요한 유일한 상황은 **"보낼 곳을 확인"** 하는 순간인데,

> **출금 목적지는 연동된 지갑으로 고정**이고 **사용자가 주소를 입력하지 않습니다.**

→ **대조할 대상 자체가 없습니다.** 전체 길이가 남는 곳은 **어드민과 이메일 기록**뿐이고, 둘 다 이미 전체 표시로 확정돼 있습니다.

### 🟠 단, 깨지는 경우가 하나 있습니다

```
0x7a3F…c51E9
  └┬─┘  └┬─┘
  앞 6자  뒤 4자   →  0x 는 항상 고정이므로
                     실제로 구분하는 문자는 8자뿐
```

**이 충돌은 가정이 아닙니다.** Lighter는 **축약 주소가 겹치면 지갑을 `Processing`으로 잡아두는** 구조입니다 — 우리 시스템 안에서 실제로 일어납니다.

→ 한 회원이 **같은 거래소에 지갑 둘**을 연동했고 축약값이 같으면, 선택 목록에 **똑같은 행이 둘** 뜨고 구분할 수 없습니다.
**그 경우에만** 더 긴 형태나 사용자 별칭이 필요합니다. (제가 `16-15`로 올려두겠습니다)

11월  DEX 4곳 추가
