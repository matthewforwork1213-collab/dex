# 어드민 화면별 DEX 반영 사항

작성일 2026-10-20
근거: 실제 어드민 화면 12종 + DEX Backoffice PRD + 기존 테더맥스 정책
범위: **기존 어드민 화면 변경분.** 신규 화면은 별도 문서로 분리합니다.

---

## 0. 대원칙

PRD가 정한 설계 원칙입니다. 화면 변경은 전부 이 원칙을 따릅니다.

> **복제하지 말고 분류한다.**
> 거래소 레코드에 `Exchange Type`(CEX / DEX / Broker) 필수 필드를 추가하고, 하위 모듈은 **DEX 전용 사본 없이 이 필드만 읽습니다.** (`LST-1` "병렬 모듈 금지")

**이 원칙에서 파생되는 3가지 판정 기준**

| 기준 | 적용 |
|---|---|
| **① 돈이 테더맥스를 거치는가** | 거치지 않으면 DEX 행을 만들지 않거나 `-` 처리 |
| **② 식별자가 UID인가 지갑인가** | 컬럼·검색·마스킹 규칙을 분기 |
| **③ 금액 합계에 DEX가 섞여도 되는가** | 섞이면 "테더맥스가 지급할 돈"으로 잘못 읽힘 → 분리 |

## 2. 회원관리 > 회원 리스트

### 현재 구성

**요약 카드** 어제 가입자 / 오늘 가입자 / 페이백 신청(24hr)
**필터** 구분, 국가 코드, 항목 필터, 기간 정렬(최신순), 연동계정 Y·N, 내용 검색
**기간** 페이백 기간(시작~종료), 회원 가입일(시작~종료)
**액션** 초기화, 검색, 엑셀 다운로드, 페이백 엑셀 업로드

**컬럼** 번호 / 회원 번호 / 추천인 코드 / 나의 초대코드 / 아이디(이메일) / 현재 페이백 잔여액 / 누적 페이백 잔여액 / 남은 페이백(기간 적용) / 누적 페이백(기간 적용) / 연동계정수 / 구글 OTP 연동 / 회원 가입일 / 국가 코드

### 변경 사항

**2-1. 금액 컬럼 4개에 DEX 금액을 섞지 않습니다 🔴**

`현재 페이백 잔여액` / `누적 페이백 잔여액` / `남은 페이백(기간 적용)` / `누적 페이백(기간 적용)`

이 네 컬럼은 **테더맥스가 보유하고 지급할 금액**입니다. DEX 페이백은 이미 사용자의 DEX 계정에 들어가 있어서 테더맥스가 지급할 의무가 없습니다. 섞으면 CS와 재무가 "지급해야 할 돈"으로 잘못 읽습니다.

| 안 | 내용 | 권고 |
|---|---|---|
| (a) | 기존 4개 컬럼은 **CEX 전용 유지**, DEX 금액은 별도 컬럼 `DEX 누적 페이백(USDT)` 1개 추가 | **권장** |
| (b) | 기존 컬럼에 합산하고 툴팁으로 설명 | 비권장 |
| (c) | DEX 금액을 이 화면에 표시하지 않음 | 가능 |

(a)를 권장하는 이유는, CS가 "이 회원에게 DEX 페이백이 얼마나 쌓였나"를 묻는 문의를 받을 수 있기 때문입니다. 보이되 분리되어야 합니다.

**2-2. `연동계정수` 분리**

현재는 단일 숫자입니다. DEX 지갑이 들어오면 **UID 수와 지갑 수를 분리**해야 합니다.

- 표기안: `3 / 2` (UID 3, 지갑 2) 또는 컬럼 2개로 분리
- **지갑 한도 관리에도 필요합니다.** 한도가 "3 × 활성 DEX 수"라면 운영자가 사용량을 봐야 합니다

**2-3. 필터 `연동계정 Y,N` 확장**

`전체 / 연동 있음 / 연동 없음`에 더해 `UID만 / 지갑만 / 둘 다`를 구분할 수 있어야 합니다. **CEX 연동 없이 DEX만 쓰는 회원**을 찾아야 할 일이 생깁니다 — 3 USDT 쿠폰을 청구할 수 없는 회원이 여기에 해당합니다.

**2-4. 엑셀 다운로드**

위 컬럼 변경을 반영합니다. 금액 컬럼의 통화는 전부 USDT이고, DEX 원 통화(USDC 등)는 이 화면에 노출하지 않습니다.

## 3. 회원관리 > 제휴사 (목록)

### 현재 구성

**필터** 등록일(최신순), 검색 구분, 거래소(UID 검색), 내용 검색
**컬럼** 번호 / 회원번호 / 가입 이메일 / 리워드 출금 거래소 / 리워드 출금 UID / 초대 코드 / 누적 초대 리워드 / 리워드 비율 / 등록일 / 수정일 / 수정 / 하부 내역 / 삭제

### 변경 사항

**3-1. `리워드 출금 거래소`와 `리워드 출금 UID`는 CEX 전용 유지**

테더맥스가 초대 리워드를 송금하는 목적지입니다. DEX 지갑은 올 수 없습니다.

**3-2. `거래소(UID 검색)` 필터에서 DEX 제외**

이 필터는 리워드 출금 거래소를 찾는 용도이므로 DEX를 넣으면 항상 빈 결과입니다.

**3-3. `하부 내역`에는 DEX가 나타납니다**

하위 계정이 DEX를 쓸 수 있으므로 상세 화면에는 DEX 행이 표시됩니다. 다만 **그 행의 초대 리워드는 0**입니다.

기존 규칙과 자동으로 맞아떨어집니다.
> 초대 리워드 = 하위 계정 출금액 × 거래소 마진 × 리워드 비율

DEX는 테더맥스를 통한 출금이 없어 **출금액이 0**이고, 마진율도 0으로 둘 예정이므로 **별도 차단 로직 없이 0**이 됩니다.

> 🔴 **2026-10-20 갱신 — 이 서술은 A-19와 어긋납니다.** [03_정책_결정_기록.md](03_정책_결정_기록.md) A-19에서 **"DEX 초대에도 초대 리워드가 발생한다. DEX 행에도 실제 누적 금액을 표시한다"**로 결정됐습니다(사용자 지시). 근거는 **테더맥스가 DEX로부터 margin을 받기 때문**입니다 — Lighter는 테더맥스 몫이 메인 계정으로, EdgeX는 `partnerRate` 차액이, Aster·ApeX도 각각 커미션 구조가 있습니다.
>
> 따라서 **"자동으로 0이 되니 편하다"는 전제를 더 이상 쓸 수 없습니다.** 공식의 입력값을 바꿔야 A-19가 성립합니다.
>
> | 입력값 | 현행 (CEX 전제) | DEX에 필요한 값 |
> |---|---|---|
> | 하위 계정 출금액 | 테더맥스 출금액 → DEX는 0 | **DEX가 지급한 페이백 금액** |
> | 거래소 마진 | 0으로 둘 예정 | **DEX별 실제 파트너 요율** |
>
> 선례가 있습니다 — 챌린지 누적 기준도 같은 방식으로 `적격 UID에 지급된 커미션` → `+ DEX가 지급한 페이백 금액`으로 넓혔습니다(03 문서). 미해결 공백은 **B-2-8**(지급 트리거 부재)·**B-2-9**(DEX만 연동한 초대자의 출금 경로)입니다.

**3-4. ~~하부 내역에 오해 방지 표기 추가~~ → 🔴 폐기 (2026-10-22)**

> ~~DEX 행에 `초대 리워드 대상 아님` 표기가 필요합니다.~~

**A-19와 정면으로 어긋납니다.** DEX 초대에도 **초대 리워드가 발생합니다.** `대상 아님` 표기를 붙이면 **확정된 정책과 반대되는 안내**가 화면에 나갑니다.

대신 필요한 것은 **0이 보일 때의 설명**입니다. 마진율이 비어 있으면 출금액은 실재하는데 리워드만 0으로 찍히므로, 제휴사는 *"하위는 버는데 나는 왜 0인가"* 를 화면에서 알 수 없습니다. → `D-1` 마진율이 들어오면 해소됩니다.

> **프로토타입 확인 위치** — 백오피스 `회원·제휴사 > 제휴사 하부 내역`

## 4. 회원관리 > 제휴사 등록 모달 — **필수 변경**

### 현재 구성

| 필드 | 형태 |
|---|---|
| 회원번호 | 입력 |
| 상위 파트너 타입 / 이메일 | 드롭다운(`Affiliate (A)`) + 입력 |
| 커미션비율 | `commissionRate` 필수 |

| 제휴사 별명 | 입력 |

### 변경 사항

**4-1. `거래소명` 드롭다운에서 DEX 제외 🔴**

**이 필드는 리워드 출금 목적지를 정하는 곳입니다.** 테더맥스가 DEX 지갑으로 송금할 수단이 없으므로 DEX를 선택할 수 없어야 합니다.

| 항목 | 처리 |
|---|---|
| 드롭다운 목록 | `Exchange Type = CEX`인 활성 거래소만 |
| 서버 검증 | 드롭다운을 우회해 DEX ID가 들어와도 **서버에서 거부** |
| 거부 메시지 | `Destination must be a linked centralised exchange UID` 계열 |

**4-2. `거래소 UID` 필드 라벨 유지**

DEX를 제외하므로 이 필드는 UID 전용입니다. 지갑 주소 입력 분기가 필요 없습니다.

**4-3. 참고 — 같은 규칙이 적용되는 다른 화면**

| 화면 | 처리 |
|---|---|
| 페이백 > 초대 리워드 출금 | CEX 전용. DEX 서버 거부 |
| 이벤트 > 이벤트 리워드 지급 | CEX 전용. 필터에 DEX 없음 |

## 5. UID > UID 리스트 — **가장 큰 변경**

### 현재 구성

**필터** 구분, 거래소, 내용 검색 / 연동상태 Y·N, 소유권 Y·N, 정렬(최신순), `이슈` 체크박스
**기간** 페이백 기간, 생성일
**결과 요약** `검색 결과: 85087`, `누적 페이백(기간적용): 55943956.07`
**액션** 엑셀 다운로드, 페이백 엑셀 업로드

**컬럼** 번호 / 연동·인증(Y·N 뱃지 2개) / 거래소 / UID / 테더맥스 UID / 누적 페이백(USDT) / 남은 페이백(USDT) / 받아간 페이백(USDT) / 누적 페이백(기간 적용) / 남은 페이백(기간 적용) / 받아간 페이백(기간 적용) / 이슈 / 생성일 / 수정일

### 변경 사항

**5-1. 메뉴 이름 변경**

| 현재 | 변경 후 |
|---|---|
| `UID` (상위 메뉴) | **`Account`** |
| `UID 리스트` | **`Account List`** 또는 `계정 리스트` |

지갑 주소도 담기 때문입니다(`NAV-5`). 하위 항목 순서는 유지합니다. 기존 URL(`/UID/...`) 북마크는 리다이렉트로 유지하는 것을 권고합니다.

**5-2. 컬럼 추가 3개**

| 컬럼 | 내용 |
|---|---|
| **Exchange Type** | `[CEX]` / `[DEX]` 뱃지. 기존 레코드는 전부 CEX로 일괄 채움 |
| **지갑 주소** | `0x` + 앞 4자 … 뒤 4자 + 복사 아이콘. 복사 시 전체 주소. 표시는 EIP-55 체크섬 형식 |
| **DEX 계정 ID** | DEX가 반환한 값. Lighter·Aster는 비어 있는 것이 정상. ApeX는 미반환 상태라 `확인 중` 표기 필요 |

**5-3. `UID` 컬럼 처리**

DEX 행에서는 UID가 없습니다. 두 가지 안이 있습니다.

| 안 | 내용 |
|---|---|
| (a) `UID` 컬럼에 DEX는 지갑 주소를 표시하고, 헤더를 `UID / 지갑 주소`로 변경 | 컬럼 수가 늘지 않음 |
| (b) `UID`는 CEX 전용으로 두고 `지갑 주소` 컬럼을 별도로 추가 | **권장.** 검색·정렬·복사 동작이 달라서 분리가 안전 |

**5-4. DEX에서 의미가 없는 컬럼 🔴**

| 컬럼 | DEX 행 처리 | 이유 |
|---|---|---|
| `남은 페이백(USDT)` | **`-`** | 테더맥스가 보유한 미출금 잔액. DEX에는 없음 |
| `남은 페이백(기간 적용)` | **`-`** | 동일 |
| `받아간 페이백(USDT)` | **DEX가 Paid로 보고한 금액** | 테더맥스 출금이 아니라 DEX 지급액. 의미가 다르므로 컬럼 설명 필요 |
| `받아간 페이백(기간 적용)` | 동일 | |
| `누적 페이백(USDT)` | DEX 누적 적립액 | USDC는 1:1, Aster는 `usdtValue` |

`받아간 페이백`이 가장 헷갈립니다. CEX에서는 "사용자가 테더맥스에서 출금해 간 금액"인데, DEX에서는 "DEX가 사용자에게 지급한 금액"입니다. **컬럼 헤더에 툴팁을 붙이거나 DEX 전용 컬럼으로 분리**해야 합니다.

**5-5. 상단 합계 분리 🔴**

현재 `누적 페이백(기간적용): 55943956.07`은 단일 합계입니다. DEX 금액이 섞이면 **재무가 "테더맥스가 지급한 총액"으로 읽습니다.**

권고 표기:
```
검색 결과: 85,087
누적 페이백 (기간적용) — CEX: 55,943,956.07 USDT  |  DEX: 0.00 USDT
```

타입 필터를 적용하면 해당 타입 합계만 표시합니다.

**5-6. 검색 카테고리 추가**

`구분` 드롭다운에 **`지갑 주소`**와 **`DEX 계정 ID`**를 추가합니다. 선택하면 `거래소` 드롭다운이 활성 DEX 목록으로 바뀝니다.

검색 규칙
- 전체 값으로 검색. 부분 검색 불가
- 앞뒤 공백 제거, 대소문자 무시
- 빈 값은 서버에서도 거부
- 형식 오류는 "결과 없음"이 아니라 **오류 메시지** 표시

**5-7. 필터 추가**

| 필터 | 값 |
|---|---|
| **Exchange Type** | 전체 / CEX / DEX / Broker |
| 기존 `연동상태 Y,N` | DEX에도 적용 |
| 기존 `소유권 Y,N` | **DEX는 항상 N (A-16).** 소유권 경로가 없습니다 |
| 기존 `이슈` 체크박스 | **DEX 대응 개념 미정** — 아래 5-8 |

**5-8. `이슈` 개념의 DEX 대응 ⚠️**

CEX의 `이슈 UID`는 페이백 내역·랭킹·쿠폰 선택·초대 리워드 출금에서 전부 제외되는 플래그입니다. **지갑 주소에는 대응물이 정의되지 않았습니다.**

DEX에서 비슷한 상황이 되는 경우:
- ApeX 계정 ID 미반환
- 제한 IP에서의 거래 (커미션 0)
- Aster 바인딩 만료 후 레코드

이것들을 `이슈`로 묶으면 **의도치 않게 랭킹·내역에서 전면 제외**됩니다. **별도 상태값으로 분리할 것을 권고**합니다. 정책 결정이 필요합니다.

**5-9. 성능**

현재 8.5만 행입니다. DEX 지갑이 추가되고 타입 필터가 들어가면 **인덱스가 필요합니다.** PRD는 타입 필터 적용 시 2초 이내를 요구합니다(`NFR-3`).

## 6. UID > 소유 확인 — 🚫 **보류 (A-16)**

> **2026-10-20 확정.** DEX는 소유권 경로가 없으므로 **이 화면에 DEX 관련 변경이 없습니다. 동영상 플레이어 신설도 불필요합니다.**
>
> 아래는 보류 전에 정리한 내용으로, 소유권을 다시 도입할 때의 출발점으로 남겨 둡니다. **현행 설계가 아닙니다.**

### 현재 구성

**필터** 구분, 거래소(UID 검색), 내용 검색. `검색 결과: 151`
**컬럼** 번호 / 상태 변경(`완료(1)`) / 처리 여부(`완료`) / UID / 거래소 / 테더맥스 UID / 생성일 / 수정일 / **첨부파일(이미지 썸네일)** / 거절시 사유

### 변경 사항

**6-1. 첨부파일이 동영상으로 바뀝니다 🔴**

| 항목 | CEX (현재) | DEX |
|---|---|---|
| 증빙 형태 | 이미지 썸네일 | **MP4 또는 MOV, 최대 100MB** |
| 심사 방식 | 썸네일 확대 | **재생해서 3단계 확인** |

**필요한 기능**
- 목록에서 **동영상 썸네일 또는 재생 아이콘** 구분 표시
- 상세에서 **인라인 플레이어**. 배속·구간 이동 필요 (100MB 영상을 5분 안에 심사해야 함)
- **다운로드 금지** (개인정보). 스트리밍만
- 바이러스 검사 실패 시 큐에 올리지 않음
- 열람 자체를 감사 기록에 남길 것을 권고

**6-2. 심사 기준 3단계 표시**

심사자가 무엇을 확인해야 하는지 화면에 명시합니다.

| 단계 | 확인 항목 |
|---|---|
| 1 | 녹화 시작 후 DEX에서 **지갑 연결 해제**가 보이는가 |
| 2 | **같은 지갑으로 재연결**하는 과정과 승인 화면이 보이는가 |
| 3 | 계정 메뉴에서 **전체 지갑 주소**가 모든 문자 식별 가능하게 보이는가 |

**6-3. 거절 사유 표준화**

현재 `거절시 사유`가 자유 입력입니다. DEX는 표준 사유 6종을 제안합니다. 운영 일관성에 직접 영향을 줍니다.

1. 주소 불일치
2. 연결 해제·재연결 미표시
3. 주소 일부 가려짐
4. 다른 DEX 화면
5. 재생 불가
6. 편집된 영상

사유는 **사용자에게 그대로 표시**되므로 문구를 확정해야 합니다.

**6-4. 컬럼 추가**

- `Exchange Type` 뱃지
- `지갑 주소` (DEX 행)
- `경과 시간` — 5분 목표 대비. 기존 정책에 **10분 무응답 시 자동 실패** 규칙이 있어 운영자가 남은 시간을 봐야 합니다

**6-5. 자동 실패 시간 확인 필요 ⚠️**

| 출처 | 값 |
|---|---|
| 기존 테더맥스 정책 | **10분 무응답 시 자동 실패** |
| DEX PRD | 검토 목표 약 5분, 자동 실패 규칙 없음 |

**동영상 심사는 이미지보다 오래 걸립니다.** 10분 자동 실패를 DEX에도 적용하면 실패율이 올라갈 수 있습니다. 확인이 필요합니다.

## 8. 페이백 > 전체 내역 — **DEX 행이 생기면 안 됨**

### 현재 구성

**필터** 내용 검색, 기간 정렬(최신순), 구분, 거래소(UID 검색), 페이백 금액순, 방식 구분, 회원 구분, 시작~종료 날짜
**컬럼** 번호 / 테더맥스 UID / 상태(`실패`/`성공`) / 처리 여부(`완료`) / 거래소 목록 / 거래소 UID / 신청 페이백 금액 / 신청 이벤트 리워드 금액 / 합산 신청 금액 / 페이백 신청시각(KST) / 페이백 출금시각(KST) / 페이백 신청시각 / 페이백 출금시각

### 변경 사항

**8-1. 이 화면은 "테더맥스를 통한 출금 신청" 화면입니다 🔴**

컬럼 구성이 이를 증명합니다 — `신청 페이백 금액`, `신청 이벤트 리워드 금액`, `합산 신청 금액`, `페이백 신청시각`, `페이백 출금시각`.

**DEX는 출금 신청 자체가 없습니다.** 사용자가 DEX 사이트에서 직접 출금하고 테더맥스는 그 사실을 알 수도 없습니다. 따라서 **이 화면에 DEX 행이 생기면 안 됩니다.**

| 항목 | 처리 |
|---|---|
| DEX 행 | **생성 금지.** 서버에서 DEX 출금 레코드 생성 자체를 거부 |
| `거래소(UID 검색)` 필터 | **DEX 제외.** 넣으면 항상 빈 결과 |
| `거래소 목록` 컬럼 | CEX만 표시 |

**8-2. 같은 규칙이 적용되는 좌측 메뉴 화면들**

화면에 보이는 페이백 하위 메뉴 중 DEX 제외 대상입니다.

| 메뉴 | DEX 처리 | 이유 |
|---|---|---|
| 비회원 수동 페이백 | **DEX 행 표시만** (출금 처리 아님) | 비회원 DEX 조회 기록. 아래 8-3 |
| 회원 수동 페이백 | 제외 | 테더맥스 지급 |
| **전체 내역** | **제외** | 테더맥스 출금 |
| 인도네시안 페이백 내역 | 제외 | 테더맥스 지급 |
| 초대 리워드 출금 | **제외** | CEX 전용 |
| 신규·기존 회원 페이백 챌린지 | 제외 (집계는 별도 검토) | 보상이 이벤트 리워드 |
| 페이백 미리 정산 | **제외** | 테더맥스 선지급 |
| STG 페이백 | 제외 | 테스트 |

**8-3. 비회원 수동 페이백 화면의 DEX 처리 ⚠️**

이 화면은 **CEX 출금 처리 모듈**인데 PRD는 여기에 DEX 비회원 조회 기록을 섞도록 설계했습니다(`LST-42`). 문제가 있습니다.

DEX 행에서 아래 컬럼의 의미가 정의되지 않았습니다.
- `Requested Cashback` / `신청 페이백 금액`
- `Final Request Amount` / `합산 신청 금액`
- `Withdrawal Time` / `페이백 출금시각`
- `Process Status` / `처리 여부`

**권고:** 비회원 DEX 조회 기록은 **별도 화면으로 분리**하거나, 같은 화면에 두되 **DEX 행은 조회 기록 전용**임을 명확히 하고 출금 관련 컬럼을 `-`로 둡니다. 운영자가 "처리"해야 할 대상이 아니기 때문입니다.

## 10. 거래소 > 거래소 래퍼럴 관리

### 현재 구성

**컬럼** 번호 / 거래소명 / 계정명 / **마진율** / 최종 수정자 / 수정
**현재 데이터** Bybit 39.96, BingX 50, Bitget 10, OKX(Before 260622) 57.14, HTX 40, BVOX 0, CoinCatch 20, BitMart 29.41, BitMEX 0, DeepCoin 39.75, BloFin 9.09, WOOX 31.81, Zoomex 44.44, MEXC 37.5, Gate 6.25

### 변경 사항

**10-1. 마진율의 역할을 먼저 확인해야 합니다**

기존 운영 규칙에 따르면 이 값은 두 곳에 쓰입니다.

1. **페이백 계산** — `페이백 = 총 커미션 × (1 - 마진율)`
2. **초대 리워드 계산** — `초대 리워드 = 하위 출금액 × 거래소 마진 × 리워드 비율`

그리고 기존 CS 규칙에 이런 문장이 있습니다.
> 거래소 margin rate가 0이면 사용자·파트너 모두 초대 리워드가 생성되지 않습니다.

**10-2. DEX 행 추가 여부와 마진율 설정**

| 안 | 내용 | 결과 |
|---|---|---|
| (a) **DEX 행을 추가하고 마진율 0** | 구조 일관성 유지 | **초대 리워드가 기존 규칙만으로 자동 0.** 별도 차단 로직 불필요 |
| (b) DEX 행을 추가하지 않음 | 이 화면은 CEX 전용 | 다른 모듈이 이 테이블을 조회할 때 DEX가 없어 오류 가능 |

**(a)를 권장합니다.** 별도 코드 없이 정책이 자동으로 지켜집니다.

**10-3. 다만 DEX의 페이백 계산에는 이 마진율을 쓰지 않습니다 ⚠️**

DEX는 테더맥스가 페이백을 계산하지 않습니다. **DEX가 산정한 금액을 그대로 받습니다.** 따라서 마진율 0이 페이백 표시에 영향을 주면 안 됩니다.

구현 시 **"DEX 행의 마진율은 초대 리워드 계산에만 사용하고 페이백 계산에는 사용하지 않는다"**를 명시해야 합니다.

**10-4. 컬럼 추가**

- `Exchange Type` 뱃지
- `최종 수정자` 컬럼은 이미 있습니다. **DEX 요율·설정 변경에도 같은 패턴을 적용**할 것을 권고합니다

| (b) 섹션명을 `계정 생성 안내`로 바꾸고 내용을 DEX에 맞게 작성 | 가입 절차 안내가 필요하면 유용 |

(a) + 별도 `DEX 계정 생성 가이드` 섹션 신설이 가장 깔끔합니다. DEX 가입은 "지갑 설치 → 레퍼럴 링크로 접속 → 지갑 연결 또는 이메일 가입"이라 CEX와 단계가 완전히 다릅니다.

>
> **(3)이 (a)인 이유:** DEX만 연동한 회원을 잡으려면 `DEX 전체` 선택으로 처리하면 됩니다.
> `없음`을 "CEX만 없음"으로 두면 DEX 연동자가 미연동자로 섞여 **오발송**이 납니다.

**AND / OR** — 현재 OR 기본값입니다. CEX 그룹과 DEX 그룹 사이에도 같은 연산자가 적용되는지,
그룹별로 분리할 수 있어야 하는지 확인이 필요합니다.

```
OR    Bitget 또는 Lighter 연동                    ← 합집합
AND   Bitget 과 Lighter 를 모두 연동               ← 교집합
?     (CEX 중 아무거나) AND (DEX 중 아무거나)      ← 그룹별 연산자가 필요한 경우
```

### 13-9-2. 🔴 **5번 말고도 DEX가 걸리는 조건이 4개 더 있습니다**

거래소 칩만 추가하면 끝나는 화면이 아닙니다. **나머지 조건들의 집계 범위에 DEX가 포함되는지**가 전부 미정입니다.

| 조건 | DEX 쟁점 | 영향 |
|---|---|---|
| **1. 회원 구분** | `커미션 페이백 이력 존재/없음` 판정에 **DEX 페이백이 포함되는가** | DEX만 쓰는 회원이 "이력 없음"으로 분류되면 **발송 대상에서 누락** |
| **2. 커미션 페이백** | 금액 범위 필터가 **CEX+DEX 합산인가 CEX만인가** | 합산이 아니면 금액대 타겟팅이 어긋남 |
| **2-1. 이벤트 리워드** | DEX 이벤트 리워드가 포함되는가 | **A-1로 DEX에도 이벤트 리워드를 주기로 했으므로 포함되어야 함** |
| **3. 출금 여부** | `출금 이력 있음/없음`에 **DEX 출금이 포함되는가** | V2는 DEX도 테더맥스에서 출금하므로 **포함이 자연스러움** |
| **6. 날짜 선택** | `날짜 구분` 드롭다운 항목에 DEX 관련 기준일이 필요한가 | 드롭다운 내용 미확인 |

**원칙 제안**

> **2~3번은 "테더맥스 잔액" 기준이므로 CEX·DEX를 합산해야 합니다.**
> V2에서 DEX 페이백도 테더맥스 잔액에 쌓이고 테더맥스에서 출금되므로, 분리할 근거가 없습니다.
>
> **1번도 같은 논리로 DEX 페이백을 포함해야 합니다.**
> 포함하지 않으면 DEX만 쓰는 회원이 `커미션 페이백 이력 없음`으로 잡혀,
> 페이백을 받고 있는데도 "아직 페이백이 없는 회원" 대상 푸시를 받게 됩니다.

→ **화면 확인 필요:** `금액 구분` 드롭다운과 `날짜 구분` 드롭다운의 선택지 목록
