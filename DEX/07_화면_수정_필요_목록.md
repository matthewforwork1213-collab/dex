## 1. 전역 / 공통

### 1-1. 🔴 "Available Cashback" 명칭 재정의

**현재:** DEX 카드가 `Available Cashback`으로 표시하지만 값은 **누적 적립액**입니다.

**문제**
- 사용자가 DEX에서 출금해도 이 숫자는 줄지 않습니다 (의도된 동작)
- DEX마다 의미가 다릅니다

| DEX | 실제 값 |
|---|---|
| Lighter | 주간 CSV 기준 누적 Paid |
| ApeX | 누적 Paid. 별도로 `Available on ApeX`가 실제 잔액 |
| EdgeX | `totalPaidAmount` — 누적 지급액 |
| Aster | 정의 없음 |

**ApeX 카드에는 "Available"이 두 개 있어** 어느 쪽이 실제로 뺄 수 있는 돈인지 알 수 없습니다.

**수정안:** 전 DEX에서 `Paid` 계열 명칭으로 변경. ApeX의 `available_balance`만 `Available on ApeX`로 유지 (이것만 실제 출금 가능액).

**영향 화면:** DEX 선택 카드, Hub 잔액 패널, 출금 드로어, 비회원 My Cashback, Cashback Summary 필터

---

### 1-2. 🔴 Total Claimed 제거

**현재:** DEX 카드와 비회원 카드에 `Total Claimed`가 있습니다.

**문제:** **4개 DEX 모두 누적 출금액을 제공하지 않습니다.** 구조적으로 제공할 이유도 없습니다 — 출금은 DEX 내부에서 사용자가 직접 하는 일이고 테더맥스는 당사자가 아닙니다. EdgeX만 `Paid to your EdgeX account` / `On the way`로 대체돼 있습니다.

**수정안:** DEX 화면 전체에서 제거.

---

### 1-3. 🟠 상태 칩 마스터 목록 수립

**현재:** 상태 칩이 문서 곳곳에 흩어져 있고 **마스터 목록과 우선순위가 없습니다.**

발견된 상태: `Active` / `Processing` / `Unavailable` / `Standard account, no cashback` / `Expires in {n} days` / `Referral expired` / `Inactive` / `Ownership verification in progress` / `This wallet has been unlinked` / `Ownership verification was unsuccessful` / `Data delayed`

**문제**
- 두 개 이상 동시 해당 시 우선순위가 없음 (예: Aster 만료 임박 + 데이터 지연, Lighter Standard + Processing)
- 행(Linked Accounts)과 카드(선택된 계정)의 표시가 다름
- EdgeX·ApeX 고유 상태(AccountID 미반환, 제한 IP 거래)는 칩 자체가 없음

**참고:** 기존 테더맥스에 **UID 상태 우선순위 1~7**이 있습니다. 전역 규칙은 이것 하나뿐이므로 같은 형식(정수 priority)으로 확장하는 것이 일관성 측면에서 낫습니다.

**수정안:** 상태 정의표를 별도 작성. 열 = 상태명 / 조건 / 우선순위 / 행 표시 / 카드 표시 / 금액 표시 여부 / 액션 상태 / 적용 DEX.

---

### 1-4. 🟠 `Unavailable` 칩 명칭 변경

**현재:** 페이백이 0일 때 `Unavailable` 칩이 표시됩니다.

**문제:** 정상적으로 연동한 신규 사용자에게 "사용할 수 없음"으로 읽힙니다. 실제로는 "아직 거래를 안 해서 적립이 없음"입니다.

**수정안:** `No cashback yet` 계열로 변경.

---

### 1-5. 🟠 요율 하드코딩 제거

**현재:** `CH-16`이 요율 하드코딩을 금지하는데, 아래가 고정 문구입니다.
- `RT-3` / `RT-4` / `RT-5`: "UP TO 90% / 30% / 84%"
- `CH-4`: "0.0280%"

**문제:** 요율이 바뀌면 배포가 필요합니다.

**수정안:** `UP TO {n}%` 형태로 바꾸고 해당 라우트 파트너 중 최고 요율을 계산해 넣습니다.

---

### 1-6. 🟡 "Exchange Cashback" 용어 중복

CEX 전용 카드가 `Exchange Cashback Balance`인데, DEX 카드 내부 항목도 `Exchange Cashback`입니다. 서로 다른 것을 같은 단어로 부릅니다.

**수정안:** DEX 쪽을 `Trading Cashback` 또는 `{DEX} Cashback`으로 분리.

---

### 1-7. 🟡 영문 용어를 공식 언어팩에 맞추기

기존 언어팩 기준 공식 영문입니다.

| 한국어 | 공식 영문 | 쓰면 안 되는 말 |
|---|---|---|
| 페이백 / 페이백 | `cashback` | `payback`, `rebate` |
| 연동 | `Link` | `integration`, `interworking` |
| 연동 해제 | `Unlink` | `disconnect` |
| 비회원 | `non-member` | `guest` |
| 포인트 | `point` / TP | `Points` (복수형 비표준) |

**현재 DEX PRD는 영문에서 `cashback`을 올바르게 쓰고 있습니다.** 다만 `Points`(GN-6) vs `Point`(4.20) 불일치가 있습니다.

---

### 1-8. 🟡 시간대 표기 통일

**수정안:** 회원 화면은 UTC 통일 + `(UTC)` 명시. 백오피스는 UTC 주 표기 + KST 보조 (한국 운영자 기준).

---

### 1-9. 🟡 금액 표시 자릿수 규칙

**현재:** 계산기 일별 금액이 `$0.0333`처럼 소수 4자리인데 다른 금액은 2자리입니다. 통일 규칙이 없습니다.

**제안된 규칙:** 저장은 원 정밀도, 표시는 2자리 반올림(half-up), 합계는 반올림 전 값으로 더한 뒤 반올림. 랭킹 정렬은 반올림 전 값 기준.

## 2. Cashback Hub

### 2-1. 🟠 CEX 파트너 수 오류

`RT-6`이 "16 CEX marks"인데 메인 PRD와 `LW-26`은 17개입니다 (23 = 17 + 4 + 2).

### 2-2. 🟠 라우트 순서 불일치

`GL-2`·`CH-4`는 CEX → DEX → 브로커, `RT-2`는 DEX → CEX → 브로커입니다. 의도 확인 후 통일이 필요합니다.

### 2-3. 🟠 계산기 거래량 범위 불일치

Hub는 DEX 1K~250K, 상세 페이지는 100K~10M입니다. **같은 DEX의 같은 계산인데 범위가 다릅니다.**

**수정안:** DEX별 단일 범위를 백오피스(Spending Estimate)에서 관리하고 두 화면이 같은 값을 읽습니다.

### 2-4. 🟠 게스트 이유 카드에 CEX 전용 내용

`RT-7`의 3개 카드 중 "More cashback from events"와 "Invite friends, earn more"는 **CEX에서만 발생합니다.** DEX 랜딩(`DX-8`)에서 재사용할 때 그대로 노출됩니다.

**수정안:** DEX 맥락에서는 해당 카드를 숨기거나 단서를 붙입니다.

### 2-5. 🟡 비교표 컬럼명

컬럼명이 `Exchange`, 검색 문구가 `Search for an exchange`인데 DEX와 브로커까지 포함합니다.

### 2-6. 🟡 비교표 미정 항목

- 브로커의 Final Taker / Maker 표시 방법
- 브로커 Monthly cashback이 어느 공식을 쓰는지
- `Highest payout` 배지 기준 (필터별인지 전체인지)
- Rating 데이터 출처

### 2-7. 🟡 터치 동작 충돌

`GL-2`에서 터치 기기는 tap으로 Cashback 패널을 열고, 라벨 클릭은 랜딩으로 이동합니다. 같은 tap에서 무엇이 일어나는지 정의가 필요합니다.

### 2-8. 🟡 앱 진입 경로

`GN-6`은 Cashback이 "모든 Cashback 상품의 단일 진입점"이라면서 Exchanges 탭을 유지합니다. 앱에서 DEX로 가는 경로가 정의되지 않았습니다.

### 2-9. 🔴 페이백 계산기 (실물 화면) — DEX 추가 필요

**화면:** `Cashback Preview` → 1단계 `먼저, 가장 자주 사용하는 거래소는 어디인가요?`
**형태:** 상단 진행바 + 거래소 카드 그리드(단일 선택) + `뒤로` / `다음`

> **사용자 지시 (2026-10-20): "여기 DEX도 해야 된다. 디자인은 이미 작업돼 있는 걸로 안다."**
> Figma Hub 계산기(④ 문서 1-3)가 이 화면을 대체하는 것으로 보이나, **두 화면의 형태가 다릅니다** (아래 참조).

#### 현재 화면 구성

| 요소 | 값 |
|---|---|
| 질문 | `먼저, 가장 자주 사용하는 거래소는 어디인가요?` |

#### 🔴 조치 1 — DEX를 선택지에 넣습니다

A-08 기준으로 **포함**입니다. 계산기 입력은 "돈을 받는 목적지"가 아니라 **자격·조회 영역**입니다.

#### 🔴 조치 2 — 결과 화면이 DEX에서는 달라져야 합니다

이게 더 큰 작업입니다. 현행 계산기는 **"테더맥스에서 얼마를 받는다"**를 전제로 합니다. DEX는 **DEX가 직접 지급**합니다.

| 항목 | CEX | DEX |
|---|---|---|
| 지급 주체 | 테더맥스 | **DEX** |
| 지급처 | 테더맥스 잔액 | **내 DEX 계정** |
| 최소 출금액 | 10 USDT | **없음** |
| 매칭 리워드 | 있음 | **없음** (A-09) |

Figma Hub 계산기는 이걸 **`Paid into your Lighter account`** 한 줄로 처리하고 있습니다 (④ 문서 1-3). **실물 계산기에도 같은 처리가 필요합니다.**

#### 🟠 조치 3 — 거래소 목록이 네 번째로 다릅니다

④에서 Figma의 로고 그리드(16)와 비교표(16)가 **구성이 6개씩 다르다**고 지적했는데, **실물 계산기는 또 다른 12곳**입니다.

| 목록 | 수 | 비고 |
|---|---:|---|
| 실물 계산기 | **12** | 두 Figma 목록에서 섞여 있음 |
| Figma 로고 그리드 | 16 | |
| Figma 비교표 | 16 | 그리드와 6개씩 다름 |
| Figma 비교표 제목 | **23** | `across 23 partners` |
| PRD 본문 | **17** | CEX 수 |

**다섯 개 숫자가 전부 다릅니다.** `NFR 11`은 "파트너 수를 게시된 레코드에서 계산하고 마크업에 숫자를 적지 않는다"고 규정합니다. **이 화면도 레코드 기반으로 생성되어야 합니다.**

12곳이 전체인지, 페이지네이션된 일부인지 확인이 필요합니다.

#### 🟠 조치 4 — 용어가 다릅니다

| 화면 | 표기 |
|---|---|
| 실물 계산기 | **`최종 페이백률`** |
| Figma 비교표 | `Final Taker` / `Final Maker` (**두 개로 분리**) |
| Figma 계산기 | `Cashback, 20%` |

**셋이 같은 값인지 다른 값인지 불명확합니다.** 실물의 `최종 페이백률 100%`(WOO X Pro)와 Figma 비교표의 최고값 85%(Bitunix)가 맞지 않습니다. 1-6(용어 중복)·1-7(공식 용어)과 함께 정리해야 합니다.

#### ⚠️ 확인 필요 — 두 화면의 관계

| | 실물 계산기 | Figma Hub 계산기 |
|---|---|---|

**Figma가 이 화면을 대체하는 것인지, 둘 다 유지되는 것인지 확인이 필요합니다.** 대체라면 이 화면의 DEX 작업은 불필요하고, 병존이라면 **양쪽 다** 작업해야 합니다.

## 3. DEX 랜딩 페이지

### 3-1. 🔴 히어로 리드 문구

**현재:** `No KYC checks. Connect a wallet, and start trading!`

**문제:** 문서 전체가 "지갑 연결을 절대 요구하지 않는다"를 반복 강조하는데, **사용자가 처음 보는 문장이 그것을 뒤집습니다.** 엣지케이스 문서도 미해결 항목 #16으로 올려놨습니다.

**수정안:** DEX에서 하는 일(지갑 연결, 거래)과 테더맥스에서 하는 일(주소 붙여넣기)을 문장으로 분리합니다.

### 3-2. 🟠 DEX 노출 순서가 4가지

| 위치 | 순서 |
|---|---|
| `DX-11` 요약 타일 | Lighter, Aster, EdgeX, ApeX |

## 4. DEX 상세 페이지 — 가장 많은 수정 필요

### 4-1. 🔴 계산기가 돈의 흐름을 반대로 설명

**현재 `VD-5` 흐름도**
```
You → Trading fee → {venue} → Partner settlement → TetherMax → "Cashback returned to you"
```

**현재 설명 카드**
> `TetherMax gives cashback` — TetherMax returns {cashback} to you, so your effective fee becomes {effective fee}.

**현재 `VD-6` 설명 서랍**
> 거래소가 테더맥스에 정산금을 지급하고 테더맥스가 대부분을 돌려준다

**같은 페이지의 FAQ(`VD-8`)는 정반대입니다.**
> Lighter pays your cashback in USDC **into your own Lighter account**, and you withdraw it on Lighter.

랜딩(`DX-3`, `DX-12`)도 "Paid by the DEX, into your account"입니다.

**영향:** 사용자가 테더맥스 잔액에 쌓인다고 믿고 출금하러 갔다가 찾지 못합니다. CS 문의와 신뢰 손상으로 직결됩니다.

**원인:** CEX 템플릿을 그대로 복사했습니다. 카피 수정이 아니라 **흐름도 구조 자체를 다시 설계**해야 합니다.

**수정안**
- 흐름도를 `You → Trading fee → {DEX} → {DEX}가 당신의 {DEX} 계정으로 지급` 구조로 변경
- 테더맥스를 "추적하고 보여주는 주체"로 표현
- `Partner settlement`라는 CEX 용어 제거
- 디스클레이머의 "exchange partner settlements"도 CEX 용어라 수정 필요

### 4-2. 🔴 단계별 가이드 기본 문구

**현재 `VD-7` 2단계 라벨:** `Deposit {currency} into your TetherMax wallet`

**문제:** 테더맥스에는 지갑이 없습니다. 사용자가 이 지시를 따를 방법이 없습니다.

**수정안:** "거래소나 지갑에서 {DEX}로 {currency} 전송"으로 변경. 백오피스에서 단계별로 운영자가 작성하는 구조이므로 기본값만 고치면 됩니다.

### 4-3. 🟠 계산기 거래량 범위

Hub(1K~250K)와 다릅니다. 2-3 참조.

### 4-4. 🟠 계정 등급 선택 UI 없음

`VD-5` 설명 카드가 `{account tier}`를 참조하는데, 사용자가 등급을 고르는 UI가 정의되지 않았습니다.

### 4-5. 🟠 안전 메시지 3종의 배치와 강제 방식

필수 안전 메시지 3개가 있습니다.
1. 12단어 복구 문구를 보관하고 아무에게도 공개하지 말 것
2. 잘못된 체인으로 전송하면 자금이 사라짐
3. 가입 후 DEX 안에서 추천코드를 확인할 것

**문제:** 자유 텍스트에서 탐지해 저장을 차단할지(`EDC-17`), 시스템 고정 문구로 넣을지(백오피스 엣지케이스) 두 안이 상충합니다. **다국어 자유 텍스트에서 메시지 존재를 탐지하는 것은 현실성이 낮습니다.**

**수정안:** 고정 문구를 시스템이 삽입하고 운영자는 위치만 지정합니다.

### 4-6. 🟠 EdgeX 헤드라인 요율 검증 방식

`VD-12`의 EdgeX "up to 30%"는 테더맥스 활성 코드 중 최고 `registrationRate`를 넘을 수 없습니다. 그런데 헤드라인이 자유 텍스트라 어떻게 비교하는지 정의가 없습니다.

### 4-8. 🟡 Aster Solana 언급

`VD-12` 상세 콘텐츠가 Aster의 Solana 지원을 언급하는데, 연동 검증은 EVM 전용입니다(`EXT-13`).

### 4-9. 🟡 리뷰 하위 점수 `Cashback withdrawal`

DEX는 출금이 DEX에서 일어나므로 테더맥스 평가 항목으로 성립하지 않습니다.

### 4-10. 🟡 수치 출처

`VD-12`의 수치가 서드파티 리뷰에서 가져온 것이라 파트너 확인이 필요합니다.

### 4-11. 🟡 미제작 에셋

EdgeX 배너, Step 4용 3D 렌더가 아직 없고, ApeX 칩은 줄여야 할 수 있습니다.

### 5-6. 🟠 마일스톤 진행바 — **DEX에서 제거** (등급 상향)

`WD-1`은 DEX 단독 회원에게도 렌더한다고 하고, `GW-2`는 비회원에게 숨긴다고 합니다. 원래 CEX 10 USDT 최소액 달성 UI인데 DEX에는 최소액이 없습니다.

**2026-10-20 확정 (A-18).** 마일스톤·VIP 진행바에서 **DEX를 제거합니다.**

VIP 게이지는 **TUID(계정)가 아니라 개별 UID 단위**로 산정됩니다. DEX UID는 이벤트 리워드를 받을 수 없으므로 등급을 매길 이유가 없습니다. 챌린지(A-13)는 "게이지는 DEX로도 찬다"로 정했지만 **VIP는 자격과 보상이 분리되지 않습니다.** 등급이 곧 요율이고 요율이 곧 이벤트 리워드이므로, 게이지를 채워도 줄 수 있는 것이 없습니다.

**DEX 단독 회원에게는 진행바 자체를 렌더하지 않습니다.** 채울 수도 없고 채워도 의미가 없습니다.

## 9. Cashback Summary / 랭킹 / Partner Hub

### 9-1. 🟠 랭킹 보상 규칙 부재

`RK-1`과 `LST-22`가 CEX UID와 DEX 지갑을 한 랭킹에 넣습니다. 그런데 **순위 보상 규칙이 없습니다.**

기존 페이백 랭킹은 순위별 10/20/50/100 USDT를 **이벤트 리워드로** 지급합니다. DEX 사용자는 받을 수단이 없습니다.

**확정 (A-11): DEX 지갑을 랭킹 대상에서 아예 제외합니다.** 표시에서도 빠집니다.

제가 처음에 적은 수정안("표시만 하고 보상은 없게 하거나, CEX만 보상 대상으로 명시")은 **채택되지 않았습니다.** 더 단순하게 끊었습니다.

**되돌려야 할 설계:** `RK-1`(CEX UID와 DEX 지갑을 한 랭킹에 표시), `LST-22`(어드민 랭킹에 DEX 포함, USDC 1:1 합산).
**`RK-2`(홈 `Linked Accounts` 카드)는 랭킹과 별개이므로 DEX를 유지합니다.**

### 9-2. 🟡 Cashback Type 필터 명칭

`CS-1`이 `Trading Cashback`을 `Exchange Cashback`으로 바꾸는 안을 제안합니다. 1-6과 함께 결정이 필요합니다.

### 9-3. 🟡 Partner Hub 표시 지표 오해 가능성

DEX 행을 표시하되 초대 리워드는 없다고 캡션으로 설명하는 구조입니다. **Partner가 "하위의 DEX 페이백에 대해 보수를 받는다"고 오해할 여지**가 있어 구분 표기를 강화할 필요가 있습니다.

### 9-4. 🟡 IF-5 배지 예시 산술 오류

"1 + 10 + 10 = 31"로 적혀 있는데 합이 21입니다. 거래소 4곳 기준이면 "1+10+10+10"일 것으로 추정됩니다.

### 9-5. 🔴 친구초대 — DEX 처리 (실물 화면 확인, A-19)

**화면:** `Point > 친구초대 > 초대 리워드`

| 영역 | 조치 | 담당 |
|---|---|---|
| **`거래소 UID 등록 현황` 목록** | **DEX 행을 추가합니다.** 거래소명·UID 등록 개수·누적 초대 리워드 모두 CEX와 동일하게 표시 | 개발 |
| **개수 배지** (현재 `18`) | **DEX를 포함해서 셉니다.** 포함하지 않으면 배지와 목록이 어긋납니다 | 개발 |
| **`누적 초대 리워드` 컬럼의 DEX 행** | **실제 금액을 표시합니다.** `-`나 `0 고정`이 아닙니다 | 개발 |
| 🔴 **출금 UID 선택 모달** (`Select a UID to withdraw referral rewards`) | **DEX 행을 렌더하지 않습니다.** ⚠️ **비활성(회색)이 아니라 아예 없는 것으로 처리** | 개발 + 디자인 |

#### 왜 비활성이 아니라 미렌더인가

| 방식 | 사용자가 읽는 의미 |
|---|---|
| 비활성(회색) | "지금은 못 고르지만 **조건을 맞추면 고를 수 있다**" |
| **미렌더 (채택)** | "이 목적지는 **존재하지 않는다**" |

DEX 지갑은 조건을 맞춰도 영원히 출금 계좌가 될 수 없습니다. 비활성으로 두면 **"왜 안 되지, 뭘 해야 되지"**가 CS 문의로 옵니다.

#### ⚠️ 디자인이 필요한 새 상태 — 선택지가 0개인 경우

**DEX 지갑만 연동한 사용자**는 출금 모달을 열어도 **선택지가 하나도 없습니다.** 현재 디자인에 이 상태가 없습니다.

빈 모달이 뜨면 사용자는 버그로 읽습니다. **"출금하려면 거래소 UID 연동이 필요합니다" + 연동 링크**가 필요합니다. (B-2-9)

DEX는 KYC가 없어 진입이 쉬우므로 **실제로 발생하는 상태**입니다.

#### 🟠 함께 확인할 것 — `0 USDT` vs `-`

현재 CEX 행도 `0 USDT`로 표시합니다. DEX 행에 금액을 표시하기로 했으므로 충돌은 없지만, **"아직 0"과 "해당 없음"을 구분할 표기가 전체적으로 없습니다.**

### 9-6. 🟠 파트너 허브 — DEX 처리 (실물 화면 확인, A-20)

**화면:** `파트너 허브` (대시보드 / 하위 계정)

| # | 영역 | 조치 |
|---|---|---|
| 1 | 대시보드 `출금하기` 모달 (`Confirm Withdrawal?`) | **작업 없음.** 출금 거래소·UID가 어드민 고정이라 A-01로 이미 차단됩니다 |
| 2 | 대시보드 `Exchange UIDs` 목록 | **DEX 행 추가.** 배지(`10`)와 `198 Total`도 DEX 포함해서 셉니다 |
| 3 | `하위 계정` > 회원 ID 클릭 모달 (`연동된 UID`) | **DEX UID 추가.** `1 UIDs` 개수도 포함 |

1번의 근거는 모달 하단 문구입니다.

> `To change the withdrawal exchange or UID for invitation rewards, please contact support.`

**사용자가 출금 거래소·UID를 고를 수 없습니다.** 어드민 제휴사 등록에서 지정한 값이 그대로 쓰이고, 그 등록 모달에서 이미 DEX를 뺐습니다. **다만 어드민 쪽 제외가 실제로 구현돼 있는지는 확인이 필요합니다.**

### 9-7. 🟠 파트너 허브 최소 출금액이 10과 50으로 갈립니다

| 위치 | 값 |
|---|---|
| 국문 대시보드 경고 | `최소 출금 금액 10 USDT` |
| 영문 `Terms & Conditions` | `Invite Rewards can only be withdrawn when the amount is **50 USDT** or more.` |

**같은 기능 안에서 다릅니다.** 파트너 초대 리워드의 최소액이 일반 페이백 출금(10 USDT)과 다른 것인지, 둘 중 하나가 낡은 것인지 확인이 필요합니다. (`D-21`)

DEX와 직접 관련은 없지만 **같은 화면을 손볼 때 함께 고치는 게 좋습니다.**

## 10. 혜택 / 퀴즈

### 10-1. 🟠 혜택 페이지 상단 금액이 상시 0

혜택 페이지 상단이 회원에게 **이벤트 리워드 총합**을 보여줍니다. DEX 전용 사용자는 **상시 0 USDT**가 노출되어 비회원 화면과 같아집니다.

**참고:** 비회원에게는 금액 영역 자체를 제거한 선례가 있습니다. 같은 패턴을 적용할 수 있습니다.

### 10-2. 🟠 퀴즈 보상 표시

DEX 교육 모듈 2개는 보상이 없습니다(`LE-9`, `LE-10`). 그런데 `LE-1`이 기존 카드와 "구조가 동일"해야 한다고 합니다. **기존 3개 모듈에 보상 표시가 있다면 사용자가 보상을 기대합니다.**

`LE-11`이 결번인 것도 보상 관련 행을 삭제한 흔적으로 보입니다.

**수정안:** DEX 카드에서 보상 영역을 숨기고 결과 화면에도 보상 문구를 넣지 않습니다.

### 10-3. 🟠 퀴즈 거래소 지정 사전 차단

기존 퀴즈는 **참여와 쿠폰 수령이 거래소 계정 없이도 가능**하지만, 쿠폰 **사용**은 지정 거래소 UID가 필수이고 결과가 이벤트 리워드입니다. **DEX를 지정 거래소로 설정하면 쿠폰을 쓸 대상이 없습니다.**

게다가 `Exchange` 필드는 **등록 후 수정 불가**라 되돌릴 수 없습니다.

**수정안:** 백오피스에서 퀴즈 거래소 선택 시 DEX를 사전 차단합니다.

### 10-4. 🟡 퀴즈 콘텐츠 부재

본문·문항·보기·해설이 PRD에 없습니다. **정답 위치만 있습니다** ("모듈 4는 Q1 2번, Q2 3번"). 콘텐츠 제작을 별도 작업으로 분리해야 합니다.

### 10-5. 🟡 퀴즈 완료 기준 미정

제출만 하면 완료인지 2/2여야 하는지, 재응시 가능 여부, 완료 후 버튼 상태가 정의되지 않았습니다.

### 10-6. 🟡 3 USDT 쿠폰 배지

S3 홈 체크리스트의 "Link your wallet with us" 옆에 3 USDT 배지가 붙어 있습니다. **DEX 지갑만 연동한 사용자는 이 쿠폰을 받을 수 없습니다** (기존 쿠폰 규칙이 "연동 완료 UID 1개 이상 필수"). `RT-4`의 "DEX 패널에서 보상을 약속하지 말 것"과도 취지가 충돌합니다.

**확정 (A-14): 배지를 유지하고 안내 문구를 답니다.** 쿠폰은 **받을 수 있지만 DEX에서는 쓸 수 없습니다.** 쿠폰함에 **"CEX UID 연동 시 사용 가능"**을 명시합니다. 리뷰 보상 쿠폰(A-17)도 동일합니다.

## 11. 백오피스

### 11-1. 🔴 Spending Estimate 소수점 제한 버그

`SPE-6`이 요율 입력을 소수 3자리까지만 허용하는데, 같은 문서의 예시 `SPE-7`이 0.05% = **0.0005**(소수 4자리)입니다. Lighter 요율 테이블은 4자리를 허용합니다.

**구현하면 예시 값조차 입력할 수 없습니다.**

**수정안:** 소수 4자리로 변경.

### 11-2. 🟠 Aster 연동 섹션 없음

Lighter(`EXT-18`), ApeX(`EXT-19`), EdgeX(`EXT-20`)는 전용 섹션이 있는데 **Aster만 없습니다.** 365일 바인딩, usdtValue, 웹훅 설정을 관리할 화면이 없습니다.

### 11-3. 🟠 지갑 한도 설정·조회 화면 없음

프론트는 "3 × 활성 DEX 수, 전체 합산"으로 명시돼 있는데 백오피스에 **설정 위치, 회원별 사용량 조회, 예외 처리가 전혀 없습니다.**

### 11-4. 🟠 Preview / Draft 없음

다국어 대량 작성인데 **저장이 곧 라이브**입니다. 배너 미리보기만 있습니다. DEX 1곳당 운영자 입력 필드가 약 100개 + 미디어 26개입니다.

### 11-5. 🟡 `EDC-14` 헤딩 오류

헤딩이 "Min & Max **Fees**"인데 필드는 Volume입니다.

### 11-6. 🟡 Line 2 길이 제한 — **랜딩 10자는 정상. 상세 4자만 남음**

랜딩 10자, 상세 Right Box 4자입니다.

**Figma 대조 결과 랜딩 10자는 적절합니다.** 디자인이 `Up to` / `20%` / `trading fees rebate` 3토막 구조이고, **Line 2는 `20%` 같은 요율 표기용**이기 때문입니다 (13-13 참조). 처음에 "같은 헤드라인인데 제한이 다르다"고 적었는데 **같은 헤드라인이 아닙니다.**

**남은 문제는 상세 Right Box의 4자**입니다. 무엇을 넣으라는 칸인지 확인이 필요합니다.

### 11-7. 🟡 저장 모델 혼재

DEX 리스트와 브로커 리스트는 마우스를 놓는 즉시 저장, Edit Display Priority는 Edit/Save/Cancel입니다. 즉시 저장은 키보드 대안(`NFR-8`)과도 충돌할 수 있습니다.

### 11-8. 🟡 `Execution Modal` 오타

브로커 비교 에디터 라벨입니다. 문서 자체가 `Execution Model`로 수정하라고 지시합니다.

#### ⬜ 미정 — CEX / DEX 구분 방식 (사용자 지시로 미정 유지)

| 안 | 내용 |
|---|---|

| 부제 | — | `지갑 연결이나 서명이 필요 없습니다` 추가 |

**DEX 선택 시 다음 단계 화면 자체가 분기**해야 합니다. 같은 입력 필드를 재사용할 수 없습니다.

#### 🟠 조치 3 — `여기서 가입하세요` 링크의 목적지

### 14-3. 🟠 비회원 홈 실시간 출금 목록 — DEX 표시 시 컬럼 3개가 성립하지 않습니다

**화면:** 비회원 홈 `지금 이 순간에도 누군가는 페이백을 받고 있어요`
**현재 컬럼:** `UID` / `거래소` / `페이백` / `출금 시각` / `상태`

DEX 건도 이 목록에 나와야 하는데, **5개 컬럼 중 3개가 DEX에서 뜻이 달라집니다.**

| 컬럼 | CEX | DEX | 조치 |
|---|---|---|---|
| **`UID`** | 거래소 UID 마스킹 (`*****6974`) | **UID가 없음.** 지갑 주소뿐 | 🔴 헤더를 중립어로 (`UID / 지갑` 또는 `계정`). 지갑은 `0x7a3F…51e9` 형식 마스킹 |
| `거래소` | 로고 | 동일 | — |
| `페이백` | 금액 | 동일 (USDT 환산) | — |
| **`출금 시각`** | 테더맥스가 송금한 시각 | **테더맥스는 DEX 출금을 볼 수 없음.** 알 수 있는 건 `DEX가 지급 완료한 시각`뿐 | 🟠 DEX 행은 `지급 시각` 의미로 채우고 헤더를 중립어로 |
| **`상태 = 완료`** | 테더맥스 출금 완료 | **DEX 지급 완료**. 고객이 실제로 뺐는지는 모름 | 🟠 같은 `완료`를 쓰되 의미가 다름을 툴팁·각주로 구분하거나 DEX 전용 상태값 정의 |

> 섹션 제목 `지금 이 순간에도 누군가는 페이백을 받고 있어요`와 부제 `쌓인 페이백을 한 푼도 빠짐없이 받아가세요`는 **DEX에 더 잘 맞습니다** (DEX는 자동 지급이라 실제로 받아가고 있음). 제목 수정은 불필요합니다.

**데이터 가용성 확인 필요:** Lighter는 주 1회 CSV 확정이라 이 목록에 **월요일에만** 행이 생깁니다. 실시간성이 DEX마다 다르다는 점을 디자인에 반영해야 합니다 (Lighter 주간 / EdgeX·Aster 일간 / ApeX 시간당).

### 14-4. 🔴 출금하기 모달 — DEX 추가 필요 (분리/통합 미정)

**화면:** `출금하기` 모달 (회원)

| 요소 | 현재 값 |
|---|---|
| 상단 | `출금 가능 페이백` `0.00 USDT` |
| UID 카드 | 거래소 로고 + 이름 + `UID 99925851` + `출금 불가` 칩 |
| 카드 경고 | `거래소 페이백을 5.00 USDT 더 받으면 출금할 수 있어요` |
| 카드 내역 | `거래소 페이백` 0.00 / `이벤트 리워드` 5.00 |
| 하단 경고 | `출금 가능한 UID가 없습니다` |
| 버튼 | `출금하기` (비활성) |

**기존 출금 정책:** 출금 가능한 UID들의 **최대 출금 가능 금액을 일괄 출금 요청** (부분 출금 없음).

#### ⬜ 미정 — DEX를 탭으로 분리할지, CEX와 통합할지 (사용자 지시로 미정 유지)

#### 🔴 통합 시 깨지는 것 4가지

| # | 요소 | 문제 |
|---|---|---|
| 1 | **`출금 가능 페이백` 합계** | DEX 금액은 **출금 가능 금액이 아니라 이미 받은 금액**입니다. 합산하면 "출금 가능 100인데 버튼 누르면 40만 나감"이 됩니다. [04 문서 165줄](04_부가서비스_DEX연동_가능여부.md)의 지적과 같은 뿌리 — "테더맥스가 줄 돈"과 "DEX가 이미 준 돈"을 한 숫자로 합치면 안 됩니다 |
| 2 | **`이벤트 리워드` 행** | DEX는 이벤트 리워드가 발생하지 않습니다 (A-09). 행 자체를 숨길지 `-`로 둘지 결정 필요 |
| 3 | **`거래소 페이백을 N USDT 더 받으면 출금할 수 있어요`** | DEX는 **최소 출금액이 없습니다.** 이 문구가 DEX 카드에 뜨면 거짓입니다 |
| 4 | **`출금 가능한 UID가 없습니다`** | DEX만 연동한 사용자는 **영구히 이 경고를 봅니다.** 정상 상태인데 오류처럼 보입니다 |

#### 🔴 추가 — `출금하기` 버튼의 동작이 DEX에서 성립하지 않습니다

기존 정책은 "출금 가능한 UID들의 최대 금액을 일괄 요청"입니다. **DEX는 출금 요청 자체가 없고**, 카드마다 `{DEX}로 이동`하는 개별 동작만 있습니다. 일괄 버튼 하나로 묶을 수 없습니다.

```
CEX  [출금하기] ──▶ 선택된 UID 전부 일괄 출금 요청 (1회 동작)
DEX  [EdgeX로 이동] [ApeX로 이동] … ──▶ DEX별 새 탭 (개별 동작, N회)
```

#### 참고 — 분리안이 안전한 이유

통합하면 상단 `출금 가능 페이백` 숫자의 정의가 깨집니다(위 1번). 분리하면 "테더맥스에서 꺼내는 돈"과 "DEX에서 이미 받은 돈"이 섞이지 않습니다. **다만 결정은 미정으로 둡니다.**

**연관 항목:** 1-1(`Available Cashback` 명칭), 1-2(Total Claimed 제거), 6-1(`Withdraw on {DEX}` 노출 조건), [03 B-1-4·B-6-7](03_정책_결정_기록.md)

### 14-5. 🔴 페이백 요약(페이백 내역) — DEX 추가 필요, 유형 필터 2개가 성립하지 않음

**화면:** `페이백 요약` — 좌측 필터 3종 + 우측 월 캘린더 + 선택일 내역 목록

| 요소 | 현재 값 |
|---|---|
| 필터 1 | `모든 거래소` → `WOO X Pro (1 UID)` |
| 필터 2 | `모든 UID` |
| 필터 3 | `모든 페이백 유형` → `페이백` / `이벤트 리워드` / `출금 금액` (체크박스 다중) |
| 버튼 | `재설정` / `검색` |
| 캘린더 | 월 단위, 날짜 아래 일별 합계 (`+5.00`) |
| 목록 | `쿠폰 사용` + 거래소명 + UID + `+5 USDT` |

#### 🔴 조치 1 — 거래소 필터와 내역 목록에 DEX를 넣습니다

현재 DEX 건이 **조회 자체가 안 됩니다.** 드롭다운 표기 `WOO X Pro (1 UID)`는 DEX에서 성립하지 않습니다 — UID가 없으므로 `(지갑 1개)` 등 중립 표기가 필요합니다. 14-3의 `UID` 컬럼 건과 같은 뿌리입니다.

#### 🔴 조치 2 — 유형 필터 4개 중 **2개**가 DEX에서 성립하지 않습니다

사용자 지시는 `이벤트 리워드` 1개였으나, **`출금 금액`도 같은 이유로 성립하지 않습니다.**

| 유형 | DEX | 이유 |
|---|---|---|
| `페이백` | ✅ 있음 | 단 "DEX가 지급한 금액"이라 의미가 다름 |
| `이벤트 리워드` | **❌ 없음** | A-09 전면 배제 |
| `출금 금액` | **❌ 없음** | 테더맥스를 통한 출금이 없음. 기록될 건이 0 |

→ **DEX만 선택하면 유효한 유형이 `페이백` 하나만 남습니다.** 필터 자체를 숨길지, 비활성 상태로 둘지 결정이 필요합니다 (B-7-20).

**다중 선택이므로 규칙을 명시해야 합니다.** CEX와 DEX를 함께 선택한 경우에는 `이벤트 리워드`·`출금 금액`이 유효합니다(CEX 때문). **선택된 거래소가 전부 DEX일 때만** 숨기거나 비활성화합니다.

#### 🟠 조치 3 — 캘린더 일별 합계의 의미가 섞입니다

캘린더 날짜 아래 `+5.00`은 CEX에서 **"테더맥스 잔액이 그날 늘어난 금액"**입니다. DEX 금액을 더하면 **"DEX가 내 계정에 넣어준 금액"**이 섞여 들어갑니다. 1-1(`Available Cashback` 명칭)·5-1(DEX Cashback Balance 정의)과 같은 뿌리입니다.

#### ⚠️ 확인 필요 1 — 날짜 경계가 UTC와 KST로 갈립니다

DEX 레코드는 **UTC 일 기준**입니다 (EdgeX 00:00 UTC, Aster 09:00 UTC 공개). 캘린더가 KST라면 **하루가 밀려서 찍힙니다.** 1-8(시간대 표기 통일)·[03 B-6-4](03_정책_결정_기록.md)와 함께 결정해야 합니다.

#### ⚠️ 확인 필요 2 — Lighter는 캘린더에 월요일만 찍힙니다

주 1회 정산이라 **한 달에 4~5칸만 금액이 있고 나머지는 공백**입니다. 사용자가 "적립이 안 됐나" 오해할 수 있어, 주간 정산 DEX임을 알리는 표시가 필요합니다.

#### ✅ `거래소 이벤트`(exchange type) — 기존 결정과 일치

#### 🔴 `테더맥스 전용 이벤트`(with type) — **기존 결정과 정면 충돌**
