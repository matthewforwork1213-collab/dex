> 이 문서가 기준 문서다(통합본 없음, 2026-10-01 정리).
> **수록 범위**: 사용자 화면 전용 요구사항(FR) + 시스템 로직(SYS) + 알림(NTF). SYS·NTF는 화면이 없는 공통 로직이라 **사용자·백오피스 문서에 같은 내용으로 중복 수록**한다. 백오피스 전용 요구사항은 `분할문서/백오피스/요구사항정의서_ko.md`에 있다.
> **ID 규칙**: REQ 번호는 분할 전 통합 번호를 그대로 쓴다(번호가 건너뛰는 것은 다른 파트 요구사항이다).
> **구분**: FR = 사용자 화면(프론트), AD = 어드민(백오피스), SYS = 시스템 로직(배치·판정·지급), NTF = 알림.
> 모든 기간·날짜 판정은 **UTC 기준**, 리워드는 **USDT**. 사용자 화면의 날짜·시각은 UTC 값을 **사용자 기기의 로컬 시간으로 변환해 표시**한다(NFR-011).
> **구현 기준(확정 2026-10-12)**: 목업 기본 화면(V2, 이벤트형 디자인)의 **화면 배치** + 이 문서의 **규칙**. V2는 배치(디자인)만 바꾼 것이며 문구·정책은 문서가 우선한다. 목업에서 문서 규칙과 다른 부분(상단 보조 문구, 영문 payback 표기, 일정 기본 펼침 등)은 구현하지 않는다.
> **"(백오피스 요구사항정의서 참조)"** 표시가 붙은 REQ 번호는 이 문서에 없고 `분할문서/백오피스/요구사항정의서_ko.md`에 있다.

**용어 (확정 2026-10-12)**

| 용어 | 정의 |
|------|------|
| 달성 | 줄 완성(빙고 리워드)·빙고판 완성(완성 리워드)·랭킹 순위 안에 든 상태. **받을 예정**일 뿐 돈은 아직 나가지 않았다. 사용자 화면 내 리워드의 금액(배지 "받을 예정" / "집계 중" / "확정")은 달성 기준 금액이다 |
| 지급(적립) | 지급 기간 시작 시 확정된 리워드를 참여 UID로 지급되는 금액에 실제로 적립하는 것. 리워드는 지급 기간 시작 때 최종 상태 기준으로 한 번만 지급된다. 사용자 화면 문구는 "지급", 시스템 처리 이름은 "적립"이며 같은 뜻이다 |
| 참여 UID를 잃음 | 사용자는 UID를 직접 연동 해제할 수 없다. 참여 UID가 끊기는 원인은 **소유권 이전**(다른 사람이 소유권 인증으로 가져감)과 **이슈 UID 지정** 두 가지다(탈퇴는 별도 상태). 판정 시각은 테더맥스 계정 DB 이력의 시각이다 |
| 초기화 (`RESET`) | 참여 기간 중 참여 UID를 잃은 경우. 그 빙고판에서 **처음 온 사람처럼** 된다(체크 칸·줄·완성·랭킹·달성 리워드 전부 사라짐). 새 UID를 선택할 수 있고 새 UID는 자기 게이지로 시작한다. 사유 `OWNERSHIP_TRANSFER` / `ISSUE_UID` |
| 소멸 (`FORFEITED`) | 집계 시작 이후~지급 전에 참여 UID를 잃은 경우. 리워드 없음, 빙고판 완성자면 랭킹 자리 비움. 사유 `OWNERSHIP_TRANSFER` / `ISSUE_UID` |
| 지급 후 UID 변경 | 지급(적립) 이후 소유권 이전·이슈 UID 지정. 이미 지급된 금액은 회수하지 않으며, 원 TUID의 참여 상태·지급 금액은 바꾸지 않고 이력만 남긴다 |

## 1. 기능 요구사항 (Functional Requirements)

### 1.3 참여 자격·참여 UID

| ID | 구분 | 요구사항 | 우선순위 | 인수 기준 |
|----|------|----------|----------|-----------|
| REQ-022 | SYS | 참여 자격은 TUID가 아니라 UID 기준으로 판정한다. | Must | TUID 가입 시점은 판정에 쓰지 않음 |
| REQ-023 | SYS | 참여 시작일 30일 전부터 테더맥스 DB에 등록된 UID만 참여할 수 있다. | Must | 참여 기간 중에 새로 등록된 UID도 참여 가능. UTC 날짜 기준. 기준일은 **테더맥스 DB 최초 등록일**(재연동해도 바뀌지 않음) |
| REQ-024 | SYS | 같은 빙고판에 참여 기록이 한 번이라도 있는 UID는 그 빙고판에 다시 참여할 수 없다. | Must | 소유권 이전으로 다른 TUID에 넘어간 경우, 원 TUID로 다시 돌아온 경우, 이슈 UID 지정이 풀린 경우 모두 재참여 불가(진행 복원 없음). 다른 빙고판에는 제한 없음 |
| REQ-025 | SYS | 참여 기록은 사용자가 UID를 참여 UID로 등록(선택)한 시점에 생긴다. | Must | 게이지 자동 적립만으로는 참여 기록이 생기지 않음 |
| REQ-026 | FR | 빙고판의 대상 거래소 UID만 참여 UID로 등록할 수 있다. | Must | 다른 거래소 UID는 선택 목록에 나오지 않음 |
| REQ-027 | FR | 한 TUID는 빙고판마다 한 번에 1개의 UID로 참여한다. | Must | 거래소가 다른 빙고판은 각각 UID 1개씩 참여 가능 |
| REQ-028 | FR | 참여 UID 등록 전에 확인 팝업 "등록 후에는 변경할 수 없어요."(EN "You can't change it after registration.")를 보여준다. | Must | 확인해야 등록됨. 선택 화면에는 자격 UID 목록만 표시(UID별 게이지 미표시). 초기화 후 새 UID를 고를 때 팝업 문구는 "새 UID를 선택하면 이 빙고판의 진행이 처음부터 다시 시작돼요. 등록 후에는 변경할 수 없어요."(EN "If you select a new UID, your progress on this board starts over. You can't change it after registration.") (확정 2026-10-12) |
| REQ-029 | FR | 참여 UID는 사용자가 임의로 바꿀 수 없다. | Must | 변경 메뉴 없음. 사용자가 참여 UID를 끊는 기능도 없음(참여 UID를 잃는 원인은 소유권 이전·이슈 UID 지정뿐, 확정 2026-10-12) |
| REQ-030 | FR | 참여 UID를 잃은 사용자(소유권 이전·이슈 UID 지정)에게 혜택 상세 맨 위 안내 영역으로 알리고, 참여 기간이면 새 UID를 선택하게 한다. | Must | 팝업이 아니며 그 상태인 동안 상세에 들어올 때마다 표시. 제목 "참여 중이던 UID로 더 이상 참여할 수 없어요"(EN "You Can No Longer Participate with This UID") + 본문 "이 UID로는 이 빙고판에 다시 참여할 수 없어요."(EN "This UID can no longer join this board."). 원인별 제목·사유 구분 없음. 안내 아래는 처음 참여하는 사람과 같음: 참여 기간 + 고를 자격 UID 있음 → [새 UID 선택하기] → UID 선택 레이어, 고를 자격 UID 없음 → "참여할 수 있는 {거래소} UID가 없어요. 새 UID를 연동하면 다시 참여할 수 있어요." + [UID 연동하기](선택 레이어 열지 않음). 참여 기간 이후는 버튼 없이 안내만. 집계·결과 발표 단계에는 "이벤트 리워드는 지급되지 않아요"를 함께 표시, 지급 기간에는 이 문장을 쓰지 않음(이미 지급됐을 수 있음). 새 UID를 고르면 그 빙고판에서 처음 온 사람처럼 시작(칸·줄·완성·랭킹·달성 리워드 없음, 새 UID 게이지·연속 기록은 그 UID 이력으로 소급). 새 UID도 자격 조건 충족 필요 (확정 2026-10-12) |
