> 이 문서가 기준 문서다(통합본 없음, 2026-10-01 정리).
> **범위**: 사용자 화면에서 보여주고 입력받는 것. 서버 판정·저장·배치는 `기능명세_백엔드_ko.md`에 있다.
> F-ID는 분할 전 통합 번호를 그대로 쓴다. 같은 F-ID가 백엔드 문서에도 있으며, 프론트는 화면, 백엔드는 서버 처리를 다룬다.
> **[잠정]** 표시는 아직 기획 확정 전인 항목이다. 확정되면 이 문서를 고친다.
> **구현 기준(확정 2026-10-12)**: 배포 목업 `src/mockup/index.html`의 **기본 화면(V2, 이벤트형 디자인)의 화면 배치** + **이 문서의 규칙**이다. V2는 배치(디자인)만 바꾼 것이며 **문구·정책은 이 문서가 우선**한다. V2의 배치 요소(히어로, 참여 영역, 섹션 이동 탭, 빙고 미션 영역·HOW TO PLAY, 02 / REWARDS)는 F-002 "화면 구성"과 정보구조도 1.4에 적었다. V2에서 문서 규칙과 다른 부분(상단 "TETHERMAX × 거래소 / PAYBACK EVENT" 보조 문구, 영문 payback·Maxboard 표기, 전체 일정 기본 펼침·시각 미표시, 카운트다운 아래 마감 일시 숨김, 사전공개 이름 "사전 공개 / Preview")은 **구현하지 않고** 이 문서를 따른다. 기본 화면의 설정(칸 구성 "혼합", 빙고판 색 "기본", 서비스명 "맥스보드")이 기준이며, 목업의 시나리오 패널(단계·사용자·폭 전환 등), V1 비교 화면(`?ui=v1`), 개선안, 칸 구성·빙고판 색·대비 보정·서비스명 토글은 **비교·시연용이며 구현 대상이 아니다**. 칸 구성(금액 칸만/연속 칸만) 표시는 실제 빙고판 구성에 따라 자동으로 적용한다(F-006).
> **미정 항목 개발 기본값(2026-10-07)**: 확정 전까지 아래 값으로 개발하고, 확정되면 이 문서를 고친다. 서비스명 = 맥스보드 / MAX BOARD(#NAME), 빙고판 배경색 = TetherMax 기본 파랑 고정·백오피스 입력 없음(색 변경 기능 검토 중, #COLOR), 혜택 상세 상단 큰 제목 = 어드민 입력 제목(`<br />` 줄바꿈 적용, #TITLE), 빙고 Batch 실행 시각 = 설정값(예시 12:30 UTC, #BATCH), SEO 중국어 간체 = 미지원(#SC), 배너 외 추가 이미지 = 없음(배너는 혜택 목록 카드 전용, #IMG). "오늘 마감"은 기기 로컬 날짜 기준(확정 2026-10-07).

## 2. 공통 규칙

| 항목 | 규칙 | 근거 |
|------|------|------|
| 시간 | API의 모든 일시는 UTC. 다음 업데이트 시각과 마지막 갱신 시각은 사용자 화면 어디에도 표시하지 않는다(확정 2026-10-02, 마지막 갱신 시각 확정 2026-10-12). 화면의 날짜·시각(단계별 기간, 참여 시작 일시, 자격 기준 일시, 지급 예정일, 이력 시각 등)은 **사용자 기기의 로컬 시간으로 변환해 표시**하고 "UTC"를 붙이지 않는다. 변환은 프론트가 한다. 판정(단계 전환, 참여 가능 여부 등)은 서버의 UTC 값을 그대로 따른다. 예외: 공통 유의사항 문구는 UTC 기준 안내("모든 기간과 시각은 UTC 기준입니다")를 유지한다(판정 기준 안내) | NFR-011 (확정 2026-10-02) |
| 기간 표기 | 단계 기간은 API의 `startAt` ~ `endAt`(= 시작일 00:00:00 UTC ~ 종료일 23:59:59 UTC)을 기기 로컬 시간으로 변환해 **날짜와 시각을 함께** 표시한다(로컬 날짜가 UTC 날짜와 어긋나기 때문). `startDate`·`endDate`만 쓰는 곳은 경계 시각(00:00:00 / 23:59:59 UTC)을 붙여 변환한다. 예: 참여 10-08 ~ 10-21(UTC) → KST 기기에서 "2026.10.08 09:00 ~ 2026.10.22 08:59" | API스펙 1.1, 1.5 |
| 금액 | API 금액은 소수점 둘째 자리 10진 문자열(`"12.50"`). 숫자(부동소수점)로 바꿔 계산하지 말고 문자열로 표시한다. 단위는 USDT. 표기 규칙(확정 2026-10-12): **어드민 설정 금액**(칸 목표 금액, 줄·완성 리워드, 랭킹 구간 금액, 히어로 "빙고 리워드 최대" 합계, 총 랭킹 리워드)은 소수부 끝의 불필요한 0을 지워 표시(`"3.00"` → "3", `"2.50"` → "2.5", 예: "+3 USDT", "2.5 USDT"). **계산 값**(빙고 게이지, 내 리워드 금액·합계, 총 페이백)은 둘째 자리 그대로 표시(예: "12.50 USDT") | API스펙 1.1, REQ-129 |
| 에러 문구 | API `error.message`는 개발용이다. 사용자 문구는 `error.code`로 i18n 리소스에서 고른다 | NFR-009 |
| 언어 | 제목·부제목·OG는 KO면 KO, 그 외 언어는 EN. `lang` 쿼리는 언어별 내용이 있는 API-001·002에만 보낸다(API-003~007은 보내지 않음) | REQ-085 |
| 용어 | 리워드, 빙고(가로/세로), 빙고 리워드, 빙고판 완성, 완성 리워드, 칸 체크, 빙고 게이지, N일 연속 페이백, 랭킹 리워드. 영문은 페이백을 **Cashback**으로, 서비스명을 **MAX BOARD**로 쓴다(payback·Maxboard 표기 금지). 집계 단계 표기는 KO "집계 중", EN "Calculating"(언어팩 "계산 중"은 쓰지 않음, 확정 2026-10-02). 단계 이름(사용자 화면): 오픈 예정 / 참여 기간 / 결과 집계 / 결과 발표 / 리워드 지급(EN Pre-launch / Participation / Calculating / Results / Reward Distribution, Participation은 언어팩 검토 필요. "사전 공개 / Preview"는 쓰지 않음). 참여 마감까지 / 오늘 마감(EN Ends in / Ends Today). 카운트다운 단위 일 / 시간 / 분 / 초(EN Days / Hrs / Mins / Secs). 체크 가능한 최대 칸(EN Max Cells to Check). 순차적으로 지급 중(EN Paying Out Sequentially) (확정 2026-10-05~06). 내부 용어("보상", "줄 달성")는 화면에 쓰지 않는다. 영문 대응: 리워드 Reward, 빙고(가로/세로) Bingo (Row / Column Bingo), 빙고 리워드 Bingo Reward, 빙고판 완성 Full Board, 완성 리워드 Full Board Reward, 칸 체크 Check, 빙고 게이지 Bingo Gauge, N일 연속 페이백 N-Day Cashback Streak, 랭킹 리워드 Ranking Reward, 이벤트 리워드 Event Reward, 유의사항 Notes. 문장 톤은 테더맥스 언어팩을 따른다(정리: `05.리포트/맥스보드_문구_톤가이드.md`). **달성과 지급(적립)**(확정 2026-10-12): 달성 = 줄 완성·빙고판 완성(·랭킹 순위 안에 듦)으로 리워드를 **받을 예정**인 상태(돈은 아직 나가지 않음, 내 리워드 배지 "받을 예정" / "집계 중" / "확정"), 지급(적립) = 지급 기간 시작 시 확정 리워드를 참여 UID로 **실제 지급**하는 것(화면 문구는 "지급", 시스템 처리 이름은 "적립", 같은 뜻). 참여 UID를 잃어 초기화되면 그 빙고판의 달성 리워드도 모두 사라진다(F-005) | REQ-083, 요구사항정의서 "용어" |
| 줄바꿈 | 제목·부제목에 `<br />`·`<br/>`·`<br>`(대소문자 무관)이 있으면 **줄바꿈으로 표시**한다(혜택 목록 카드, 혜택 상세 모두). SEO 타이틀·디스크립션과 OG에는 적용하지 않는다. `<br />` 외 HTML 태그는 실행하지 않고 문자 그대로 표시한다(보안). 글자 수 제한이 없으므로 긴 문구도 레이아웃이 깨지지 않게 줄바꿈 처리 | REQ-107 |
| 랭킹 OFF | `rankingEnabled=false`면 랭킹 안내 영역, 리더보드, 결과 발표 단계를 **그리지 않는다**(API 응답에도 `ranking` 키와 `ANNOUNCEMENT` 단계가 없다) | REQ-082, NFR-008 |

- **사전공개 자격 표시**(확정 2026-10-05): 사전공개 단계에도 로그인 사용자의 현재 연동 UID로 자격을 조회해 결과를 보여준다(30일 기준은 참여 시작일로 계산하므로 시작 후에도 같은 결과. 소유권 이전·이슈 UID 지정 등 이후 변화는 참여 기간에 다시 판정). API-003은 사전공개에도 `state`·`eligibleUids`를 판정해 주며 `actions.canRegister`는 `false`다. 사전공개에는 [UID 연동하기] 버튼을 두지 않고 안내 문구만 보여주며, 버튼은 모든 사용자에게 비활성 "○○ 오픈 예정"(○○ = 참여 시작 일시, 로컬 시간, EN "Opens on ○○")이다(확정 2026-10-12).
- **참여 기간 이후 미참여자 화면**(확정 2026-10-02): 결과 발표·지급 기간에 참여 UID를 등록하지 않은 사용자(비회원 포함. GUEST·NO_ELIGIBLE_UID·NOT_REGISTERED 모두 같은 화면)에게는 "참여 기간이 끝났어요"(EN "The Participation Period Has Ended") 안내와 비활성 버튼 "참여 기간 종료"(EN "Participation Ended")를 보여준다. 로그인 유도·참여 CTA·지급 안내는 보여주지 않는다. 랭킹 ON이면 "최종 순위를 확인해보세요."(EN "Check the final ranking.")와 최종 순위를 함께 보여준다. 비회원도 이 화면과 같으며 로그인 유도는 하지 않는다. 집계 단계는 기존 "집계 중" 화면을 그대로 쓴다.
- **리더보드 노출 범위**(랭킹 ON, 확정 2026-10-02): 모든 단계(참여·집계·결과 발표·지급 기간)에서 **수상 인원 전체**(1위부터 `winnerCount`위까지, 예: 수상 30명이면 30위까지)의 순위와 내 순위를 보여준다.
- **리더보드 행 수·페이지네이션**(랭킹 ON, 확정 2026-10-02): 완성자가 수상 인원보다 적으면 있는 순위까지만 표시하고 빈 행 UI는 두지 않는다(예: 수상 30명·완성 18명이면 18행). 한 페이지 10행 고정(사용자가 행 수를 바꿀 수 없음)으로 나누고 페이지 번호 + 이전/다음 버튼으로 이동하며 모든 단계에서 같다. 1페이지뿐이면 페이지 버튼을 숨긴다. 내 순위 행은 페이지와 무관하게 목록 아래 고정한다. 기존 "고정 높이 스크롤·PC 2열" 방식은 쓰지 않는다(PC·모바일 모두 1열).
- **집계 단계 리더보드**(랭킹 ON, 확정 2026-10-02): 집계 단계 시작(다음 날 00:00 UTC) 직후 서버가 한 번 재산정한 순위를 노출한다. 참여 기간 마지막 날 빙고 Batch 이후 완성자(마지막 날 참여 UID를 등록해 소급 게이지로 완성한 경우 포함)까지 참여 기간 중 모든 완성자가 들어 있으며, 이후 갱신은 멈춘다. 집계 단계 동안 생긴 비운 자리(어뷰징 제외·탈퇴·소멸)도 이 단계에서는 반영하지 않고 재산정 결과 그대로 고정하며, 결과 발표 때 반영한다(확정 2026-10-12). 라벨은 "집계 중"(EN "Calculating")으로 확정한다. 보조 문구가 필요하면 "집계 중이에요. 결과 발표 때 최종 순위가 확정돼요" [검수 필요, 언어팩 검수 대상]를 쓴다. 집계 중 순위와 최종 순위의 차이는 이렇게 비운 자리에서만 생기며, 결과 발표 때 그 자리를 비워 두고 뒷순위를 당기지 않는다(확정). 참여 기간 중 탈퇴·초기화된 완성자는 다음 빙고 Batch 재산정에서 순위 대상에서 빠진다(자리 비움 아님, 확정 2026-10-12).
- **연속 기록 표시**(확정 2026-10-12, 목업 방식): 참여 기간에는 라벨 "현재 연속 페이백 기록"(EN "Current Cashback Streak") + 큰 숫자 "4일"(EN "4 Days", 1이면 "1 Day", `streak.currentDays`) + 작게 "연속 페이백"(EN "Cashback Streak") + 진행 막대로 보여준다. 최고(최장) 기록은 표시하지 않는다(API-005 `streak.maxDays`는 화면 미사용). 집계·결과 발표·지급 기간에는 라벨을 "최종 연속 페이백 기록"(EN "Final Cashback Streak")으로 바꾸고 같은 숫자 표시를 쓰며 진행 막대는 숨긴다. EN은 Day/Days 첫 글자를 대문자로 쓴다. 최종 값 = 참여 기간 종료 시점의 현재 연속 일수(API-005 `streak.currentDays`, 집계부터 갱신 없음).
- **최종 수상자 리더보드**(랭킹 ON, 화면 라벨 "최종 순위" / EN "Final Ranking"): 결과 발표 단계부터 확정 순위를 한 번에 발표하고, 지급 기간에도 종료(404)까지 같은 내용을 계속 노출한다. 컬럼은 다른 단계와 같다: 순위, 트레이더(마스킹 TUID), 총 페이백, 랭킹 리워드(EN Rank / Trader / Total Cashback (USDT) / Ranking Reward (USDT), 확정 2026-10-12). 집계 이후 갱신하지 않는다(최종 결과 고정).
- 버튼 활성 여부는 프론트가 판단하지 말고 API 값(`actions.participationOpen`, `actions.checkOpen`, `actions.canRegister`, `actions.canReselect`)을 따른다.
- **어뷰징 제외 사용자 화면**(확정 2026-10-02): 제외(EXCLUDED) 사실을 사용자에게 알리지 않는다. "지급 대상 아님" 같은 별도 안내 문구·화면 상태를 두지 않는다(API-003에서 `PARTICIPATING`으로 옴). 프론트는 `participantStatus`로 분기하지 않고 API 값대로 그린다. 집계 기간에는 일반 참여자와 같다. 결과 발표·지급 기간(랭킹 OFF는 지급 기간)에는 API-005 리워드 금액이 `null`로 오면 금액을 "-"로 표시하고 적립 안내 문구는 표시하지 않는다. API-005 `ranking`·API-007 `me`가 `null`이면 내 순위 표시와 리더보드 "내 순위" 행을 숨긴다. 리더보드 목록에서도 그 자리는 다른 비운 자리처럼 행이 보이지 않는다(확정 2026-10-05). 내 리워드 상태 배지(받을 예정 / 집계 중 / 확정)는 일반 참여자와 같게 둔다(배지를 바꾸면 제외 사실이 드러나므로, 확정 2026-10-05).
- **참여 UID를 잃은 사용자 화면**(API-003 `RESELECT_REQUIRED`, 확정 2026-10-12): 사용자는 UID를 직접 연동 해제할 수 없으며, 참여 UID가 끊기는 원인은 소유권 이전·이슈 UID 지정이다. 원인과 관계없이 같은 화면이다(F-005). 혜택 상세 **맨 위 안내 영역**(팝업 아님, 상단 공동 표기·히어로보다 위, 그 상태인 동안 들어올 때마다 표시)에 제목 "참여 중이던 UID로 더 이상 참여할 수 없어요"(EN "You Can No Longer Participate with This UID") + 본문 "이 UID로는 이 빙고판에 다시 참여할 수 없어요."(EN "This UID can no longer join this board.")를 보여준다. 집계·결과 발표 단계(지급 전)에는 본문 아래 "이벤트 리워드는 지급되지 않아요"(EN "No event rewards will be paid." [EN draft])를 함께 보여주고, 지급 기간에는 이 문장을 쓰지 않는다(지급 후 잃은 경우 이미 지급됐을 수 있음). 그 아래 화면은 **처음 참여하는 사람과 같다**: 빙고판은 구성만(게이지·내 리워드 없음), 참여 기간이면 고를 자격 UID 유무에 따라 [새 UID 선택하기] 또는 "참여할 수 있는 {거래소} UID가 없어요. 새 UID를 연동하면 다시 참여할 수 있어요." + [UID 연동하기](선택 레이어를 열지 않음, 처음 참여자의 자격 UID 없음과 같은 정책). 참여 기간 이후는 처음 참여하는 사람과 같은 비활성 버튼(집계 "집계 중", 결과 발표·지급 기간 "참여 기간 종료")만 보이고, 리더보드(랭킹 ON)는 다른 사용자와 같게 보인다(내 순위 행 없음).
- **단계 안내 문구·배지·칸 동작**(확정 2026-10-12): `notice=AGGREGATING`은 "데이터 집계 중이에요"(EN "Calculating") + 결과 발표 일시(ON) 또는 지급 시작 일시(OFF), `notice=RESULT_ANNOUNCED`는 참여자에게 "리워드가 확정됐어요"(EN "Rewards Confirmed") + "○월 ○일 ○○:○○부터 참여 UID로 이벤트 리워드가 지급돼요."(미참여자는 "참여 기간이 끝났어요"), `notice=PAYOUT_IN_PROGRESS`는 참여자에게 "리워드를 지급하고 있어요"(EN "Paying Rewards") + 상태 문구 "순차적으로 지급 중". 내 리워드 상태 배지는 참여 기간 "받을 예정", 집계 "집계 중", 결과 발표·지급 기간 "확정"(지급 기간에도 "확정" 유지, 별도 "지급 완료" 배지 없음). 잠긴 칸(`LOCKED`)은 눌러도 아무 동작이 없다(`aria-disabled`, 안내 팝업 없음). 참여 UID가 없는 사용자(비회원·미참여자·참여 UID를 잃은 사용자)에게는 9칸을 모두 잠김 모양(점선·반투명)으로 그리고 칸 값(목표 금액·N일)만 보여주며, 사전공개·참여 단계면 빙고판 위에 "참여하면 받은 페이백으로 원하는 칸을 골라 체크할 수 있어요."를 표시한다.

## 5. 앱 푸시 이동 경로

앱 푸시 발송은 서버가 한다(백엔드 문서 F-032). 프론트는 **모든 맥스보드 푸시의 이동 경로가 혜택 상세(SCR-U02)** 라는 점만 맞추면 된다. 푸시로 들어온 빙고판이 이미 종료·강제 종료됐다면 F-002 규칙대로 SCR-U05(404)를 보여준다.

## 6. 화면 버튼 이동 경로 (확정 2026-10-07)

사용자 화면의 모든 버튼·링크가 어디로 가는지 정리한다. 버튼 표시 여부는 API 값(`actions.*`)과 F-002 "버튼" 규칙을 따른다.

| 버튼 / 링크 | 표시 조건 | 이동 / 동작 | 관련 요구사항 |
|-------------|-----------|-------------|---------------|
| 혜택 목록 카드 | 사전공개~지급 기간 | 혜택 상세 `/{lang}/max-board?benefitNo={n}` | REQ-075 |
| 로그인하고 참여하기 | 참여 기간, 비회원 | 기존 로그인 화면. 로그인 또는 그 화면에서 회원가입을 마치면 같은 `benefitNo`의 혜택 상세로 복귀 | REQ-076 |
| UID 연동하기 | 참여 기간, 자격 UID 없음(`NO_ELIGIBLE_UID`) 또는 참여 UID를 잃고 고를 자격 UID가 없음(`RESELECT_REQUIRED` + `eligibleUids=[]`). 사전공개에는 없음 | 기존 거래소 UID 연동 화면, 이 빙고판 거래소(`exchange.code`) 미리 선택. 연동 완료 또는 취소 후 같은 `benefitNo`의 혜택 상세로 복귀 | REQ-077, REQ-124 |
| 참여하기 | 참여 기간, 참여 UID 미등록(`NOT_REGISTERED`) | 상세 안 참여 UID 선택 레이어(SCR-U03, 모바일 바텀시트·PC 팝업) | REQ-027 |
| 새 UID 선택하기 | 참여 기간, 참여 UID를 잃음(`RESELECT_REQUIRED`) + `actions.canReselect=true`(고를 자격 UID 있음) | 상세 안 참여 UID 선택 레이어(SCR-U03) → 재선택 확인 팝업(F-005) | REQ-030 |
| 이벤트 리워드 확인하기 | **지급 기간**, 참여자(`PARTICIPATING`, 어뷰징 제외자 포함). 결과 발표 단계, 참여 UID를 잃은 사용자(`RESELECT_REQUIRED`)에게는 표시하지 않음 | 기존 페이백 요약(히스토리) 화면을 필터 미리 선택 상태로 연다: 거래소 = `exchange.code`, UID = 참여 UID, 유형 = 이벤트 리워드, 달력 월·날짜 = 지급 시작일(`PAYOUT.startAt`의 로컬 날짜). 어뷰징 제외자는 지급되지 않은 그대로(빈 내역) 보임. 히스토리 화면이 이 필터를 주소 파라미터로 받아 미리 선택하는 기능을 이번 범위에서 개발한다(파라미터 이름은 히스토리 화면 개발 시 정함) | REQ-125 |
| 총 랭킹 리워드 | 랭킹 ON, 사전공개부터(히어로 "랭킹 리워드 총"과 02 / REWARDS 랭킹 영역) | 등수별 랭킹 리워드 팝업(모바일 바텀시트) | REQ-112, REQ-128 |
| 리더보드 페이지 번호·이전/다음 | 랭킹 ON | 같은 화면에서 API-007 `page` 변경 | REQ-052 |
| 전체 일정 보기 | 상세 노출 단계 | 같은 화면에서 펼치기·접기 | REQ-123 |
| 섹션 이동 탭 | 상세 노출 단계(이벤트 안내 / 빙고 미션 / 리워드 · 랭킹 / 유의사항) | 같은 화면의 해당 섹션으로 스크롤, 누른 탭 강조 | REQ-126 |
| 혜택 목록 (뒤로) | 혜택 상세 | 혜택 목록 | REQ-075 |
| 앱 푸시 | 푸시 5종 | 혜택 상세(5장) | REQ-090~094 |
| 결과 이메일 버튼 | 이메일 2종 | 혜택 상세(백엔드 F-033). 하단 고객센터·수신 거부·SNS 링크는 기존 테더맥스 시스템 이메일과 같은 주소 | REQ-095~097 |
