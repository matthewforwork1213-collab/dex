> 이 문서가 기준 문서다(통합본 없음, 2026-10-01 정리).
> **범위**: (1) 어드민 API(API-101~116)의 서버 처리 (2) 공통 시스템 로직 F-012~F-020 (3) 공통 알림 F-031~F-033.
> **(2)·(3) 공통 섹션은 사용자 백엔드 문서에 같은 내용으로 중복 수록**되어 있다. 고칠 때는 두 문서를 함께 고친다.
> F-ID는 분할 전 통합 번호를 그대로 쓴다. 같은 F-ID가 프론트 문서에도 있으며, 프론트는 화면, 백엔드는 서버 처리를 다룬다.
> 모든 날짜·시각 판정은 **UTC**(API 응답도 UTC, 사용자 화면은 프론트가 기기 로컬 시간으로 변환 표시, 백오피스 화면은 UTC 표시), 금액은 **USDT**(소수점 둘째 자리 10진 문자열, 부동소수점 금지). 어드민 응답은 TUID·UID를 **마스킹하지 않는다**.
> **미정 항목 개발 기본값(2026-10-07)**: 확정 전까지 아래 값으로 개발하고, 확정되면 이 문서를 고친다. 서비스명 = 맥스보드 / MAX BOARD(#NAME), 빙고판 배경색 = TetherMax 기본 파랑 고정·백오피스 입력 없음(색 변경 기능 검토 중), 혜택 상세 상단 큰 제목 = 어드민 입력 제목(`<br />` 줄바꿈 적용), 빙고 Batch 실행 시각 = 설정값(예시 12:30 UTC, #BATCH), SEO 중국어 간체 = 미지원(#SC), 배너 외 추가 이미지 = 없음(#IMG). "오늘 마감"은 기기 로컬 날짜 기준(확정 2026-10-07).

## 1. 어드민 API 서버 처리

### F-030. 권한 제어 (모든 어드민 API 공통)

| 항목 | 내용 |
|------|------|
| 설명 | 백오피스 기존 인증·권한 체계로 맥스보드 API를 제한한다. |
| 처리 | 공통 인가 미들웨어에서 역할(MASTER / OPERATOR / PM / CS) 확인. MASTER·OPERATOR·PM: 전체. CS: 조회(GET)만. **변경 요청(생성·수정·제외·복구·강제 종료·이미지 업로드)과 CSV는 CS면 `403 FORBIDDEN_ROLE`**. 맥스보드 메뉴 권한이 없으면 `403 FORBIDDEN` |
| 출력 | 조회 응답의 `actions`, `excludable`, `recoverable` 같은 버튼 활성 값에 요청자 역할을 반영(CS는 항상 false). 목록 [빙고판 생성]·[CSV 다운로드]처럼 응답에 활성 값이 없는 버튼은 화면이 **기존 백오피스 세션의 역할 정보**로 판단하므로 맥스보드 API에 역할 필드를 따로 두지 않는다 |
| 예외 | 화면 버튼 비활성과 별개로 서버가 모든 변경 요청에서 역할을 다시 검사한다 |
| 관련 요구사항 | REQ-020, REQ-021, NFR-006 |

### F-022. 빙고판 생성

| 항목 | 내용 |
|------|------|
| 설명 | 새 빙고판을 등록한다. **임시저장 없이 등록 즉시 확정**된다. |
| API | API-102 `POST /api/admin/maxboard/boards`, API-115(거래소 목록), API-116(이미지 업로드) |
| 입력 | `confirmed`, 거래소 1곳, 랭킹 ON/OFF, 단계 일정(사전공개 시작일과 각 단계 종료일), 9칸(종류·값), 리워드 7개(가로 1~3, 세로 1~3, 완성), 랭킹 구간(ON만), 콘텐츠(제목·부제목 KO/EN, 배너, OG KO/EN, SEO 6개 언어) |
| 검증 | `confirmed=true` 필수. 거래소 1곳(배열이면 거부). 기간: 각 단계 종료일 ≥ 시작일(하루짜리 단계 가능, 단계 생략 불가), 종료일은 그 단계 마지막 날(23:59:59 UTC까지 포함), 날짜 역전 금지, 전체 기간 상한 없음, **과거 날짜 제한 없음**(모든 단계 과거 가능), 랭킹 ON이면 결과 발표 종료일 필수·OFF면 금지. 칸: 9개, cellNo 1~9 중복·누락 없음, 금액 칸 목표 ≥ 0.01, 연속 칸 N ≥ 1 정수이고 참여 기간 일수 이하, 종류와 값 일치. 리워드 7개 모두 필수, 각 최소 0.01(0 불가). 랭킹 구간: ON 필수·OFF 금지, 첫 구간 1위부터, 다음 시작 = 이전 끝 + 1(공백·겹침 금지), 시작 ≤ 끝, 1인 금액 최소 0.01(0 불가). 콘텐츠: 제목·부제목(KO/EN)·배너 필수(`<br />` 포함 그대로 저장, 글자 수 제한 없음), OG·SEO 선택. 이미지는 WebP·5MB 이하. 이미지 ID는 API-116으로 업로드된 ID여야 하고 용도(`purpose`)가 입력란과 맞아야 함(아니면 `INVALID_IMAGE_REF`). 금액은 소수점 둘째 자리 10진 문자열. 검사 순서: 권한(403) → `confirmed` → 본문 검증. 본문 검증 실패는 **최상위 `VALIDATION_ERROR`** 로 한 번에 돌려주고 항목별 코드(아래 목록 중 `CONFIRMATION_REQUIRED`·`FORBIDDEN_ROLE` 외)는 `details.fields[].code`에 담는다(API스펙 1.3) |
| 처리 | 저장 시 다음 단계 시작일 = 앞 단계 종료일 + 1일로 연속 저장. 빙고판마다 **혜택 번호(benefitNo)** 를 백엔드가 새로 발급(상세 주소 `/{lang}/max-board?benefitNo=` 에 사용). 1인당 비용 합계(6줄 + 완성), 수상 인원(마지막 구간 끝 순위), 랭킹 리워드풀(Σ 구간 인원 × 1인 금액) 계산. 생성 직후 상태는 현재 UTC 시각 기준 단계(사전공개 시작일 전이면 `SCHEDULED` 노출 전, 확정 2026-10-05). 등록자·등록 시각 기록 |
| 출력 | boardId, benefitNo, 현재 상태, 1인당 비용 합계, 수상 인원·리워드풀, 등록 시각·등록자 |
| 에러 코드 | 최상위: `CONFIRMATION_REQUIRED`, `VALIDATION_ERROR`, `FORBIDDEN_ROLE`. `details.fields[].code`: `INVALID_EXCHANGE`, `MULTIPLE_EXCHANGES_NOT_ALLOWED`, `INVALID_SCHEDULE`, `INVALID_CELLS`, `AMOUNT_CELL_MIN`, `STREAK_DAYS_MIN`, `INVALID_REWARDS`, `INVALID_AMOUNT`, `RANK_TIERS_REQUIRED`, `RANK_TIERS_NOT_ALLOWED`, `RANK_TIER_NOT_FROM_ONE`, `RANK_TIER_GAP`, `RANK_TIER_OVERLAP`, `CONTENT_REQUIRED`, `REWARD_AMOUNT_MIN`, `STREAK_DAYS_EXCEED_PERIOD`, `INVALID_IMAGE_REF` |
| 예외 | 1인당 비용 합계는 계산만 하고 금액을 제한하지 않는다. 같은 거래소 기간 중복은 검사하지 않는다(운영 원칙). 미리보기·임시저장 API 없음. 과거 날짜 등록은 테스트 용도이므로 이미 지난 배치·알림·확정·지급에 대한 별도 처리는 만들지 않는다(확정) |
| 관련 요구사항 | REQ-001~010, REQ-106 |

### F-023. 빙고판 수정

| 항목 | 내용 |
|------|------|
| 설명 | 등록된 빙고판의 콘텐츠만 부분 수정한다. |
| API | API-104 `PATCH /api/admin/maxboard/boards/{boardId}/content` |
| 입력 | 보낸 필드만 반영: 제목·부제목(KO/EN), 배너, OG(KO/EN), SEO(6개 언어) |
| 처리 | 금액·조건 필드(거래소, 랭킹 ON/OFF, 기간, 칸, 리워드, 랭킹 구간)가 하나라도 있으면 **전체 거부**. 제목·부제목·배너는 빈 값·null 불가(`<br />` 포함 그대로 저장). OG·SEO는 null이면 삭제(사이트 기본값 사용). 이미지 ID 검증은 F-022와 같음(`INVALID_IMAGE_REF`). 검사 순서: 권한(403) → 빙고판 존재(404) → 종료 상태(`BOARD_CLOSED`) → 잠긴 필드(`LOCKED_FIELD_NOT_EDITABLE`) → 본문 검증. 수정자·수정 시각 기록. **저장 후 사용자 API(API-001, API-002) 캐시 무효화**(API스펙 1.1 캐싱) |
| 출력 | 수정된 필드 목록, 수정 시각, 수정자 |
| 에러 코드 | `LOCKED_FIELD_NOT_EDITABLE`, `VALIDATION_ERROR`(지원하지 않는 언어 키 포함, 항목별 `details.fields[].code`: `CONTENT_REQUIRED`, `INVALID_IMAGE_REF`), `FORBIDDEN_ROLE`, `BOARD_NOT_FOUND`, `BOARD_CLOSED`(ENDED·TERMINATED) |
| 관련 요구사항 | REQ-011, REQ-106 |

### F-024. 빙고판 상세 · 현황

| 항목 | 내용 |
|------|------|
| 설명 | 상단 요약·설정값, 현황 지표, 어드민 리더보드를 제공한다. |
| API | API-103 `GET .../boards/{boardId}`, API-105 `GET .../stats`, API-106 `GET .../leaderboard` |

## 2. 공통 시스템 로직 (사용자 백엔드 문서와 동일)

> 아래 F-012~F-020은 사용자·백오피스 양쪽이 쓰는 배치·판정·지급 로직이다. 분할 전 기능명세서 v1.3 원문을 그대로 옮겼다. 내부 작업 상세(JOB-01~11)는 `API스펙_ko.md` 5장을 함께 본다.
>
> **빙고 Batch (2026-10-02 도입)**: 맥스보드는 거래소 페이백 배치(테더맥스 기존 시스템, 이하 "페이백 배치")를 직접 쓰지 않고, 페이백 배치 결과를 불러오는 **빙고 전용 일 배치 "빙고 Batch"** 를 둔다. 빙고 Batch는 **하루 1회, 모든 거래소 공통 고정 시각**(설정값, 가장 늦은 페이백 배치인 Bitget UTC 12:00 이후. 구체 시각은 미정, PRD Open Issue #BATCH)에 실행하며, 한 번에 F-012(게이지)·F-013(연속 기록·연속 칸 활성화)·F-014(랭킹)를 함께 갱신한다. 지연·누락 판정과 복구는 모두 빙고 Batch 기준이다. 사용자 화면에는 다음 업데이트 시각을 표시하지 않고 참여 기간 중에만 "하루 한 번 업데이트돼요"를 표시한다(확정 2026-10-02). 연속 판정 기준일은 **페이백 배치 반영일**(빙고 Batch 실행일 아님)이다.

### F-016. UID 소유권 이전·탈퇴 처리

| 항목 | 내용 |
|------|------|
| 설명 | 참여 UID의 소유권 이전, 이슈 UID 지정, TUID 탈퇴를 반영한다. 사용자는 UID를 직접 연동 해제할 수 없으므로 참여 UID를 잃는 원인은 소유권 이전(다른 사람이 소유권 인증으로 가져감)과 이슈 UID 지정 두 가지다(확정 2026-10-12). |
| 입력 | 계정 DB의 소유권 이전 이력, 이슈 UID 지정 이력, TUID 탈퇴 이력(모두 맥스보드가 직접 확인). 판정 시각은 **테더맥스 계정 DB 이력의 시각**(확정 2026-10-12) |
| 처리 | 확인 시점: 사용자 요청 시(상세 진입·참여 등록·칸 체크), 매일 빙고 Batch(참여 기간 이후에도 **지급 완료까지** 계속 대조, 확정 2026-10-12), 리워드 확정(F-017)·적립(F-018) 직전. 소유권 이전·이슈 UID 지정은 같은 규칙으로 처리하며 이력 시각으로 상태를 정한다: (1) 참여 기간 안 → 초기화(`RESET`, 사유 `OWNERSHIP_TRANSFER` / `ISSUE_UID`). 그 빙고판에서 처음 온 사람처럼 된다(체크 칸·줄·완성·랭킹·달성 리워드 전부 이 TUID 진행에서 분리). 새 UID를 선택할 수 있고 새 UID는 자기 게이지·연속 이력으로 시작. 완성자였다면 다음 빙고 Batch 산정에서 순위 대상에서 빠짐(자리 비움 아님). 단, 이력 시각이 참여 기간 안이어도 **집계 시작 재산정 이후에 감지**되면 순위를 다시 당기지 않도록 (2) 소멸로 처리한다(확정 2026-10-12) (2) 집계 시작 이후~지급(적립) 전 → 소멸(`FORFEITED`, 같은 사유). 새 UID 선택 불가, 리워드 없음, 완성자면 랭킹 자리 비움 (3) 지급(적립) 이후 → 이미 지급된 금액은 회수하지 않고 참여 상태·지급 금액은 바꾸지 않으며 이력만 남김. 리워드는 지급 기간 시작 때 최종 상태 기준으로 한 번만 지급하므로 이중 지급은 없다(확정 2026-10-12). 소유권 이전된 참여는 새 TUID로 넘어가지 않는다. 이슈 UID는 자격 UID 목록에서 제외(F-003), 지정 기간 게이지·연속 미기록(F-012). 탈퇴: 해당 TUID의 모든 빙고판 참여 상태 `WITHDRAWN`, 리워드 미지급. 참여 기간 중 탈퇴한 완성자는 순위 대상에서 빠지고, 집계 시작 이후 탈퇴는 랭킹 자리 비움 |
| 출력 | 참여 상태(초기화 `RESET` / 소멸 `FORFEITED` / 탈퇴 `WITHDRAWN`)와 사유(`resetReason`: `OWNERSHIP_TRANSFER` / `ISSUE_UID`, RESET·FORFEITED 공통), 이력(초기화 `RESET`·소멸 `FORFEITED`·지급 후 UID 변경 `UID_LOST_AFTER_PAYOUT`, 계정 DB 이력 시각 포함) |
| 예외 처리 | 이전된 UID는 새 TUID에서도, 원 TUID로 다시 돌아와도 같은 빙고판 재참여 불가(진행 복원 없음). 이슈 UID 지정이 풀려도 재참여 불가 |
| 관련 화면 | 혜택 상세, 어드민 참여자 목록 |
| 관련 API | 계정 시스템 이벤트 수신(내부) |
