## 2. 공통 규칙

| 항목 | 규칙 | 근거 |

| 권한 | 마스터/오퍼레이터·PM은 모든 기능. **CS는 조회만**: [빙고판 생성], [수정], [강제 종료], [선택 사용자 어뷰징 제외], [복구], [CSV 다운로드] 버튼을 **비활성**으로 표시. 서버도 403으로 거부하므로 화면 비활성은 편의 장치다. 버튼 비활성 판단은 **기존 백오피스 로그인 세션의 역할 정보**(MASTER / OPERATOR / PM / CS)를 쓴다(목록 [빙고판 생성]·[CSV 다운로드]처럼 응답에 활성 값이 없는 버튼 포함). 응답에 `actions`·`excludable`·`recoverable`이 있으면 그 값을 함께 따른다 | REQ-020, REQ-021 |

### F-022. 빙고판 생성

| 항목 | 내용 |
|------|------|
| 설명 | 새 빙고판을 등록한다. 임시저장·미리보기 없이 [등록] 즉시 확정된다. |
| 화면 | SCR-A02 → SCR-A02-P1 |
| 호출 API | API-115(거래소 목록), API-116(배너·OG 이미지 업로드), API-102 `POST /api/admin/maxboard/boards` |
| ① 기본 설정 | 거래소 **1곳** 선택, 랭킹 ON/OFF |
| ② 기간 | 사전공개 시작일만 직접 입력. **이후 단계 시작일은 앞 단계 종료일 다음 날로 자동 채움.** 종료일은 그 단계의 마지막 날(23:59:59 UTC까지 포함)이며 일수 = 종료일 − 시작일 + 1(하루짜리 단계는 시작일 = 종료일). 종료일과 일수는 서로 연동. 단계 생략 불가, 전체 기간 상한 없음, **과거 날짜 입력 가능**. 랭킹 OFF면 결과 발표 행 숨김 단계 생략은 없으며, 사전공개를 사실상 건너뛰려면 사전공개 시작일·종료일을 어제로 입력한다 |
| ③ 빙고판 구성·리워드 | 3×3 칸마다 종류(금액 칸 / 연속 칸)와 값(목표 USDT / 연속 일수 N). 종류별 개수·위치 제한 없음(9칸 모두 연속 칸 가능). 리워드 입력 위치: **가로 줄 리워드는 각 행 오른쪽, 세로 줄 리워드는 각 열 아래, 완성 리워드와 1인당 비용 합계는 빙고판 오른쪽** 연속 칸은 다른 배경색으로 구분하고, 리워드 입력란은 칸과 다른 스타일로 구분한다. 9칸을 모두 같은 N으로 두면 N일째에 한 번에 완성될 수 있으므로 난이도는 운영자가 조절한다 |
| ④ 랭킹 리워드 구간 (ON만) | 구간 행(시작 순위, 끝 순위, 1인 금액) [구간 추가]로 추가, 각 행 오른쪽 [삭제] 버튼으로 삭제(마지막 1행은 삭제 불가). 수상 인원과 랭킹 리워드풀 합계 실시간 계산 |
| ⑤ 콘텐츠·SEO | 필수: 제목·부제목(KO/EN), 배너 이미지. 선택: OG 이미지(KO/EN), SEO 타이틀·디스크립션(KO/EN/VI/TC/RU/ID). 미입력 SEO는 사이트 기본값이 쓰인다는 안내 표시. 제목·부제목 입력란 옆에 "`<br />`을 입력하면 줄바꿈됩니다" 안내(`<br/>`, `<br>`도 인정, 글자 수 제한 없음). SEO·OG 입력란에는 줄바꿈이 적용되지 않는다. 이미지 업로드는 **WebP만, 5MB 이하**(위반 시 업로드 전에 안내). **유의사항 입력란은 없다**(모든 빙고판 공통 고정 문구가 자동 노출된다는 안내만 표시) |

| 에러 처리 | `BATCH_NOT_RECOVERABLE`(누락이 아님·참여 기간 밖), `BATCH_SOURCE_NOT_FOUND`(원천 데이터 없음, 페이백 시스템에서 먼저 채워야 함), `BATCH_RECOVERY_IN_PROGRESS` 안내 |
| 버튼 활성 | [복구]는 API-110 행의 `recoverable=true`일 때만 표시·활성(결과 누락 + 복구 완료·실행 중 아님 + 변경 권한 + 종료·강제 종료 아님). 복구 실패(`FAILED`) 행은 다시 [복구] 가능. 복구 행에는 실행자(`recoveredBy`)·시각(`recoveredAt`)을 표시 |
| 상태·예외 | 복구는 비동기 작업(202 + jobId)이라 완료 후 목록을 다시 불러야 결과가 바뀐다(`recoveryState`로 진행 상태 확인). 강제 종료되면 실행 중인 복구는 중단된다. 참여 기간 종료 후에도 [복구] 사용 가능(확정). 빙고 Batch 자체가 누락된 날은 다음 날 빙고 Batch가 자동으로 채우지 않으므로 이 [복구]로만 채운다(확정 2026-10-02). 컬럼명 "배치 반영일"은 어드민 용어로 유지(사용자 비노출) |
| 관련 요구사항 | REQ-058, REQ-059 |

### F-028. 어뷰징 제외

| 항목 | 내용 |
|------|------|
| 설명 | 집계 기간에 어뷰징 사용자를 리워드 지급 대상에서 제외한다. |
| 화면 | SCR-A04-T2 → SCR-A04-P2 |
| 호출 API | API-113 `POST .../exclusions`, API-112(제외 기록 조회) |
| 동작 | 참여자 선택 → [선택 사용자 어뷰징 제외] → 사유 입력 팝업(**필수**, 비어 있으면 다음 단계 버튼 비활성) → "취소할 수 없습니다" 확인 → API-113 → 목록 새로고침(상태 "제외", 어드민 리더보드는 즉시 "제외 · 자리 비움", 순위·총 페이백 고정) |
| 제외 기록 표시 (확정 2026-10-12) | ② 참여자 탭 하단에 "어뷰징 제외 기록" 표(API-112: TUID, 참여 UID, 사유, 처리 시각(UTC), 처리자)를 제외 기록이 1건 이상일 때 표시. 개별 참여자의 제외 정보는 참여자 상세(F-026) 요약·이력에도 표시 |
| 상태·예외 | 버튼은 **집계 기간에만 활성**(CS는 항상 비활성, 다른 단계에서는 비활성이며 사유 팝업도 열리지 않음). 상태가 "참여"인 행만 선택할 수 있고 초기화·제외·탈퇴·소멸 행의 체크박스는 비활성(IA-9, 확정 2026-10-05). 제외 취소 UI 없음. 제외 대상의 리워드 전체(빙고·완성·랭킹)가 미지급되고 뒷순위는 당겨지지 않는다는 안내를 팝업에 표시. `EXCLUSION_NOT_IN_AGGREGATION`, `EXCLUSION_REASON_REQUIRED`, `PARTICIPANT_NOT_EXCLUDABLE` 에러 표시. 선택 체크박스는 API-107 `excludable=true` 행만 활성(집계 단계 + 상태 참여 + 변경 권한). 다른 상태가 섞이면 API가 전체를 거부한다 |
| 관련 요구사항 | REQ-064~066 |

### F-029. 강제 종료

| 항목 | 내용 |
|------|------|
| 설명 | 빙고판을 어느 단계에서든 즉시 종료한다. |
| 화면 | SCR-A04 → SCR-A04-P1 |
| 호출 API | API-114 `POST .../terminate` |
| 동작 | [강제 종료](CS 비활성) → 확인 팝업 → [확인] → API-114 → 상태 terminated로 표시. 팝업 전문(통일, 확정 2026-10-12): "진행 중인 모든 처리가 멈추고 사용자 페이지가 바로 404가 됩니다. 지급 기간이 시작되지 않았다면 리워드는 지급되지 않으며, 이미 지급된 리워드는 회수하지 않습니다. 강제 종료는 취소할 수 없습니다." |
