> 이 문서가 기준 문서다(통합본 없음, 2026-10-01 정리).
> **수록 범위**: 백오피스 전용 요구사항(AD) + 시스템 로직(SYS) + 알림(NTF). SYS·NTF는 화면이 없는 공통 로직이라 **사용자·백오피스 문서에 같은 내용으로 중복 수록**한다. 사용자 화면 전용 요구사항은 `분할문서/사용자/요구사항정의서_ko.md`에 있다.
> **ID 규칙**: REQ 번호는 분할 전 통합 번호를 그대로 쓴다(번호가 건너뛰는 것은 다른 파트 요구사항이다).
> **구분**: FR = 사용자 화면(프론트), AD = 어드민(백오피스), SYS = 시스템 로직(배치·판정·지급), NTF = 알림.
> 모든 기간·날짜 판정은 **UTC 기준**, 리워드는 **USDT**. 백오피스 화면은 UTC로 표시하고, 사용자 화면은 기기 로컬 시간으로 변환해 표시한다(NFR-011).
> **"(사용자 요구사항정의서 참조)"** 표시가 붙은 REQ 번호는 이 문서에 없고 `분할문서/사용자/요구사항정의서_ko.md`에 있다.

**용어 (확정 2026-10-12)**

| 용어 | 정의 |
|------|------|
| 달성 | 줄 완성(빙고 리워드)·빙고판 완성(완성 리워드)·랭킹 순위 안에 든 상태. **받을 예정**일 뿐 돈은 아직 나가지 않았다. 어드민 화면의 "예상 리워드·예상 지급액"은 달성 기준 금액이다 |
| 지급(적립) | 지급 기간 시작 시 확정된 리워드를 참여 UID로 지급되는 금액에 실제로 적립하는 것. 리워드는 지급 기간 시작 때 최종 상태 기준으로 한 번만 지급된다 |
| 참여 UID를 잃음 | 사용자는 UID를 직접 연동 해제할 수 없다. 참여 UID가 끊기는 원인은 **소유권 이전**(다른 사람이 소유권 인증으로 가져감)과 **이슈 UID 지정** 두 가지다(탈퇴는 별도 상태). 판정 시각은 테더맥스 계정 DB 이력의 시각이다 |
| 초기화 (`RESET`) | 참여 기간 중 참여 UID를 잃은 경우. 그 빙고판에서 **처음 온 사람처럼** 된다(체크 칸·줄·완성·랭킹·달성 리워드 전부 사라짐). 새 UID를 선택할 수 있고 새 UID는 자기 게이지로 시작한다. 사유 `OWNERSHIP_TRANSFER` / `ISSUE_UID` |
| 소멸 (`FORFEITED`) | 집계 시작 이후~지급 전에 참여 UID를 잃은 경우. 리워드 없음, 빙고판 완성자면 랭킹 자리 비움. 사유 `OWNERSHIP_TRANSFER` / `ISSUE_UID` |
| 지급 후 UID 변경 | 지급(적립) 이후 소유권 이전·이슈 UID 지정. 이미 지급된 금액은 회수하지 않으며, 원 TUID의 참여 상태·지급 금액은 바꾸지 않고 이력만 남긴다 |

## 1. 기능 요구사항 (Functional Requirements)

### 1.1 빙고판 생성·운영 (어드민)

| ID | 구분 | 요구사항 | 우선순위 | 인수 기준 |
|----|------|----------|----------|-----------|
| REQ-001 | AD | 빙고판을 생성할 수 있다. 빙고판 1개는 거래소 1개에 대응한다. | Must | 생성 시 거래소 1곳만 선택 가능. 여러 거래소 선택 불가 |
| REQ-002 | AD | 여러 빙고판을 동시에 운영할 수 있다. | Must | 기간이 겹치는 빙고판 2개 이상이 각각 독립적으로 진행됨(같은 거래소 기간 중복은 시스템이 막지 않음, 운영 원칙으로 관리). 같은 거래소 빙고판을 참여 기간이 겹치게 열면 같은 UID가 같은 페이백으로 리워드를 이중으로 받으므로 운영에서 겹치지 않게 한다 |
| REQ-003 | AD | 빙고판 생성 시 랭킹 리워드 ON/OFF를 정한다. | Must | ON/OFF 선택 후 등록하면 이후 변경 불가 |
| REQ-004 | AD | 기간 단계(사전공개 → 참여 → 집계 → 결과 발표 → 지급 기간)의 날짜를 설정한다. 랭킹 OFF면 결과 발표를 뺀 4단계. | Must | 첫 단계 시작일만 직접 입력, 이후 단계 시작일 = 앞 단계 종료일 다음 날로 자동 설정. 종료일은 그 단계 마지막 날(23:59:59 UTC까지 포함), 일수 = 종료일 − 시작일 + 1(하루짜리 단계 가능). 종료일·일수 입력 시 서로 연동. 단계 생략 불가. 전체 기간 상한 없음. 과거 날짜 제한 없음. 랭킹 OFF면 결과 발표 행 숨김. 단계는 생략할 수 없으며, 사전공개를 사실상 건너뛰려면 사전공개 날짜를 어제로 설정한다 |
| REQ-005 | AD | 3×3 칸마다 종류(금액 칸 / 연속 칸)와 값(목표 페이백 USDT / 연속 일수 N)을 설정한다. | Must | 9칸 모두 종류·값 입력 필수. 종류별 개수·위치 제한 없음(9칸 모두 연속 칸 가능). 금액 칸 최소 0.01, 연속 칸 최소 1일·최대 참여 기간 일수(초과 시 등록 불가). 9칸을 모두 같은 N으로 두면 N일째에 한 번에 완성될 수 있으므로 난이도 조절은 운영자가 판단한다 |
| REQ-006 | AD | 가로 1·2·3줄, 세로 1·2·3줄, 완성 리워드 금액을 각각 다르게 설정한다. | Must | 7개 금액 개별 입력(각 최소 0.01, 0 불가, 소수점 둘째 자리까지). 가로 리워드는 각 행 오른쪽, 세로 리워드는 각 열 아래, 완성 리워드는 빙고판 오른쪽에 배치 |
| REQ-007 | AD | 1인당 비용 합계(6줄 + 완성)를 자동으로 보여준다. | Must | 리워드 금액을 바꾸면 즉시 재계산. 금액을 강제로 제한하지는 않음(운영 가이드). 운영 가이드: 1인 최대 리워드(6줄 + 완성)가 그 사용자가 빙고판을 완성하며 만든 테더맥스 몫을 넘지 않게 설정한다 |
| REQ-008 | AD | 랭킹 ON 빙고판은 순위 구간별 금액과 수상 인원을 설정한다. | Must | 구간(시작 순위, 끝 순위, 1인 금액) 추가 가능. 1인 금액 최소 0.01(0 불가). 수상 인원·랭킹 리워드풀 합계 자동 계산. 구간 겹침·순위 공백 시 등록 불가. 랭킹 OFF면 섹션 숨김 |
| REQ-009 | AD | 제목·부제목(KO/EN), 배너 이미지, OG 이미지(KO/EN), SEO 타이틀·디스크립션(KO/EN/VI/TC/RU/ID)을 입력한다. | Must | 제목·부제목은 혜택 목록의 제목·부제목으로 사용됨. **제목·부제목·배너 이미지는 필수**, SEO 정보(OG 이미지 포함)는 전부 선택이며 미입력 시 사이트 기본 메타·기본 미리보기 이미지 사용. 글자 수 제한 없음. 배너·OG 이미지는 WebP, 5MB 이하. 유의사항은 입력하지 않음(모든 빙고판 공통 고정 문구 자동 노출, REQ-108(사용자 요구사항정의서 참조)) |
| REQ-010 | AD | 임시저장 없이 [등록]을 누르면 빙고판이 확정된다. | Must | 등록 전 확인 팝업("등록하면 거래소, 랭킹 ON/OFF, 기간, 칸 조건, 리워드 금액은 수정할 수 없습니다…") 표시. 확인 시 즉시 확정 |
