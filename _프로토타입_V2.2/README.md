# DEX 프로토타입 V2.2

**2026-11-24 확정 문서**(정책 `00_DEX_최종정책.md` · 요구사항정의서 · 프론트/백엔드 기능명세서 · API스펙)를 기능 단위로 옮긴 화면 자료입니다. 기능마다 API 결과·오류 코드·빈 상태·로딩·지연·권한 같은 경우를 **화면 상태**로 하나씩 나눴습니다. V2.1 폴더는 수정하지 않았습니다.

- 사용자 화면: `사용자화면_DEX_V2.2_YYYYMMDD_HHMM.html` (가장 최근 파일)
- 백오피스: `백오피스_DEX_V2.2_YYYYMMDD_HHMM.html`
- 기능 → 화면 → 상태 → 요구사항 대응표: `../05.리포트/프로토타입_V2.2_기능별_화면상태표.md`

## 보는 법

| 조작 | 내용 |
|---|---|
| 상단 메뉴 | 화면 묶음(예 `거래소`, `Account`, `연동`, `출금`) |
| 둘째 줄 | 화면. 칩 앞 회색 글자가 화면 키(예 `EX-2`, `AC-3`) |
| 화면 상태 | 그 화면의 경우(예 `noledger` 원장 없음 — 승인 불가). 대응표의 「상태값」과 같습니다 |
| 변경점 표시 | 체크하면 화면별 근거(정책 절 · REQ · 미정 G-ID) |
| 주소 | `파일.html#그룹/화면`(예 `#ac/AC-3`)으로 그 화면을 바로 엽니다 |

## 범위

| 구분 | 기능 | 화면 | 상태 |
|---|---|---|---|
| 사용자 화면 (FU) | 90 / 90 | 78 | 301 |
| 백오피스 (FA) | 70 / 70 | 78 | 309 |

- 화면이 아니라 규칙만 있는 기능(표기·금액·시각·귀속 확인·감사·백필·회귀 등 사용자 21개 · 백오피스 3개)은 `공통 규칙 (명세 원문)` 묶음에 **기능명세서 표를 빌드 때 그대로 옮겨** 싣습니다(`_gen-rules.cjs`). 손으로 옮기지 않습니다.
- 백오피스 사이드바는 기존 메뉴(LLM_wiki 2026-07-23, 71메뉴)에 REQ-478 · 479 · 567 · 573 · 603을 반영한 것입니다. 명세에 메뉴 위치가 없는 신규 화면(연동 감사 로그, DEX 리포팅)은 메뉴에 넣지 않고 제목에 미정으로 표시했습니다.
- 「구현 제외(Won't)」는 백오피스 `백오피스 공통 규칙 › 구현 제외`와 사용자 `분석 이벤트 규칙 › 구현 제외`에 모았습니다.

## 문구 원칙

| 표시 | 뜻 |
|---|---|
| 명세 원문 | 명세에 백틱으로 적힌 문구는 원문 그대로입니다 |
| `[내용 — 미정 G-nnn]` | 정책 부록 G에서 아직 정하지 않은 값·문구입니다. 정하기 전에는 개발 대상이 아닙니다 |
| 원문 없는 오류·확인 문구 | 백오피스의 「필수 입력」「저장 차단 — …」 같은 문구는 **동작을 설명하는 자리 표시**이며 확정 문구가 아닙니다. 기존 백오피스 문구 톤을 따릅니다 |
| 예시 값 | 주소·금액·회원 번호·시각은 예시입니다. 실제 회원 식별자는 쓰지 않았습니다 |

## 빌드와 점검

| 명령 | 내용 |
|---|---|
| `node build.cjs` | `_gen-rules.cjs`로 규칙 화면을 만들고, V2 원본 + `src/`(V2.1 레이어 + `v22.js` + `v22-*.js`)로 두 HTML을 새 파일명으로 생성. 빌드 전에 `rm -f *.html` |
| `node check-v22.cjs` | 모든 화면 × 상태 × 변경점 표시를 JSDOM으로 열어 확인(지운 화면 없음 · 새 화면 있음 · 금지 문구 없음 · 출금 버튼 비활성 · 핵심 요소 · 스크립트 오류 0) → `점검결과_V2.2.json`, `_화면텍스트_V2.2.txt` |
| `node _audit-coverage.cjs` | 기능명세서 요구사항의 백틱 문구가 화면 어딘가에 있는지 측정 → `_audit-coverage.json` |
| `node _matrix.cjs` | 레지스트리에서 대응표 MD 생성 |

반영률 미달분은 대부분 화면에 나오면 안 되는 문구입니다: 바꾸기 전 문구(`페이백 내역`, `Select a UID to apply this coupon` 등) · 금지 문구(`Paid to your EdgeX account`, `Trusted by 0 users` 등) · 설명문 조각 · 구현하지 않는 이벤트명. 「없어야 할 문구」 위반으로 잡힌 항목은 전수 확인했고, 원문이 허용하는 자리(예: 출금 카드의 `Unavailable`은 REQ-129·146이 요구, 홈 칩에서만 금지)라 결함이 아닙니다.
