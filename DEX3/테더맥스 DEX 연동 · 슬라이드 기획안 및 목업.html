2. 공통 스토리라인과 기획 의도

6개 파일 모두 같은 뼈대를 씁니다. 읽는 사람만 다르고, 같은 도식이 반복되어야 “같은 구조 이야기”로 읽힙니다.

① 전제조건을 먼저, 숨기지 않고

테더맥스는 DEX의 현재 “자동화된 페이백” 구조의 고객 페이백 비율을 0%로 두고, 커미션을 전액 테더맥스 지갑으로 받고, API를 지원받아야 연동이 가능합니다. 이 세 가지를 요청서 4번째 장에서 한 장에 못 박습니다.

② 도식이 본문, 글은 보조

플로우는 모든 파일에서 도식으로 보여줍니다. 장마다 도식 1개, 문장은 도식을 읽는 방법만 짧게 적습니다.

③ 지갑에 이름을 붙여 고정

A지갑(커미션 정산 지갑)과 B지갑(페이백 전용 지갑)을 색으로 고정합니다. A는 파랑, B는 같은 파랑 계열의 진한 톤, DEX는 초록으로 모든 장에서 같게 씁니다.

④ 요청은 “필수 / 차선” 두 단계로

API 항목은 필수와 차선을 나눠서 상대가 최소 범위부터 승낙할 수 있게 합니다. 차선 중 거래 종목·거래량은 글로벌리그·맥스보드 같은 이벤트 활용에 필요하다는 이유를 함께 적습니다.

3. 핵심 플로우 도식 (6개 파일 공통 마스터)

아래 도식이 모든 파일의 기준입니다. 요청서에서는 윗줄(돈의 흐름)만 먼저 보여주고 아랫줄(데이터의 흐름)을 다음 장에서 붙이며, 내부 공표용에서는 한 장에 함께 씁니다.

  1. 테더맥스 레퍼럴로 가입한 고객이 DEX에서 거래하고, DEX는 커미션 전액을 테더맥스 A지갑(커미션 정산 지갑)으로 지급합니다. 고객 페이백 비율은 DEX 백오피스에서 0%로 설정합니다.
  2. DEX가 API로 전일자 커미션 원장을 지정 시각에 제공하고, 테더맥스가 수령합니다.
  3. 원장을 기반으로 A지갑에서 B지갑(페이백 전용)으로 수동 리밸런싱합니다. 전일 기준 페이백 예상 금액만큼 옮깁니다.
  4. 고객이 앱·웹에서 자신의 잔액을 확인하고, 10 USDT 이상 쌓이면 출금을 신청합니다.
  5. B지갑에 보관한 가스비와 출금 금액으로, 자동화된 출금 절차가 고객 지갑에 송금합니다.
  6. 출금 전·후 금액 변동값을 API로 테더맥스 플랫폼(쿠폰, 출금 화면, 페이백 랭킹, 글로벌리그, 실시간 출금 노출, 고객 랭킹)에 반영합니다.

4. DEX 요청 자료 4종 (파일 1~4)

4개 파일은 8장 구성이 같고, 7번째 장만 DEX마다 다릅니다. 받는 쪽이 읽는 순서는 “우리는 누구인가 → 어떻게 일하는가 → 무엇을 해달라는가 → 어떤 데이터인가 → 언제까지인가”입니다.

7번째 장 — DEX별 맞춤 장 (첨부 자료에서 확인된 사실 기준)

같은 요청이라도 DEX마다 걸리는 지점이 다릅니다. 요청서를 보내기 전에 각 DEX에 사실 확인이 필요한 부분을 함께 적었습니다.

Lighter

주 1회(월요일) 정산, USDC, Plus·Premium 계정만 캐시백 발생, 어뷰징 심사 후 지급

  • 정산이 주 단위여도 일자별 원장을 달라는 요청
  • 보류·미지급 건의 상태값 포함 요청
  • Standard 계정(수수료 0%)은 커미션이 없다는 점 확인

ApeX

시간당 정산, USDT, Rewards Center에서 직접 “받기” 후 3단계를 거쳐야 출금

  • 사용자 수령 단계 없이 A지갑으로 직접 지급되는지 확인
  • 수령·미수령 상태 구분 필드 요청
  • 시간 단위 기록을 일 단위로 집계해 제공 요청

EdgeX

일 1회(00:00 UTC) 정산, USDC, 선물 계정 증거금에 섞여 입금, 출금가능 잔액 제공은 거부

  • 회원당 일 1건 원장과 지급 식별 ID 요청
  • A지갑으로 지급 시 증거금 혼입 문제가 없는지 확인
  • 잔액 조회가 아닌 “지급 원장” 중심으로 요청해 거부 이슈 회피

Aster

일 1회 정산(00:00 산정, 09:00 공개, 익일 지급), 수수료 낸 자산 그대로 지급, 레퍼럴 365일 후 만료

  • 365일 갱신 방식 확정 답변 요청 (현재 문의 중)
  • 지급 자산이 가변이므로 USDT 환산값 필드 요청
  • 지급 자산·네트워크 명시 요청
위 내용은 첨부하신 정리 문서 기준입니다. 정산 지갑 구조(A지갑 직접 수취)로 바뀌면 달라지는 부분이 있어서, 요청서에는 “현재 이해한 내용”으로 적고 DEX가 정정할 수 있게 하겠습니다.

5. 내부 공표용 국문·영문 (파일 5, 6)

12장 구성입니다. 앞 4장은 “무엇이 바뀌는가”, 가운데 4장은 “어떻게 돌아가는가”, 뒤 4장은 “무엇을 정해야 하는가”입니다. 임원·팀 리드는 2장과 12장만 읽어도 판단이 되도록 구성했습니다.

6. 확정된 사항

확인 요청에 대한 답변을 반영해 6개 파일 모두 아래 기준으로 제작합니다.

  1. 최소 출금액. 10 USDT 이상부터 출금 신청하는 기준을 유지합니다. 요청서와 내부 공표용 모두 이 기준으로 씁니다.
  2. 원장은 일 단위. Lighter(주 1회)와 ApeX(시간당)처럼 정산 주기가 달라도, 4개 DEX 모두에 “전일 기준, 일 단위” 원장을 요청합니다.
  3. 원장 갱신 시각. 00:00 UTC 기준으로 유지합니다. 타임라인 장에 UTC 기준으로 명시합니다.
  4. 표기. 표지와 본문에는 서비스명 “테더맥스”만 쓰고, 도메인은 넣지 않습니다.
  5. 일정. 연동 목표는 11월 초중순, 런칭은 12월 초입니다. 요청서 8번째 장과 내부 공표용 12번째 장 타임라인에 반영했습니다.
이 문서는 슬라이드 제작 전 확인용 기획안입니다. 승인해주시면 6개 파일 순서대로 슬라이드를 제작합니다.
