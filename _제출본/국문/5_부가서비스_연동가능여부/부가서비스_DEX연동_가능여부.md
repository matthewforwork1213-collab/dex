# 부가 서비스 DEX 연동 가능 여부

작성일 2026-10-20
대상: **테더맥스 생태계 부가 서비스 전체** (프로젝트 폴더 전수 기준 32종 + 판정 제외 22종)
근거: 기존 테더맥스 서비스 기획서·PRD 전수 + DEX PRD 13종 + Figma DEX 디자인

## 0. 판정 기준

> **자격을 만드는 행위에는 DEX를 포함한다. 돈을 받는 목적지에서는 DEX를 배제한다.**

| 구분 | DEX | 예시 |
|---|---|---|
| **자격을 만드는 행위** | **포함** | 미션 달성, 거래로 인한 캐시백 적립, 누적액 집계, 연동 완료, 내역 표시, 알림 발송 |
| **돈을 받는 목적지** | **배제** | 이벤트 리워드 수령 UID, 쿠폰 사용 대상 UID, 초대 리워드 출금 계좌, 챌린지 보상 수령 UID |

### ⚠️ 실무 판정법을 바꿨습니다 (2026-10-20)

처음에는 **"UID 선택 목록이 뜨는 모든 화면에서 DEX를 제외한다"**로 적었습니다. **이 기준은 쓸 수 없습니다.**

기존 서비스를 전수 확인한 결과, **사용자 화면에 UID 드롭다운이 거의 없습니다.** 실제 패턴은 세 가지입니다.

| 패턴 | 설명 | 사례 |
|---|---|---|
| **(a) 연동 UID 전체 나열** | 목록에서 한 건을 누름 | 누적 캐시백 좌측 레일, 페이백 랭킹 드로어 |
| **(b) 단일 UID 상세 고정** | 진입 시점에 UID가 정해짐 | 페이백 상세 `B Bitget UID 8504291751 활성`, 캐시백 타임라인 |
| **(c) 명시적 UID 선택기** | **소수.** 돈을 받을 UID를 고름 | 맥스보드 `SCR-U03 참여 UID 선택`, WOO X Pro `리워드 수령 UID 지정` |

**(c)만이 "돈을 받는 목적지"입니다.** (a)와 (b)는 조회 화면입니다.

**그래서 화면 형태가 아니라 돈의 방향으로 판정합니다.**

> **그 화면에서 테더맥스가 사용자에게 돈을 보내는가?**
> **보낸다 → DEX 배제. 보내지 않는다 → DEX 포함.**

이 기준은 화면을 열어보지 않아도 판정할 수 있습니다.

## 2. 신규 판정 상세

### 2-1. 국가별 거래소 노출 제어 — **O, 적용 필수** 🔴

**현행 구조**
- 회원 계정의 **IP 기반 국가 코드**(Cloudflare) 기준으로 특정 거래소를 응답에서 제외
- 백오피스 `거래소별 국가 노출 관리`에서 거래소마다 블랙리스트 지정
- **서버에서 제외.** 프론트 숨김 금지 (`EX-05`)
- 적용 대상은 **로그인 회원만** (`TG-01`). 국가 코드가 비면 전부 노출 (`TG-04`)
- 원칙 `PR-02` — **"이미 맺은 관계를 보여주는 곳은 제한하지 않는다."** 연동 목록·캐시백 내역은 그대로
- `EC-03`/`DL-07` — 해당 거래소에 **UID를 연동한 회원**은 노출 제한 국가여도 상세 페이지를 볼 수 있음

**판정: O. 그러나 현행 설계에 DEX가 반영되어 있지 않습니다.**

DEX는 CEX보다 규제 민감도가 **더 높습니다.**

| 사유 | 내용 |
|---|---|
| **자체수탁** | 테더맥스가 자금을 보관하지 않음. 그러나 **소개 행위 자체**가 관할에 따라 문제될 수 있음 |
| **KYC 없음** | 비교 섹션에 `Email or a wallet, no KYC check`라고 **명시**되어 있음. 이 문구 자체가 일부 관할에서 위험 |
| **무기한 파생상품** | 4개 DEX 모두 perp 거래소 |

**⚠️ 설계 과제 4건**

| # | 과제 | 내용 |
|---|---|---|
| 1 | **DEX 연동 모달도 필터 대상에 포함** | `EX-04`가 "UID 연동 모달 거래소 선택 드롭다운"을 대상으로 지정. **DEX 지갑 연동 모달은 별도 화면이라 누락될 수 있음** |
| 2 | **Hub 비교표·로고 그리드 필터링** | ④ 문서에서 확인한 Hub 요소가 `EX-09`(계산기 거래소 선택지)·`EX-11`(수수료 비교표) 대상 |
| 3 | **`EX-18` 적용 시 DEX 섹션 전체 소멸** | "항목 0개면 영역 자체 숨김". 4개 DEX가 모두 차단된 국가에서는 **DEX overview 페이지와 Hub 히어로의 `badge / DEX`가 통째로 사라짐.** 디자인에 이 상태가 없음 |
| 4 | **`PR-02` 적용 확인** | 이미 지갑을 연동한 사용자는 차단 국가에서도 잔액·내역을 봐야 함. **DEX는 돈이 DEX 계정에 있으므로 더 강하게 보장돼야 함** |

> 참고: 8월 리서치(`exchange_display_control_by_country`)와 10월 실행 정책(`improvement_14`)이 **교차 참조 없이 분리**돼 있습니다. 8월의 4축 분류(A 규제기관 지목 / B 거래소 자체 차단 / C 선물·페이백 경로 불가 / D 현지 마케팅 적법성 미확인)와 "근거일·예외 승인자를 저장하라"는 권고가 10월 설계에 반영되지 않았습니다. **DEX 차단은 거의 전부 A축이므로 근거 기록이 특히 중요합니다.**

### 2-2. 누적 캐시백 — **O, 분리 표기 필수** 🔴

**현행 구조** (`cumulative_cashback.html`)
- 좌측 레일 "연동된 UID" 카드 아래 블록
- 표시값 3개: **누적 페이백 금액** / **이번 달 페이백** / **누적 출금 금액**
- 캡션 **"연동된 3개 UID 합산 · 매일 09:00 KST 갱신"**
- 툴팁 **"거래로 인한 캐시백과 이벤트 리워드를 합산한 금액을 표시합니다."**

**판정: O. 집계 자체는 A-08의 "자격을 만드는 행위"입니다. 그러나 그대로 합산하면 안 됩니다.**

| 표시값 | DEX 합산 | 사유 |
|---|:-:|---|
| **누적 페이백 금액** | **분리 표기** | 바로 위 카드가 `출금 가능 페이백 잔액 + 출금 버튼`입니다. **DEX 금액을 섞으면 "누적 22,864인데 출금 가능은 5,000"의 간극이 영구히 설명되지 않습니다** |
| **이번 달 페이백** | **분리 표기** | 동일 |
| **누적 출금 금액** | **합산 불가** | DEX는 테더맥스 출금이 없습니다. DEX에서 출금해도 테더맥스는 알 수 없습니다 |
| 툴팁 "이벤트 리워드 합산" | — | DEX에는 이벤트 리워드가 없습니다 (A-09). 문구 수정 필요 |
| 캡션 "연동된 3개 UID 합산" | — | DEX 지갑을 세는지 명시 필요 |

**권고 표기**

```
누적 페이백 금액          22,864.3 USDT
  ├ 테더맥스 지급          22,100.0 USDT   ← 출금 가능 잔액과 연결됨
  └ DEX 직접 지급             764.3 USDT   ← 각 DEX 계정에 이미 지급됨
```

**관련:** 07 문서 1-1(`Available Cashback` 명칭 재정의), 5-1(DEX Cashback Balance 정의)과 **같은 뿌리**입니다. "테더맥스가 줄 돈"과 "DEX가 이미 준 돈"을 한 숫자로 합치면 안 된다는 것입니다.

### 2-10. 거래소 리뷰 — A-17 보강

A-17에서 "DEX 리뷰 작성 가능, 받은 쿠폰은 DEX에 사용 불가"로 확정했습니다. 실제 설계를 확인해 **3건을 보강합니다.**

| # | 항목 | 내용 |
|---|---|---|
| 1 | **별점 3축 중 하나가 DEX에 무의미** | 축이 `거래소 사용` / `페이백 적립` / **`페이백 출금`**입니다. DEX는 테더맥스 출금이 없습니다. → 07 문서 4-9의 근거가 확실해졌습니다. **DEX는 2축으로 하거나 3번째 축을 `{DEX}에서 출금`으로 재정의해야 합니다** |
| 2 | **작성 게이트가 `me.verified`** | "이 거래소 UID 연동 여부". DEX는 **지갑 연동 여부**로 매핑됩니다. 게이트 문구 `🔒 후기를 남기려면 거래소 UID 연동이 필요합니다`를 DEX용으로 바꿔야 합니다 |
| 3 | 🔴 **첫 후기 쿠폰 CTA 목적지** | 서버가 "연동한 거래소 중 **백오피스 목록 우선순위 1등**"으로 판정합니다(`REQ-1002`). **DEX만 연동한 사용자는 DEX로 보내집니다. 그런데 거기서는 쿠폰을 쓸 수 없습니다.** 판정 로직에 "CEX만" 조건을 넣어야 하고, CEX가 하나도 없으면 `REQ-1003`(노출 거래소 1등)으로 떨어뜨려야 합니다 |

**쿠폰 자체는 계정 단위이고 사용처가 거래소 무관**이라, DEX 사용자도 **받을 수는 있습니다.** 쓸 수 없을 뿐입니다. 3-3 과제 4(쿠폰함 안내 문구)가 그대로 적용됩니다.

### 4-3. 포인트 (TetherMax Point) — **X (확정)**

> **2026-10-20 확정 (A-10).** DEX 활동으로 TP를 적립하지 않습니다. 아래 "검토필요" 서술은 확정 전 기록이며, **결론만 바뀌고 구조 설명은 그대로 유효**합니다.
>
> **"TP를 무엇으로 교환하는가"는 이제 결정 변수가 아닙니다.** 적립 자체를 배제했으므로 교환 대상과 무관하게 X입니다.

**기존 적립 공식 — 거래가 아니라 "출금"이 트리거입니다**

본인 출금 기준:
```
TP = (페이백/커미션 출금분 × 해당 UID 거래소의 페이백 TP 적립률)
   + (이벤트 리워드 출금분 × 해당 UID 거래소의 이벤트 리워드 TP 적립률)
```
하위 계정 출금에 의한 상위 TP:
```
TP = 하위 계정의 페이백/커미션 출금분 × 거래소별 상위(파트너 또는 일반) TP 적립률
```
- TP 값은 소수 둘째 자리 내림
- 하위 계정의 이벤트 리워드 출금분은 상위 TP에 포함되지 않음
- 적립률은 **거래소별로 4종** 설정 (본인 캐시백 / 본인 이벤트 / 하위→일반 / 하위→파트너)

**DEX 걸림돌**

적립 공식의 입력값이 **"테더맥스에서 출금한 금액"**입니다. DEX는 테더맥스를 거치지 않으므로 **이 값이 원천적으로 생성되지 않습니다.** 두 번째 줄(이벤트 리워드 출금분)도 DEX에서는 항상 0입니다.

**가능성이 있는 이유**

TP는 현금이 아니라 포인트입니다. 그래서 "테더맥스가 돈을 못 보낸다"는 제약과는 직접 충돌하지 않습니다. **적립 기준을 "테더맥스 출금액"에서 "DEX가 지급한 캐시백 금액"으로 바꾸면** 이론상 가능합니다.

**판정 불가 사유 — 반드시 먼저 확인해야 합니다**

> **TP를 무엇으로 교환하는지가 기존 문서 어디에도 정의돼 있지 않습니다.**

TP가 최종적으로 USDT로 전환된다면 송금 문제가 TP에도 전이되어 판정이 **X**로 바뀝니다. TP의 사용처가 이 서비스 판정의 결정 변수입니다.

**추가 미정 사항**
- 소급 TP 지급 공식이 확정되지 않음 (문서가 "확정 금액 답변 금지"로 표시)
- 거래소별 적립률 4종을 DEX에도 설정하려면 스키마 확장 필요

**DEX PRD와의 정합성**

**조건부 가능 경로**

**추가 UX 문제**

혜택 페이지 상단이 회원에게 **이벤트 리워드 총합**을 보여줍니다. DEX 전용 사용자는 상시 0 USDT가 노출됩니다. 비회원에게는 금액 영역 자체를 제거한 선례가 있으니 같은 패턴을 적용할 수 있습니다.

**정책 방향 참고**

기존 문서에 이런 기록이 있습니다.
> "가입형 고정 리워드를 30~50% 축소했고, 리워드만 노리는 사용을 막기 위해 **실제 캐시백 또는 거래량에 연동된 성과 기반 리워드로 정책을 이동 중**"

**초대 리워드 공식**
```
초대 리워드 = 하위 계정 출금액 × 거래소 margin × 초대 리워드 요율
```

**기존 운영 규칙에서 확인된 사실**
- **거래소 margin이 0이면 사용자·파트너 모두 초대 리워드가 생성되지 않음**
- **하위 계정 출금액 중 이벤트 리워드 부분은 상위 초대 리워드를 만들지 않음.** 캐시백/커미션 출금분만 사용
- Boost 상태만으로는 초대 리워드가 결정되지 않음. 핵심 값은 운영자가 설정한 거래소 레퍼럴 margin
- 출금 최소액 **50 USDT**
- Partner는 **고정된 payout UID로만** 지급받음

**활동 상태 기준**

| 상태 | 기준 |
|---|---|
| Active | 최근 7일 내 캐시백 적립 있음 |
| Idle | 7~21일 적립 없음 |
| Inactive | 21일 이상 적립 없음 |

**판정 근거 — 기존 정책 안에서 자동으로 0이 됩니다**

세 가지가 겹칩니다.
1. "DEX 활동에는 초대 리워드가 발생하지 않는다"가 DEX PRD의 전제
2. 공식의 입력값이 "하위 계정의 **테더맥스 출금액**"인데 DEX 사용자는 테더맥스에서 출금하지 않음 → **입력값이 0**
3. 테더맥스가 DEX로부터 공유받는 margin이 구조적으로 존재하지 않을 가능성이 높음 → **margin이 0이면 초대 리워드 0**이 기존 규칙

즉 **별도 차단 로직을 만들지 않아도 기존 정책만으로 자동으로 0**이 됩니다. 이 점은 DEX PRD의 설계(PH-1, IF-1)와 일치합니다.

**조건부 가능 경로 — 표시 전용**

Partner Hub의 **금전 지급과 무관한 지표**에 DEX 캐시백을 넣는 것은 비교적 저위험입니다.
- 누적 캐시백 (lifetime cashback)
- 거래소별 계정 개요
- 활동 상태 (Active / Idle / Inactive)

**단 UX 리스크가 있습니다.** Partner가 "하위의 DEX 캐시백에 대해 보수를 받는다"고 오해할 수 있습니다. 명시적 구분 표기가 필요합니다. DEX PRD는 이미 이 방향으로 설계되어 있습니다(PH-2: DEX 행을 표시하되 초대 리워드는 없음, 캡션으로 명시).

**추가 확인 필요**
- DEX 지갑을 payout UID로 쓸 수 없다는 점은 사실상 확정이지만 명문 규정이 없습니다
- 일반 회원 요율이 계산 컨텍스트에서는 10%, 현행 Partner Hub 표시는 0%로 정규화돼 있습니다. 기존 문서가 "표시값으로 지급 공식을 추론하지 말라"고 경고합니다

## 5. 결정이 필요한 사항

### 5-1. 우선 결정 (다른 판정의 전제가 됨)

| # | 항목 | 영향 |
|---|---|---|
| 1 | **TP를 무엇으로 교환하는가** | TP가 USDT로 전환되면 포인트 판정이 검토필요 → **X**로 바뀜 |
| ~~2~~ | ~~**DEX가 지갑별 요율 상향을 지원하는가**~~ | **질문 자체가 불필요해짐.** VIP·부스트 둘 다 A-18로 X 확정. ①의 해당 문항 삭제함 |
| 3 | **DEX를 백오피스의 "거래소" 엔티티로 등록할지** | 거의 모든 서비스에 연쇄 영향 (아래 5-3 참조) |

### 5-2. 등급·순위 산정에 DEX 금액을 넣을지

각 항목마다 "넣으면 지급 불가 상태가 생긴다"는 문제가 공통으로 발생합니다.

| # | 지표 | 현재 기준 | 결정 사항 |
|---|---|---|---|
| 4 | 페이백 챌린지 누적액 | 적격 UID에 지급된 누적 커미션 | DEX 캐시백 산입 여부 |
| 5 | 페이백 랭킹 순위 | 거래소별 캐시백 금액 | DEX를 별도 거래소로 포함할지 |
| 6 | ~~VIP 등급~~ | — | **결정됨 (A-18).** VIP 게이지는 개별 UID 단위 → **DEX 미산입** |
| 7 | 마일스톤 / VIP 진행바 | DEX PRD는 DEX 금액을 포함하도록 설계 | **결정됨 (A-18).** ⚠️ **설계를 되돌려야 함** |
| 8 | Partner Hub 표시 지표 | 누적 캐시백, 활동 상태 | 표시만 할지, 구분 표기 방식 |
| 9 | ~~글로벌 리그 점수 / 팀 생성 자격~~ | — | **결정됨 (A-18).** 리그는 운영 거래소 1곳 단위 → DEX 판을 안 만들면 자연 배제 |

### 5-3. DEX를 "거래소"로 등록할 때 영향받는 지점

이 결정 하나가 아래 전부에 연쇄됩니다.

- 거래소별 TP 적립률 4종 설정
- VIP 수동 지정 모달의 `Exchange` 필드
- 글로벌 리그의 거래소 배정 (리그당 1:1)
- **퀴즈의 `Exchange` 필드 (등록 후 수정 불가)**
- 이벤트 관리의 거래소 필터
- 거래소 margin 설정
- 쿠폰 사용 모달의 거래소별 UID 행
- 이벤트 메일의 `exchange` 타입

DEX PRD는 이미 이 방향으로 설계되어 있습니다 — Exchange 레코드에 `Exchange Type`(CEX / DEX / Broker) 필드를 추가하고 하위 모듈이 이 필드를 읽는 구조입니다(EXT-1~4). 따라서 **각 모듈이 DEX를 어떻게 취급할지를 모듈별로 정해야 합니다.**

### 5-4. 지갑 주소에 대한 식별자 라이프사이클 정의

기존 서비스가 전부 "이슈 UID 배제"를 전제로 동작합니다. 지갑 주소에는 대응물이 없습니다.

| # | 항목 | 필요한 이유 |
|---|---|---|
| 10 | 지갑 주소의 "이슈" 상태 개념 | 쿠폰 사용, 챌린지 reward UID, 리그 참가 UID, 이벤트 리워드 수령이 모두 이슈 UID 배제를 전제 |
| 11 | 동일 지갑 주소 중복 입력 처리 | **지갑 연결·서명이 없으므로 소유 증명 수단이 없음.** 어뷰징 리스크가 UID보다 높음 |
| 12 | 지갑 주소 마스킹 표기 규칙 | 현행은 "UID 끝 4자리 마스킹". 지갑 축약 규칙 신규 정의 필요 |
| 13 | DEX 연동 해제 시 처리 | 과거 캐시백 표시, 챌린지 누적액, 리그 점수 처리 |

**유용한 선례가 있습니다.** 과거 종료된 PMF TON Quest에서 지갑 주소를 다룬 규칙입니다.
- **"지갑 주소는 TUID 간 중복될 수 없다. 하나의 지갑 주소는 하나의 TUID에 속한다."**
- **"사용자가 지갑 주소를 직접 수정할 수 없다. CS가 변경할 수 있다."**
- 그리고 **TON 거래 보상은 지갑 주소가 아니라 별도로 연동된 CEX UID 1개를 선택**하게 했습니다

즉 **과거 테더맥스는 지갑 주소를 식별자로만 쓰고 지급 대상으로는 쓰지 않았습니다.** DEX 설계의 선례이자, "지갑으로는 지급하지 않는다"는 기존 관행의 증거입니다.

1. DEX 4곳이 제공하는 데이터 범위 — 캐시백 지급액, 거래량(선물/스팟 구분), 커미션, 지급 시각. 수신 주기와 소급 가능 기간

3. 테더맥스가 공유받는 레퍼럴 margin 존재 여부 (0이면 초대 리워드가 자동 0)
4. DEX 캐시백 산정 기준이 커미션의 몇 %인지 — 챌린지·리그 임계값(100~5000 USDT)과 비교 가능한 단위인지

### 내부에서
5. ~~TP 사용처~~ **해당 없음.** A-10으로 적립 자체를 배제했으므로 교환 대상과 무관합니다
6. ~~VIP 등급 구간 기준 금액 + VIP 최신 기획안~~ **해당 없음.** A-18로 X 확정

8. 챌린지 레벨 금액과 기간의 불일치 해소

12. DEX 데이터 수신 실패 시 폴백 — "조회 실패 시 전체 숨김"으로 fail-safe한 선례가 있습니다 (WOOX 프로모션)

## 7. 근거 문서의 한계

판정의 근거가 된 기존 정책 문서에 다음 한계가 있습니다.

**1. 작성 시점이 3개월 전입니다.** 전체가 2026년 7월 13~23일에 작성됐고 이후 갱신이 없습니다. 특히 **VIP와 글로벌 리그 문서가 7월 13일로 가장 오래되었습니다.**

**2. DEX를 전혀 다루지 않습니다.** 13개 문서 전체에 `DEX`, `Lighter`, `EdgeX`, `Aster`, `ApeX` 언급이 없습니다. 등장하는 거래소는 모두 CEX입니다. 따라서 이 문서의 모든 **X 판정은 "기존 정책이 DEX를 고려하지 않고 작성되었다"는 사실에 기반**합니다.

**3. 문서가 스스로 신뢰도를 제한한 지점이 많습니다.** 주요 항목만 적습니다.
- VIP: "랜딩 페이지 소스가 거의 비어 있다. 신청 자격을 확정 답변하지 말 것"
- TP: "소급 금액 공식이 확정되지 않았다"
- 글로벌 리그: "부정 처리와 리워드 재계산은 금전 답변 전 확인 필요"
- 챌린지: 금액·기간·배치 시각이 모두 모순으로 기록됨
- 출금 임계값: 10 USDT와 50/100 USDT가 모순으로 기록됨
- 초대 리워드: "전체 금전 공식은 별도 추출이 필요하다"

**따라서 X 판정은 비교적 견고하고(지급 수단 부재는 구조적 문제), 검토필요 판정은 근거 문서의 공백 때문인 경우가 많습니다.**

**정책 변경으로 뒤집을 수 있는 것과 구조적으로 뒤집을 수 없는 것을 구분하는 것이 다음 단계입니다.**

| 구분 | 해당 서비스 |
|---|---|
| **구조적 — 뒤집기 어려움** (테더맥스 송금 불가) | 이벤트 리워드, 쿠폰 **사용**, 페이백 랭킹 보상, 챌린지 **보상**, 글로벌 리그 보상, 초대 리워드 **출금 계좌**, **VIP 요율**, **부스트 요율**, 맥스보드 보상, 매칭 출금 |
| **정책 변경으로 가능** | ~~TP 적립 기준 재정의~~ (A-10으로 배제 확정), 챌린지 누적액 산입 (**A-13으로 산입 확정**), Partner Hub 표시 지표, 랭킹 표시 |
| **이미 가능** | 앱푸시, 이메일, 퀴즈 참여 단계, 공지, 수신거부, 누적 캐시백 표시, 캐시백 타임라인 |
| **법무 판단** | 약관 (DEX 자체수탁 고지) |

> ⚠️ **"파트너 역량에 달림" 분류가 없어졌습니다.** 원래 `VIP 요율 상향` 한 건이 있었는데 A-18로 X 확정됐습니다.
