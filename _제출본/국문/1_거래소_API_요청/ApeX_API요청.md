## 요약

ApeX가 어필리에이트 API 스펙을 보내 주었고 대부분의 요구사항이 커버됩니다.

**7건이 남아 있고 그중 4건이 출시를 막습니다.** 화면에 표시할 숫자 자체가 없기 때문입니다.

| 우선도 | 항목 |
|---|---|
| **P0** | 1. 원장 레코드 필드 — 캐시백 금액·지갑 주소·토큰·지급 시각 |
| **P0** | 2. 계정 ID |
| **P0** | 3. 인증 방식과 base URL |
| **P0** | 4. 웹훅 이벤트와 payload |
| P1 | 5. 정정·취소 처리 |
| P1 | 6. 특별 이벤트 요율 |
| P1 | 7. 조회 키 동작 |

ApeX 초안 기준 P1은 출시 후 60일입니다 (Aster는 30일).

## 1. 원장 레코드 필드 — P0

ApeX 스펙의 원장 레코드에는 `commission_state`, `reward_period`, `fee_basis`, `available_balance`, `record_id`가 있습니다.

**다음 4개가 없습니다.**

| 필드 | 필요한 이유 |
|---|---|
| **캐시백 금액** | 트레이더에게 보여줄 숫자입니다. 이게 없으면 **표시할 값이 존재하지 않습니다** |
| **`wallet_address`** | 트레이더가 테더맥스에 붙여넣은 지갑 주소로 레코드를 매칭합니다 |
| **`token`** | 모든 금액에 통화를 요구하며, 없는 레코드는 거부합니다 |
| **`payout_time`** | 캐시백이 Rewards Center에 도착한 시점을 표시합니다 |

**각 원장 레코드가 이 4개 필드를 포함하는지 확인 부탁드립니다.** 구현상 이름이 다르면 필드명을 알려주십시오.

> **참고:** 우리 엔지니어링팀이 10월 19일에 같은 내용을 제기했습니다 — *"the commission API doesn't include the commission amount, rate, or user ID. Right now we can't tell how much commission each user earned."* 출시를 막는 유일한 항목이라 다시 한번 정리해 보냅니다.

---

## 2. 계정 ID — P0

같은 지갑이 여러 DEX에서 쓰일 수 있어, 모든 DEX 레코드를 **지갑 주소 + DEX 자체 계정 ID**로 키잉합니다.

**10월 15일에 "현재 Affiliate API가 지갑 주소와 UID를 둘 다 반환하고, 업그레이드 버전도 그렇다"고 확인해 주셨습니다.** 귀속 조회는 이것으로 해결됐습니다.

**확인이 필요한 부분은 동일한 식별자가 원장 레코드와 웹훅 payload에도 들어가는지**입니다. 문서 스펙에는 세 곳 모두 `account_id`가 없어서 업그레이드가 전부를 포함하는지 확실하지 않습니다.

두 가지 중 하나면 됩니다.

**(a)** 계정 식별자(10월 7일에 표시해 드린 `id` 필드)가 **API 2, 모든 원장 레코드, 모든 웹훅 payload**에 반환

**(b)** **지갑 주소 1개가 ApeX 계정 1개에 대응**함을 확인. 그러면 Lighter처럼 지갑 주소 단독으로 키잉하고 `account_id`가 전혀 필요 없습니다

**어느 쪽인지 알려주십시오.** ApeX Omni에 서브계정 메커니즘이 없다는 점을 고려하면 (b)가 맞을 가능성이 있어 보이며, 그렇다면 양측 모두 단순해집니다.

---

## 3. 인증 방식과 base URL — P0

스펙에 인증 방식과 base URL이 없습니다.

**제안**
- HMAC-SHA256 요청 서명이 붙은 API 키
- 5분 경과 시 거부되는 타임스탬프
- IP 허용 목록
- TLS 1.2 이상

이것으로 괜찮은지, 아니면 ApeX 방식을 알려주시고 base URL을 제공해 주십시오.

---

## 4. 웹훅 이벤트와 payload — P0

스펙에는 "주요 시점에 데이터를 푸시하며, 수신 URL과 화이트리스트는 어카운트 매니저를 통해 설정한다"고만 되어 있고 **이벤트 목록과 payload가 없습니다.**

두 가지 이벤트가 필요합니다.

| 이벤트 | 시점 | 필요 payload |
|---|---|---|
| **신규 사용자 귀속** | 계정이 테더맥스 어필리에이트 트리에 바인딩될 때. **AccountID를 여기서 처음 수신** | `wallet_address`, `account_id`, 이전·신규 상태, 갱신 시각, 해당 시 `record_id`, 고유 `event_id` |
| **커미션 Pending → Paid** | 커미션 레코드가 Paid로 전환될 때 | `wallet_address`, `account_id`, `record_id`, 이전·신규 상태, 갱신 시각, 고유 `event_id` |

추가 요청
- 푸시에 **요청과 동일한 방식의 서명**
- 실패 시 우리가 HTTP 200을 반환할 때까지 **24시간 백오프 재시도**
- 중복 제거를 위한 **고유 `event_id`**

## 5. 정정·취소 처리 — P1

원장에서 정정이나 취소를 어떻게 표현합니까?

**원본 `record_id`를 참조하는 새 레코드**를 기대하며, 원본 수정은 아닐 것으로 봅니다. 우리 수집 로직은 레코드를 불변으로 다루고 기간 마감 후 48시간에 확정합니다.

---

## 6. 특별 이벤트 요율 — P1

`current_eligibility`가 무기한 계약, 예측 시장, 특별 이벤트의 캐시백 비율을 반환합니다.

**특별 이벤트 요율이 트레이더에게 표시할 캐시백 요율을 바꿉니까?**

우리는 트레이더 본인의 캐시백 요율만 표시하고, DEX 트레이더에게 이벤트 리워드를 지급하지 않습니다. 별도 안내가 없으면 **특별 이벤트 요율은 표시에서 제외**하고 무기한 계약·예측 시장 요율만 반환값 그대로 표시할 계획입니다.

---

## 7. 조회 키 동작 — P1

API 2가 지갑 주소 또는 플랫폼 UID를 받습니다. **우리는 트레이더가 붙여넣은 지갑 주소만 보냅니다.**

지갑 주소로 조회하면 **그 지갑에 귀속된 모든 계정이 반환되는지** 확인 부탁드립니다.

---

## 관할 지역 — P2

테더맥스에서 귀사 프로그램을 **어느 지역에** 노출할지에 영향을 주는 질문 2건입니다. 연동을 막는 항목은 아닙니다.

| # | 질문 | 질문 이유 |
|---|---|---|
| 1 | 귀사가 **사용자 소개를 받지 않아야 하는 관할**이 있습니까? | 사용자 국가에 따라 파트너 노출을 제어하고 있습니다. 추측하지 않고 귀사 기준을 그대로 적용하고자 합니다. |
| 2 | 서비스를 제공하지 않는 국가 목록을 공유해 주실 수 있습니까? | 동일한 목적입니다. 위 필터의 초기값으로 사용합니다. |

각 항목에 짧게만 답해 주셔도 충분합니다.

## 이미 정리된 사항 (오해가 없도록 기록)

틀린 내용이 있으면 바로잡아 주십시오.

| 항목 | 우리 이해 |
|---|---|
| **캐시백 출금은 사용자가 직접** | ApeX 입장을 전적으로 수용합니다. claim은 Reward Center에서 사용자가 수행하는 L2 서명이며, **테더맥스는 사용자 서명을 보관하거나 대행하지 않습니다.** 우리 화면은 적립 내역을 보여주고 ApeX로 연결만 합니다 |
| **딥링크 목적지** | 10월 14일 설명에 따라 **`https://omni.apex.exchange/rewards`**(claim 페이지)로 연결합니다. 이후 출금은 Perp → Funding 이체 후 진행되며 전부 ApeX에서 일어난다는 점을 이해했습니다 |
| **서브계정 없음** | ApeX Omni에는 서브계정 메커니즘이 없어, CEX처럼 지갑 하나가 여러 계정으로 갈라지지 않습니다 |
| **벌크 레퍼럴 목록** | Direct Client Query Interface로 현재 지원됩니다 |
| **레퍼럴·어필리에이트 분리** | 11월에 통합 예정이며 이후 referral 데이터가 Affiliate API에 포함된다고 이해했습니다. **출시 설계는 어필리에이트 경로만 사용하므로 차단 요소는 아닙니다.** 다만 통합 시 보이는 사용자 범위가 넓어지므로 사전 안내를 요청드립니다 |
| **기본 캐시백 요율 20%** | 확인했습니다. 트레이더별로 `current_eligibility`가 반환하는 요율을 그대로 표시하고 더 높게 표시하지 않습니다 |
| **VIP 레벨이 수수료를 낮춤** | 이해하고 수용합니다. 트레이더가 상위 VIP에 도달하면 수수료가 낮아져 커미션이 줄어드는 것은 정상이며, 오류로 표시하지 않습니다 |
| **한국 접속** | 한국 CDN 노드가 일본이나 중국으로 라우팅될 수 있고 속도만 느려질 뿐 기능은 정상이라고 이해했습니다. 다른 파트너에는 유사 제한이 없습니다. 상황이 바뀌면 조기에 알려주시면, 사용자가 겪기 전에 안내하겠습니다 |

## 프로그램 동작 이해

| # | 주체 | 단계 |
|---|---|---|
| 1 | 트레이더 → ApeX | 테더맥스 레퍼럴 링크로 가입. ApeX가 AccountID를 테더맥스 트리에 기록 |
| 2 | 트레이더 → 테더맥스 | ApeX 지갑 주소 붙여넣기 |
| 3 | 테더맥스 → ApeX | 지갑 주소 조회 (API 2) |
| 4 | ApeX → 테더맥스 | `is_partner_referral`로 귀속 확인, 가입일과 AccountID 반환 |
| 5 | 트레이더 → ApeX | 거래. ApeX가 수수료와 캐시백 산정, 시간당 정산 |
| 6 | ApeX → 테더맥스 | 계정·정산 기간별 커미션 레코드 제공 (API 3) |
| 7 | ApeX → 트레이더 | ApeX Rewards Center에 캐시백 지급 |
| 8 | ApeX → 테더맥스 | Pending → Paid 전환을 레코드 ID와 함께 푸시 (API 5) |
| 9 | 트레이더 → 테더맥스 | 캐시백 확인 후 "Withdraw on ApeX" 선택 |
| 10 | 테더맥스 → 트레이더 | ApeX Rewards Center를 새 탭으로 염 |

**테더맥스는 트레이더의 자금을 보유하거나 이동하지 않습니다.** ApeX가 보고한 내용을 표시하고 Rewards Center로 연결합니다.

## 수기 CSV 대체 경로 (API 미개통 시)

02:00 UTC까지 접근 통제 공유 폴더로 일 1회 전달.

```
record_id, wallet_address, account_id, reward_period, fee_basis,
amount, token, commission_state, payout_time
```

`payout_time`은 지급 전까지 비어도 됩니다. **`token`이 USDT가 아니거나 `record_id`가 없는 행은 거부**합니다.

## 우리 측 데이터 처리 규칙

| 규칙 | 내용 |
|---|---|
| 레코드 키 | `wallet_address` + `account_id` — 2번 항목 대기 |
| 불변성 | 수정하지 않음. 정정은 원본 참조 새 레코드 |
| 확정 | 시간당 정산 기간을 UTC 영업일로 묶음. 마감 후 48시간에 확정 |
| 금액 | 소수 6자리까지의 소수 문자열. 부동소수점 금지 |
| 지갑 주소 | 소문자 16진수, 대소문자 구분 없이 비교. 파트너가 보낸 주소도 사용자 입력과 동일 규칙으로 검증. **무효 주소는 조용히 버리지 않고 검토 보류 후 ApeX에 보고** |
| 토큰 | 모든 금액에 필수. 없는 레코드는 거부 |
| 개인정보 | 요청하지 않음 |
| 조회 기간 | 최대 180일 |

**대조:** 연동된 지갑 주소와 ApeX가 제공한 AccountID로 매칭합니다. **미매칭 레코드는 버리지 않고 보류 후 주간으로 보고**합니다. 월말에 토큰별 레코드 합계가 월 명세서와 일치해야 합니다. 양측 모두 명세서 후 30일 내 `record_id`를 인용해 이견 제기 가능합니다.

## 빌드 우선순위

**우리 측 구현 순서**입니다. 추가 요청 목록이 아닙니다. 이미 제공 확인된 항목도 포함됩니다 — 우리는 그것들에 맞춰 구현해야 하기 때문입니다. 우선도 열은 **우리 빌드 기준**이며, 파트너에게 요청하는 P0/P1/P2와는 다릅니다.

| 순서 | 항목 | API | 우선도 |
|---|---|---|---|
| 1 | **원장 레코드에 캐시백 금액·지갑 주소·토큰·지급 시각** | API 3 | **P0** |
| 2 | `is_partner_referral`과 AccountID (지갑 주소 조회) | API 2 | **P0** |
